# 注释规范 — Comments

规则的权威来源是 [AGENTS.md](../../AGENTS.md) 的「注释与文档」小节。本文只补充判据与实例。

## 时机

**写文件时不写注释**，提交前回头补 ——对着已稳定的代码看，那时才知道哪些地方真的会走错路。

提交前只审 `git diff` 里的新增与改动行，不动没碰过的行。

## 唯一的判据

删掉这条注释，会不会有人因此走错路？

会 → 写。不会 → 不写。

## 该写

**踩过的坑** —— 不这么写会坏成什么样

```css
/* hidden input 不能改成 display:none —— 那样会退出 Tab 序与无障碍树 */
```

**必须满足的约束** —— 两个东西要一起改

```js
/* 先判 indexOf —— splice(-1) 会误删最后一条 */
```

**会算错的等式** —— 手算得不到的数

```css
/* transition 不是叠加而是整体替换，位置项要一并列出，否则手柄跟随滚动会瞬移 */
```

**容易误判的库行为**

```js
// 命中判定必须按坐标做，不能走滚动条的 :hover —— 库给滚动条整体设了
// pointer-events: none，放开命中后落在带上的滚轮会被 preventDefault
```

**工具链的硬性要求**

```js
// 用 .svelte.js 后缀：要 $state，.js 里编译不了 rune
```

## 不该写

**复述代码** —— 选择器和文件名已经说明的事

```css
/* 确认框正文 */          ← 类名是 .confirm-message
/* Toast 状态与调用入口 */  ← 文件名是 toast.svelte.js
```

**决策理由** —— 「为什么当初这么选」

```css
/* 用中性色而非 accent，因为 accent 表示操作、焦点表示位置，混用会过载 */
```

代码本身就是事实，不需要注释替它辩护。

**历史沿革** —— 归 git

```js
// Svelte 5 之前是 legacy API，升级时改的
```

**描述现状的措辞** —— 「这里有」「当前是」

```js
// 同时只允许一个确认框    ← if (settle) throw 已经说了
```

**举例** —— 原理一句话说清就够

```js
// 复用上一个 promise 会让两次调用方拿到同一个答案
// 删 A 的确认框弹出时又请求删 B，A 就会删掉 B    ← 删掉后半句
```

**未验证的断言** —— 注释里说的事实要在代码里核对过

**未实现的占位** —— YAGNI 同一条

## 规则与语义

token 的用途注释、`docs/dev/frontend.md` 的组件清单、模块的用法说明属于规则与文档，不受「不解释」限制 —— 它们描述的是约定，不是决策过程。

## 提交前检查

- [ ] 删掉注释后没人会因此走错路；会的话写清楚了后果
- [ ] 注释里没有「为什么当初这么选」
- [ ] 注释里的断言在代码里核对过，不是推测
- [ ] 没有复述选择器名、文件名、函数名的注释
- [ ] 没有历史沿革
- [ ] 没有为尚未实现的功能留注释或占位
- [ ] 只审了 `git diff` 里的新增与改动行
