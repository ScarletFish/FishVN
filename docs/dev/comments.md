# 注释规范 — Comments

规则的权威来源是 [AGENTS.md](../../AGENTS.md) 的「注释与文档」小节。本文只补充判据与实例。

## 时机

**写文件时不写注释**，提交前回头补 —— 对着已稳定的代码看，那时才知道哪些地方真的会走错路。

提交前只审 `git diff` 里的新增与改动行，不动没碰过的行。

## 唯一的判据

分两步问，第二步答「是」才写。

**第一步：信息在代码里读得出来吗？** 读得出来就不写。清单：

- 参数名、函数名、字段名、模块名
- 类型签名（`&mut`、`Option<T>`、返回 `Result<_, E>`）
- 常量的字面数值、`#[cfg]` / `#[derive]`
- 紧邻下一行的校验、判空、`return false`
- 选择器名、类名、文件名
- 注释所在行的代码本身在做的事

**第二步：删掉这条，有人会因此走错路吗？** 会才写，且要写清**后果**。

> 踩过坑不等于该写。现象在代码里、后果在代码里没有，才写。

## 写法：写后果，不写现象

| 场景 | ✗ 复述现象 | ✓ 写后果 |
|---|---|---|
| 空值判断 | 「加了个空值检查」 | 「只判本地会抹掉用户已有封面」 |
| 类型不匹配 | 「这里用了 Arc」 | 「注册类型与 State 泛型按类型精确匹配，写错编译期不报」 |
| 尺寸上限 | 「长边取 560」 | 「不能往 `--card-w` 靠：那会把路径输入框挤到读不下」 |

## 该写

**踩过的坑** —— 不这么写会坏成什么样

```css
/* hidden input 不能改成 display:none —— 那样会退出 Tab 序与无障碍树 */
```

**必须满足的约束** —— 两个东西要一起改

```js
/* 先判 indexOf —— splice(-1) 会误删最后一条 */
```

**会算错的等式** —— 手算得不到的数

```css
/* transition 不是叠加而是整体替换，位置项要一并列出，否则手柄跟随滚动会瞬移 */
```

**容易误判的库行为**

```js
// 命中判定必须按坐标做，不能走滚动条的 :hover —— 库给滚动条整体设了
// pointer-events: none，放开命中后落在带上的滚轮会被 preventDefault
```

**工具链的硬性要求**

```js
// 用 .svelte.js 后缀：要 $state，.js 里编译不了 rune
```

**外部系统的约定** —— 跨文件的一致性，代码里读不出

```js
// 后端 image crate 的 feature 与这份清单要一致，见 src-tauri/Cargo.toml
```

## 不该写

**复述代码** —— 选择器和文件名已经说明的事

```css
/* 确认框正文 */          ← 类名是 .confirm-message
/* Toast 状态与调用入口 */  ← 文件名是 toast.svelte.js
```

**给代码里已有的检查加注解** —— 下一行就是检查本身

```js
// id 来自网络，拼路径前要验
if (id.is_empty() || !id.bytes().all(|b| b.is_ascii_alphanumeric())) {
```

**决策理由** —— 「为什么当初这么选」

```css
/* 用中性色而非 accent，因为 accent 表示操作、焦点表示位置，混用会过载 */
```

代码本身就是事实，不需要注释替它辩护。

**历史沿革** —— 归 git

```js
// Svelte 5 之前是 legacy API，升级时改的
```

**描述现状的措辞** —— 「这里有」「当前是」

```js
// 同时只允许一个确认框    ← if (settle) throw 已经说了
```

**举例** —— 原理一句话说清就够

```js
// 复用上一个 promise 会让两次调用方拿到同一个答案
// 删 A 的确认框弹出时又请求删 B，A 就会删掉 B    ← 删掉后半句
```

**未验证的断言** —— 注释里说的事实要在代码里核对过。**过时的断言比没有注释更糟**：读代码的人会信它。

**计数型断言** —— 「xxx 有 N 个」「xxx 恒为 N」「最大的是 xxx」

代码不承诺任何数量，加一处调用点、换一张图、改一个上游默认值，断言就错了。而且它对读代码毫无帮助——读者要的是约束，不是快照。

```js
// ✗ 消费端只有两个尺寸        ← 加了第三个消费点就成了误导
// ✗ thumbnail 恒 256 宽       ← 上游改过这个值
// ✗ 原图实测 550 KB           ← 单个样本，不是约束
```

要写就写不随改动失效的那种：

```js
// ✓ 560 = --card-w(277px) 的 2 倍，覆盖到 200% 缩放屏
// ✓ 下 url 不下 thumbnail：thumbnail 宽度不足以覆盖 2× 屏
```

**未实现的占位** —— YAGNI 同一条

## 规则与语义

token 的用途注释、`docs/dev/frontend.md` 的组件清单、模块的用法说明属于规则与文档，不受「不解释」限制 —— 它们描述的是约定，不是决策过程。

## 提交前检查

逐条对着 `git diff` 的新增与改动行过：

- [ ] 每条注释的信息都读不出来自代码（参数名、类型、下一行的校验不算信息）
- [ ] 每条注释写的是**后果**，不是现象
- [ ] 没有给代码里已有的检查加注解
- [ ] 没有「为什么当初这么选」
- [ ] 没有计数型断言（「有 N 个」「恒为 N」「实测 N KB」）
- [ ] 断言在当前代码里核对过，不是推测，也没有过时的
- [ ] 没有复述选择器名、文件名、函数名、字段名
- [ ] 没有历史沿革（「Svelte 5 之前…」「改的时候…」）
- [ ] 没有「这里有」「当前是」这类描述现状的措辞
- [ ] 没有举例
- [ ] 没有为尚未实现的功能留注释或占位
- [ ] 只审了 `git diff` 里的新增与改动行
