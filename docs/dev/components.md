# 组件与交互惯例 — Components

- **原名优先**：人名与作品名在界面上展示 `original`，罗马音 `name` 用作配对与检索身份。VNDB 同步填进表单的展示名按「官方中文标题 → 原文标题（alttitle）→ 主标题（title）」选择，别名放主标题；新增任何展示 VNDB 名字的位置都沿用这一优先级。
- **`GameForm` 的保存顺序是「内容先行，绑定殿后」**：安装、状态、元数据、角色全部写成功后，最后一步才写 `vndb_id`，绑定始终与已落库的内容一致。新建条目在创建返回后立刻切到更新通道，失败重试落在同一条上。选中搜索命中先查库内占用，已有条目绑定同一作品就当场提示，校验通过才进入拉取。
- **bits-ui 是无头行为层，视觉全部留在自家 CSS**：`Select`（`SelectDd` 内部）、`DropdownMenu`（`Menu` 内部）、`Tabs`（两处 tablist）、`ContextMenu`（横幅）都只借它的键盘导航、焦点管理与 ARIA，DOM 结构和类名是我们渲染的（`child` snippet / `class` 透传 / `ContentStatic` 文档流定位）。组件上不能写 `class:` 指令，动态类名用三元拼进 `class`。受控状态走函数绑定 `bind:value={() => v, set}`，API 与调用方约定不变。**以装好的包为准，别照官方文档站抄新 API**——文档站常跑到 npm 发布前面（`Select.ItemText` 在 2.20.3 里不存在，输入过滤走 `Item` 的 `label` prop），照抄就是静默渲染成空。
- **`Menu`**：内部是 bits-ui `DropdownMenu`，浮层**必须**套 `Portal` 后由 Floating UI 定位（`align="end"` 保持右对齐、防溢出翻转）——卡片 hover 有 `transform` 过渡，不套 Portal 的 `position: fixed` 会被 transform 祖先劫持成相对卡片定位，悬浮态一变菜单就整块跑偏。开合状态仍可由调用方 `bind:open` 持有。它只管 ⋮ 那种挂在宿主右下角的下拉，不跟鼠标点。
- **右键菜单走 bits-ui 的 `ContextMenu`**（横幅是当前唯一入口）。硬约束：触发区必须挂在 `.detail-banner` 上，`.detail-ambience` 是 `pointer-events: none` 又压在横幅容器之下，右键永远落不到它；菜单内容是**状态面板**，用表单那套控件（`forms.css` 的 `.seg-radio-group`、`.toggle-switch`）而不是 menuitem 动作条目，点选天然不关菜单；单选钮是半受控的——选项值由 meta 派生，选「自定义」后取消文件对话框不触发重渲染，DOM 会卡在视觉选中态，靠 `{#key}` 重挂载回弹；面板视觉在 `menus.css` 的 `.menu__list` 规则组上做 `.context-menu--panel` 变体，底压到 surface 是因为段控件的提亮语言（现在是明度对比）需要容器比选中格暗一档。若将来要用回 `RadioItem` / `CheckboxItem`，必须套在 `Group` / `RadioGroup` 里，否则渲染时抛 `Context not found`——错误只在控制台，DOM 一片空白。给封面单独做菜单，在内部再套一个 `Root` 就够——内层开菜单时会 `preventDefault`，外层见到 `defaultPrevented` 不再开。
- **`SelectDd`**：下拉选择的唯一入口，选项以 `{ value, label }` 数组传入，开合状态由调用方持有（`open` + `onopenchange`），同一表单内多处下拉互斥靠调用方比较存的是「哪一处开着」。内部是 bits-ui `Select`（方向键 / 输入过滤 / `data-highlighted` 高亮），浮层用 `ContentStatic` 随组件文档流定位，宿主容器不要再套 `overflow` 滚动，长列表交给面板级滚动。
- **tablist 只换骨不换皮**：`GameForm` 与 `SettingsDialog` 的标签条用 bits-ui `Tabs`（roving tabindex + 方向键），触发器渲染自家 `.modal-tab`；面板不走 `Tabs.Content`——表单面板常挂、靠 `.modal-panel.active` 切换显示，滚动手势（`use:panelScrollbars`）和已填状态都不受切页影响。
- **`DetailSection`**：详情页分区的统一外壳（卡片 + 标题 + 计数 + 内边距）。`.section-card` 基类只有背景与边框，内边距由外壳统一给出；新增详情分区直接用组件，自己拼 `section.section-card` 会让标题与相邻分区错位。标题右侧除 `count` 外可挂一段 `action` snippet（感想的编辑铅笔走这里），它排在计数之后、靠右对齐。
- **详情页感想的就地编辑**：文本框定高、`resize: none`，内容在框内滚动，长度不推挤下面的按钮行；宽度向左侧出血，让正文左缘与展示态、与上面的简介同一条线，右缘仍与标题行的铅笔对齐，滚动条落位也与展开态一致 —— 进出编辑文字不横向跳。边框用 `1px` 的 `box-shadow` 画在盒外，不占内容宽，hover / focus 只改描边深浅。取消与保存按钮在 `mousedown` 上挡掉焦点转移，否则点按钮会先触发失焦保存，取消变成「先存再撤」。
- **`tooltip.js` / `side-tip.js`**：`data-tooltip` 走前者（跟随光标），`data-tip` 走后者（锚定侧栏条目，文案随属性变）。两条禁令：**不要把气泡做成每节点一枚**——只有单例（`document` 委托 + 一个 `current`）才结构性地排除「相邻两项同时亮」，action 版做得到挂起，但没人仲裁谁该熄；**主题切换时不要试图保住气泡**——`startViewTransition` 期间指针状态不保证连续，`side-tip` 顺势在主题广播时瞬时收起，消失并入整页淡入，加坐标或 `:hover` 守卫只会把真正的离开一起吞掉。
- **`Detail`**：鼠标侧键 3 是后退，4 不接。
- **`MyList`**：打开表单前先落 `gameId`，`GameForm` 的 `$effect` 与 `open` 在同一帧读到的是最终值。
- **`DetailCharacters` / `CharacterEditor`**：立绘走封面那条 `coverSrc` 管线 —— 缩图与 asset 协议授权都在那边做过。
- **`VnMergeDialog`**：单一取舍面板承载两层分区——元数据字段行与角色冲突行。角色区立绘随元数据区一起预取，面板关掉时结果作废。
- **`CharacterEditor`**：回选只在「角色列表变化」时发生（加载 / 增删 / 保存回填），用 `untrack` 让它只依赖 `characters`、不追踪 `selectedId`，用户手动点开或收起不会被抢回。
- **`SettingsDialog`**：打开时的初始化整块包在 `untrack` 里，让 `$effect` 只依赖 `open`。那段初始化读了主题、accent、排除标签等 store，不包的话任何 `notifyConfigChanged`（比如在侧边标签池里加一个标签）都会让 effect 重跑一次：表单字段被重新拉取覆盖，`poolOpen` 也被重置，侧栏当场收起。
- **`PlaytimeField.svelte`**：总时长单输入框，失焦即 `update_game_state`。输入认 `12:30`、`12h30m` 与纯数字（按秒），右侧读数列显示秒；回填用无损写法（整分 `12:34`，带秒 `12:34:56`），认不出来的输入还原成原值。
- **输入组**（输入框 + 右侧内嵌按钮）：容器单边框，输入框无框伸缩（`flex:1` + `min-width:0`），按钮坐右侧、中间一条分隔线；容器 `:focus-within` 接管焦点高亮，点输入框或点按钮整个框一起亮；按钮 `min-width` 兜住两种文字宽度，切换时输入框不抖帧；内嵌按钮做成无底无框的附属动作（hover 只变文字色 + 出 `--bg-hover` 底），不与表单行里的主按钮同权重。与 `.num-stepper` 同构，「框 + 附属动作」的组合沿用这一只。
- **成组输入**：几个短字段同属一个语义组（宽高、三围这类）时并成一条外壳，不要各占一行——外壳只画外框、格间断竖线，组内 input 自身无框；组内标签可以压成单个字母或单位前缀，但 `.sr-only` 要补出全名（可访问名含可见标签，WCAG 2.5.3）。焦点由整格底色加格底内线承担，不套 `--focus-ring`：编辑区的焦点是中性强调（`--bg-raised` / `--border-strong`），accent 只表示选中身份。容器用 `role="group"` + `aria-label`，`fieldset` 的 `legend` 会在上边框留一道缺口；外壳 `overflow: hidden`，方角底色才能沿圆角收口。
- **chip 双选**：tag-pill 体系复用到非标签场景（同步导入名单这类「出现在表单里 = 选中」的清单）时，选中用实心、未选用幽灵（虚线 + 前景色透明化），`aria-pressed` 承载语义，点一下两态切换；chip 内只放条目名，状态与分组由组头承载，chip 里不重复。
- **`TaskDock`**：全局任务状态面板，浮动在视窗底部居中（380px，非详情页展示），层级压在全部弹窗与 toast 之上。与 Toaster 一样经 portal 挂进 `#modal-root`：弹窗打开时 `body` 的直接子元素（除 `#modal-root` / `#globalTooltip`）整体 blur，浮条挂在 `#app` 里会跟着糊掉。当前承载资料补全任务——它是唯一在弹窗外跑的长任务。显隐语义：× 在任务在途时折叠成底部居中的小手柄（状态点 + 进度文案 + 展开箭头），任务 alive 期间手柄常驻，点击恢复完整面板；完结汇总始终自动唤起（含 × 折叠期间），带 6 秒倒计时自动隐藏，倒计时走完后的 × 才是真收起。新任务启动（列表按钮触发时派发 `backfill-refresh` 窗口事件、后台接续时经首个进度事件）无条件重新打开——收起不能让人错过下一轮进度。状态归约抽到纯模块 `dock-state.js`（与 Svelte/DOM 解耦、可单测）：后端 `vndb-backfill` 事件全部消费，阶段事件 `meta`/`cover`/`characters`/`images` 只更新 `phase`、不污染全局 `done`/`total`，`error` 收进 `errors[]`、面板给「N 条失败」展开；收起/关闭状态不另存标记，由 `run_id` 判定：新一轮与上轮的 `run_id` 不同即视为「这轮没折叠/关过」，上一轮完结汇总随之自然作废，不需要手动 reset。挂载时只接在途任务，刷新后从进行中的进度续上，上一轮的完结汇总随刷新作废。× 是右上角的独立角标，不压动作按钮。完整面板与手柄是同一个 fixed 容器的两种形态，原地切换——折叠只是换形态，不挂方向相反的 `fly`，否则会闪。库里刷新广播的契约见 [libs.md](./libs.md)。
- **`SyncResultDialog`**：重操作（VNDB 同步这类秒级拉取）点下即开弹窗进加载态，反馈先于结果出现，不等 await 返回才弹窗；加载态的阶段文案只消费后端进度事件，前端不虚构阶段。父级用序号令牌防迟到结果：每次触发自增序号，await 返回时序号已被新的触发或取消改掉就丢弃（`seq !== syncActive` 直接 return），旧请求的 plan / error 不会覆盖新状态；按钮的忙态只由最新一次在途调用置位与清除。计划内容分两步呈现：有冲突时第一屏只做裁决，第二屏是写入预览（推送与导入各自可取消勾选），底部按钮随步骤切换为「下一步」/「上一步 · 应用」；只有一类内容时不分步。应用阶段若涉及上传 VNDB，弹窗留在原地显示写入进度（进度事件 `phase` 为 `push`），期间 `onclose` 返回 `false`，Esc 与关闭按钮都不生效；按钮换成禁用的进度态，避免长任务中途留下半截状态。
- **`ImageViewer`**：单图查看画布。只管一张图怎么看：滚轮以指针为中心缩放、拖动图面平移、双击在适应窗口/100% 间切换、右上角缩放比、stage 尺寸变化时适应态保持整图可见。图源从外部注入 `src`，不关心图从哪来（封面缩略图或本地原图都行）；`maxZoom` prop 化——封面编辑器传 4（预览图最大边 560px，再大必糊），直开原图的场景可以传更大。`children` snippet 收 `{ toImage, toScreen, view }` 供浮层做坐标换算（取景框就浮在它上面）；单击图面（位移 < 4px）回调 `ontap(图坐标)`。viewport 纯函数在 `lib/image-viewer.js`（带单测）。**坑**：滚轮监听必须 `addEventListener('wheel', h, { passive: false })` 才能 `preventDefault`，Svelte 的 `onwheel` 属性写法不行——不加 passive 选项浏览器默认 passive，`preventDefault` 是静默无效的，页面会跟着滚。**边界**：多图导航、画廊、旋转、信息面板都是内核之外的层，挂在查看器外面——等真实需求来了再长，现在猜接口必然猜错；内核（视口数学 + 画布手势）保持不动。
- **`CoverFocalDialog`**：封面展示焦点的取景框编辑器（表单「调整展示位置」打开），画布是 `ImageViewer`，自己只做焦点数学（`lib/cover-focal.js`）。约定：焦点不参与合并面板（`vn-merge.js` 的 `FIELDS` 不加它，远端没有这个概念）；换封面重置焦点由后端 `metadata::upsert` 收口，前端只在 picker 选图与合并接受两条路径同步重置显示值，别处不要再造重置逻辑；新增封面展示处要读焦点字段（清单见 [backend.md](./backend.md)「封面展示焦点」）。手势路由：拖框与拖图面是两个区域的手势——取景框自己收 pointer 事件并 `stopPropagation`（否则画布会跟着平移），框外区域归画布（拖动平移、单击移框）；方向键微调焦点（Shift 加速，无效轴忽略），弹窗打开即聚焦到根容器。
- **`InstallationList`**：安装行 = 单选圆点 + `.install-main`（路径框 + `.install-flags`）。flags 区两个开关各自成行，形态对齐设置页的 `toggle-switch` + 标签，不加说明文字（开关本身自明）：转区启动一行；Magpie 缩放一行，行右挂两态段控件（全屏 / 窗口），开关关闭时段控件禁用置灰——开关即 `magpie` 的 off，开启默认落 `full`。段控件复用设置页的 `seg-radio-group` / `seg-radio-item`（label 包隐藏 radio、纯自定义样式，不用原生控件外观），radio 的 `name` 按 `item.key` 隔离防多行串组。flags 块整体缩进 + 左竖线，表明从属于该安装行；圆点与移除按钮都只跟路径框行对齐（移除是 `btn btn-danger`，跟角色面板的移除同一按钮语言）。转区开着时参数框禁用、placeholder 换成「转区时无法附加参数」（LE 链路不透传；别在禁用 input 上挂 tooltip——浏览器不派发鼠标事件给 disabled 控件，hover 永远不触发）。
- **`SettingsDialog` 的「工具」标签**：登记 Magpie / Locale Emulator 两个工具路径。失焦即保存（`oncommit`）：trim 后为空发 `null` 注销，非空先 `path_exists` 校验、不存在出行内错误且不落库，通过了才 `update_config` + 广播 `CONFIG_CHANGED`。浏览选完文件同样触发提交——`PathField` 的 `oncommit` 在 pick 成功后也会调，不只是 blur。
