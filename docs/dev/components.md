# 组件与交互惯例 — Components

- **原名优先**：人名与作品名在界面上展示 `original`，罗马音 `name` 用作配对与检索身份。VNDB 标题按「官方中文 → 日文原名 → 罗马音主标题」组成候选链，去空去重；主标题取链上第一项，副标题取下一个不同的项，只剩一项时副标题为空。前后端共用的链由 `src-tauri/spec/display-titles.json` 生成；新增任何展示 VNDB 名字的位置都沿用这一条链。
- **`GameForm` 的保存顺序是「内容先行，绑定殿后」**：安装、状态、元数据、角色全部写成功后，最后一步才写 `vndb_id`，绑定始终与已落库的内容一致。新建条目在创建返回后立刻切到更新通道，失败重试落在同一条上。元数据写入要过 `hasMetadataContent` 这道闸：新建表单的默认焦点与观感（`cover_focal_*` 50/50、`ambience_mode` soft、`ambience_plate` false）不算资料，只填名字就整份 patch 不传——后端 `create_game` 见 `None` 便不 upsert，条目才留在待处理里；编辑侧本来 `meta == null`（没有行）且这次也没内容时同样跳过 `update_game_metadata`，否则改名一次就把空壳行点出来了，`has_metadata` 变 1、批量补全永远扫不到它。选中搜索命中先查库内占用，已有条目绑定同一作品就当场提示，校验通过才进入拉取。
- **`add-game.svelte.js`：添加/编辑表单的全局单例状态**。`GameForm` 与 `ScanAddDialog` 只在 `App` 挂一份，`openForm(id, { tab })` / `openPrefilled(path)` / `addFromFile` / `addFromScan` 是唯一驱动入口，各视图不持有自己的表单实例。新建（`id == null`）固定从「基本」页开始并覆写记忆标签页；编辑未指定 tab 沿用记忆页；详情页跳指定页（标签 / 安装）走 `tab` 参数。标签页记忆由 `App` 的 `$effect` 统一落地 `form-tab-pref`。扫描完成的刷新走 `LIBRARY_CHANGED` 广播，视图各自订阅。
- **bits-ui 是无头行为层，视觉全部留在自家 CSS**：`Select`（`SelectDd` 内部）、`DropdownMenu`（`Menu` 内部）、`Tabs`（两处 tablist）、`ContextMenu`（横幅）都只借它的键盘导航、焦点管理与 ARIA，DOM 结构和类名是我们渲染的（`child` snippet / `class` 透传 / `ContentStatic` 文档流定位）。组件上不能写 `class:` 指令，动态类名用三元拼进 `class`。受控状态走函数绑定 `bind:value={() => v, set}`，API 与调用方约定不变。**以装好的包为准，别照官方文档站抄新 API**——文档站常跑到 npm 发布前面（`Select.ItemText` 在 2.20.3 里不存在，输入过滤走 `Item` 的 `label` prop），照抄就是静默渲染成空。
- **`Menu`**：内部是 bits-ui `DropdownMenu`，浮层**必须**套 `Portal` 后由 Floating UI 定位（`align="end"` 保持右对齐、防溢出翻转）——卡片 hover 有 `transform` 过渡，不套 Portal 的 `position: fixed` 会被 transform 祖先劫持成相对卡片定位，悬浮态一变菜单就整块跑偏。开合状态仍可由调用方 `bind:open` 持有。它只管 ⋮ 那种挂在宿主右下角的下拉，不跟鼠标点。
- **右键菜单走 bits-ui 的 `ContextMenu`，实现收在 `AmbienceMenu.svelte`，横幅与展厅舞台两处入口**。触发元素由调用方经 `child` snippet 渲染：横幅必须挂在 `.detail-banner` 上并按横幅矩形过滤（`.detail-ambience` 是 `pointer-events: none` 又压在横幅容器之下，右键永远落不到它；横幅比氛围图高，低处不该开菜单），展厅挂在整页 `section` 上但只认底栏上沿以上的坐标，低于它的右键不开。菜单内容是**状态面板**，用表单那套控件（`forms.css` 的 `.seg-radio-group`、`.toggle-switch`）而不是 menuitem 动作条目，点选天然不关菜单；单选钮是半受控的——选项值由调用方派生，选「自定义」后取消文件对话框不触发重渲染，DOM 会卡在视觉选中态，组件靠 `{#key}` 重挂载回弹；面板视觉在 `menus.css` 的 `.menu__list` 规则组上做 `.context-menu--panel` 变体，底压到 surface 是因为段控件的提亮语言（现在是明度对比）需要容器比选中格暗一档。能力差异走 prop：`showPlate` 只有横幅开——展厅没有板；`showFocal` 两处都开——横幅跳表单图片页，展厅直接开 `CoverFocalDialog`（参考画幅 2.4:1，写独立的 `showcase_focal_*`），选图只提交 `ambience_path`，焦点归位由后端按路径是否变化判定；模式写入的字段名走 `modeKey`，横幅用默认 `ambience_mode`，展厅传 `showcase_mode`。同一个右键面板按入口写各自字段，横幅与展厅各自单独调整。展厅的清晰层高度由缩略图条尺寸决定：`--showcase-clear-bottom` 从 `--showcase-thumb-w` 推导（缩略图高 + 条内边距 + 底栏下内边距）。清晰图套一层 `.showcase-stage__clear-box`，容器用 `inset: 0 0 这个值 0` 把下沿收在缩略图条上沿，`overflow: hidden` 裁掉溢出；图在容器里 `width/height: 100%` + `cover` 放大铺满容器，焦点独立。模糊层是整页 `cover` + `blur(24px)` + `scale(1.02)`（只留盖住模糊羽化的量），从清晰层下方露出。**高度和裁切一律交给容器，不要把 `inset` 或高度写在 `<img>` 上**——替换元素绝对定位时 `height: auto` 取图片内在高度，over-constrained 的 `bottom` 被忽略（CSS 2.1 §10.6.5），图会照旧按宽度铺满；`<img>` 只管在容器里 `100% × 100%` + `cover`。若将来要用回 `RadioItem` / `CheckboxItem`，必须套在 `Group` / `RadioGroup` 里，否则渲染时抛 `Context not found`——错误只在控制台，DOM 一片空白。给封面单独做菜单，在内部再套一个 `Root` 就够——内层开菜单时会 `preventDefault`，外层见到 `defaultPrevented` 不再开。
- **`SelectDd`**：下拉选择的唯一入口，选项以 `{ value, label }` 数组传入，开合状态由调用方持有（`open` + `onopenchange`），同一表单内多处下拉互斥靠调用方比较存的是「哪一处开着」。内部是 bits-ui `Select`（方向键 / 输入过滤 / `data-highlighted` 高亮），浮层用 `ContentStatic` 随组件文档流定位，宿主容器不要再套 `overflow` 滚动，长列表交给面板级滚动。
- **tablist 只换骨不换皮**：`GameForm` 与 `SettingsDialog` 的标签条用 bits-ui `Tabs`（roving tabindex + 方向键），触发器渲染自家 `.modal-tab`；面板不走 `Tabs.Content`——表单面板常挂、靠 `.modal-panel.active` 切换显示，滚动手势（`use:panelScrollbars`）和已填状态都不受切页影响。
- **`GameForm`**：打开时的初始化整块包在 `untrack` 里，让 `$effect` 只依赖 `open`；`initialTab` 与 `bind:tab` 同源，切标签页会让它变化，不收窄依赖就会重跑初始化、清空整份表单与下载资料结果。切标签页只收起与页绑定的标签/特征侧栏；下载资料侧栏跨页留着，直到主动关闭或唤起别的侧栏。
- **bits-ui 迁移边界**：`TagPicker`（过滤 + 常驻多选网格）与 `Modal`（主面板 + 侧栏双栏）不迁库——交互形态不合其模型，维持手写。上库前先确认形态同构。
- **日期字段只有一条通道：bits-ui `DatePicker`**（发行日期在用），数据以 `YYYY-MM-DD` 字符串进出、组件内经 `@internationalized/date` 的 `parseDate` 转换，解析失败（`TBA`、乱格式）显示为空且不覆写原值。`Content` 必须套 `Portal to="#modal-root"`——表单在 `.modal` 里，后者持久持有 `transform: scale(1) translateY(0)`，不套会被劫持成相对模态框定位；不挂 `#modal-root` 则 modal 打开期间会被 `body:has(...)` 的整页模糊波及（toast 同理挂这里），z-index 用 `--z-popover`（260）盖过 modal（250）。日历的月对象是 `{ value, weeks }`、周直接是日期数组（照源码写，别照文档站抄）；头部年份/月份用 bits-ui `Select` 自绘下拉（浮层 `Portal to="#modal-root"`、选项列表必须套 `Select.Viewport`——没有它打开时不会把选中项滚进视口；Viewport 自带隐藏滚动条的全局样式，日历下拉保留默认不显示滚动条），视图状态走 `DatePicker.Root` 的受控 `placeholder`，年份范围由 `minValue`/`maxValue`（1980–2030）圈定。**生日不用它**：VNDB 的角色生日一半没有年份（`[null, 8, 8]` 序列化成 `8-8`），而 `CalendarDate` 必须有年——生日保持文本输入，格式校验走 `form-metadata.js` 的 `isValidBirthday`（放行 `YYYY-MM-DD` 与 `M-D`）。
- **`DetailSection`**：详情页分区的统一外壳（卡片 + 标题 + 计数 + 内边距）。`.section-card` 基类只有背景与边框，内边距由外壳统一给出；新增详情分区直接用组件，自己拼 `section.section-card` 会让标题与相邻分区错位。标题右侧除 `count` 外可挂一段 `action` snippet（感想的编辑铅笔走这里），它排在计数之后、靠右对齐。
- **详情页感想的就地编辑**：文本框定高、`resize: none`，内容在框内滚动，长度不推挤下面的按钮行；宽度向左侧出血，让正文左缘与展示态、与上面的简介同一条线，右缘仍与标题行的铅笔对齐，滚动条落位也与展开态一致 —— 进出编辑文字不横向跳。边框用 `1px` 的 `box-shadow` 画在盒外，不占内容宽，hover / focus 只改描边深浅。取消与保存按钮在 `mousedown` 上挡掉焦点转移，否则点按钮会先触发失焦保存，取消变成「先存再撤」。
- **`tooltip.js` / `side-tip.js`**：`data-tooltip` 走前者（跟随光标），`data-tip` 走后者（锚定侧栏条目，文案随属性变）。两条禁令：**不要把气泡做成每节点一枚**——只有单例（`document` 委托 + 一个 `current`）才结构性地排除「相邻两项同时亮」，action 版做得到挂起，但没人仲裁谁该熄；**主题切换时不要试图保住气泡**——`startViewTransition` 期间指针状态不保证连续，`side-tip` 顺势在主题广播时瞬时收起，消失并入整页淡入，加坐标或 `:hover` 守卫只会把真正的离开一起吞掉。悬停提示只有这两条通道，**禁止原生 `title=`**，不再引入第三套气泡。内容装配两套共用 `lib/tip-body.js`（`.tip-label` + 可选 `.tip-key` 键帽），定位、延迟与触发属性各自独立；加键帽只传 `data-tip-key` / `data-tooltip-key`，不另写一套结构。
- **`Detail`**：鼠标侧键 3 是后退，4 不接。
- **`DetailCharacters` / `CharacterEditor`**：立绘走封面那条 `coverSrc` 管线 —— 缩图与 asset 协议授权都在那边做过。
- **`VnMergeDialog`**：单一取舍面板承载两层分区——元数据字段行与角色冲突行。角色区立绘随元数据区一起预取，面板关掉时结果作废。
- **`CharacterEditor`**：回选只在「角色列表变化」时发生（加载 / 增删 / 保存回填），用 `untrack` 让它只依赖 `characters`、不追踪 `selectedId`，用户手动点开或收起不会被抢回。
- **`SettingsDialog`**：打开时的初始化整块包在 `untrack` 里，让 `$effect` 只依赖 `open`。那段初始化读了主题、accent、排除标签等 store，不包的话任何 `notifyConfigChanged`（比如在侧边标签池里加一个标签）都会让 effect 重跑一次：表单字段被重新拉取覆盖，`poolOpen` 也被重置，侧栏当场收起。
- **角色档位与默认顺序单一来源**：`src-tauri/spec/character-roles.json` 定义档位与收录范围，`build.rs` 生成 `src-tauri/src/generated/character_roles.rs` 与 `frontend/src/lib/generated/character-roles.js`；前后端都不再各写一份 `main` / `primary` / `side` / `appears` 表（`check:generated` 与 `FISHVN_GENERATED_CHECK` 校验产物）。`SettingsDialog` 的「角色范围」段控件遍历生成的 `CHARACTER_SCOPES`，档位 id 由 spec 决定；切到含配角不弹二次确认，成本写在 hint 里；设置只影响之后的下载，不回头补齐已有角色。`char-merge.js` 与后端 `map_characters` 共用生成的排序方法：先主要后次要只作为**写入侧默认顺序**，读取层不改 `sort_order`——`CharacterEditor` 的上移/下移是用户语义，`replace_all` 按数组下标落库，展示层若按 role 强制重排会把手动顺序吞掉。
- **`PlaytimeField.svelte`**：总时长单输入框，失焦即 `update_game_state`。输入认 `12:30`、`12h30m` 与纯数字（按秒），右侧读数列显示秒；回填用无损写法（整分 `12:34`，带秒 `12:34:56`），认不出来的输入还原成原值。
- **输入组**（输入框 + 右侧内嵌按钮）：容器单边框，输入框无框伸缩（`flex:1` + `min-width:0`），按钮坐右侧、中间一条分隔线；容器 `:focus-within` 接管焦点高亮，点输入框或点按钮整个框一起亮；按钮 `min-width` 兜住两种文字宽度，切换时输入框不抖帧；内嵌按钮做成无底无框的附属动作（hover 只变文字色 + 出 `--bg-hover` 底），不与表单行里的主按钮同权重。与 `.num-stepper` 同构，「框 + 附属动作」的组合沿用这一只。
- **成组输入**：几个短字段同属一个语义组（宽高、三围这类）时并成一条外壳，不要各占一行——外壳只画外框、格间断竖线，组内 input 自身无框；组内标签可以压成单个字母或单位前缀，但 `.sr-only` 要补出全名（可访问名含可见标签，WCAG 2.5.3）。焦点由整格底色加格底内线承担，不套 `--focus-ring`：编辑区的焦点是中性强调（`--bg-raised` / `--border-strong`），accent 只表示选中身份。容器用 `role="group"` + `aria-label`，`fieldset` 的 `legend` 会在上边框留一道缺口；外壳 `overflow: hidden`，方角底色才能沿圆角收口。
- **chip 双选**：tag-pill 体系复用到非标签场景（同步导入名单这类「出现在表单里 = 选中」的清单）时，选中用实心、未选用幽灵（虚线 + 前景色透明化），`aria-pressed` 承载语义，点一下两态切换；chip 内只放条目名，状态与分组由组头承载，chip 里不重复。
- **补全页列表是「选中集 + 右栏对象 + 锚点」三个状态，不是一个 `selected`**：`backfillStore.picked` 保序存 id（`$state` 不代理 Set，Set 只用 `$derived` 做渲染查表），`selected` 是右栏那条、跟随最后点击，`anchorId` 只在不带修饰键的点击与 Ctrl 点选时移动。决策全收在 `backfill-list.js::pickOnClick` 纯函数（带单测）：Shift=区间、Ctrl/⌘=增减、Ctrl+Shift=并集；区间按当前 `items` 现算，被范围或「仅看无 ID」筛掉的行不会顺带选中，锚点自己被筛掉时退化为单选并把锚点挪过去。单击在集合只剩一项时清空并关面板，多选状态下收敛为单选——这一条决定了「多选后随手点一行」不会把整片选中一起丢掉。开跑只清 `picked`、不动 `selected`：右栏留着看结果；切范围或改筛选则裁掉不可见选中并 toast 条数，否则「补全所选」会跑用户看不到的条目。行只复用列表原有的点选样式 `.is-selected`（accent 左竖条 + `--bg-hover-strong`），`aria-pressed` 跟 `picked`——不为批量另造一套色，选中集本身就等于「这些行被点了」。按钮文案随 `picked.length` 变「补全所选 N 部」，选中恰好 1 条时左侧浮出 `.bf-shift-tip`「Shift+点击 选区间」，多选后自动收——Shift 是隐藏手势，提示只在该被用到的一刻出现。后端零改动：`start_backfill(game_ids)` 早已支持按 id 跑（重试失败走同一条），空集合时仍不带参、由服务端扫全部无资料行的条目。
- **`BackfillPanel` 的分支只看有没有 `vndb_id`**：未绑定的进面板就有搜索框与候选；有 ID 的给一个「换绑」展开同一套搜索。两条都走 `vn-merge-flow` 的候选 → 逐字段对比 → `accept()` 写入，不依赖跑过批留下的 `bind_source`，所以重启之后照样能改绑。头部是条目名与关闭按钮，名字超长省略、`data-tooltip` 补全，不再单列一行「游戏名」。已绑定条目的身份区自上而下是封面、标题，标题的 label 做成带下划线的小标题（`--text-sm` + medium），内容另起一行落在它下面；未绑定条目不渲染身份区（没有 VNDB 身份），提示「按游戏名搜索匹配」直接接在搜索框上方。身份区的封面单独一块居中，宽 `--backfill-panel-cover-w`（192px，3:4），读 `cover_path` 经 `coverSrc` 取本地缩略图，没有图时落首字占位；候选列表的封面另走 `--backfill-cand-w`（96px），两者不共用尺寸。底部两档：写操作用 ghost 按钮（换绑 / 重新补全，未绑定条目没有这一档），跳转（打开详情页 / 在编辑表单中打开）降成 `.bf-link` 文字链接。详情页跳转由 `App` 以 `onopendetail` 注入，面板不自己持有路由。日志区有两个数据源：本次会话从事件流直投页面内存，切到历史项时调 `backfill_run(id)` 回放落库事件；选择器用 `SelectDd`，本次会话没跑过时默认落在最近一次。
- **`Sidebar`**：导航图标条。`item.dot` 只表达两件事——任务在跑、或上一轮完结还没看；一个 6px 的 accent 圆点，在跑脉冲、完结静止，进入补全页即清。提示文案走 `data-tip`：在跑时带进度，完结时带汇总。不做计时器、不做数字角标，也不在补全页内重复显示；状态归约抽在纯模块 `backfill-status.js`（与 Svelte/DOM 解耦、可单测），只保留圆点与提示真会读的进度、暂停、限流与完结汇总，`run_id = 0` 的单条重试不进这里。库里刷新广播的契约见 [libs.md](./libs.md)。
- **`SyncResultDialog`**：重操作（VNDB 同步这类秒级拉取）点下即开弹窗进加载态，反馈先于结果出现，不等 await 返回才弹窗；加载态的阶段文案只消费后端进度事件，前端不虚构阶段。父级用序号令牌防迟到结果：每次触发自增序号，await 返回时序号已被新的触发或取消改掉就丢弃（`seq !== syncActive` 直接 return），旧请求的 plan / error 不会覆盖新状态；按钮的忙态只由最新一次在途调用置位与清除。计划内容分两步呈现：有冲突时第一屏只做裁决，第二屏是写入预览（推送与导入各自可取消勾选），底部按钮随步骤切换为「下一步」/「上一步 · 应用」；只有一类内容时不分步。应用阶段若涉及上传 VNDB，弹窗留在原地显示写入进度（进度事件 `phase` 为 `push`），期间 `onclose` 返回 `false`，Esc 与关闭按钮都不生效；按钮换成禁用的进度态，避免长任务中途留下半截状态。
- **`ImageViewer`**：单图查看画布。只管一张图怎么看：滚轮以指针为中心缩放、拖动图面平移、双击在适应窗口/100% 间切换、右上角缩放比、stage 尺寸变化时适应态保持整图可见。图源从外部注入 `src`，不关心图从哪来（封面缩略图或本地原图都行）；`maxZoom` prop 化——封面编辑器传 4（预览图最大边 560px，再大必糊），直开原图的场景可以传更大。`children` snippet 收 `{ toImage, toScreen, view }` 供浮层做坐标换算（取景框就浮在它上面）；单击图面（位移 < 4px）回调 `ontap(图坐标)`。viewport 纯函数在 `lib/image-viewer.js`（带单测）。**坑**：滚轮监听必须 `addEventListener('wheel', h, { passive: false })` 才能 `preventDefault`，Svelte 的 `onwheel` 属性写法不行——不加 passive 选项浏览器默认 passive，`preventDefault` 是静默无效的，页面会跟着滚。**边界**：多图导航、画廊、旋转、信息面板都是内核之外的层，挂在查看器外面——等真实需求来了再长，现在猜接口必然猜错；内核（视口数学 + 画布手势）保持不动。
- **`CoverFocalDialog`**：展示焦点的取景框编辑器（表单「调整展示位置」与展厅右键入口共用），画布是 `ImageViewer`，自己只做焦点数学（`lib/cover-focal.js`），参考画幅由 `aspect` / `aspectLabel` 注入。约定：焦点不参与合并面板（`vn-merge.js` 的 `FIELDS` 不加它，远端没有这个概念）；换图归位由 `metadata::upsert` 按图路径是否变化判定，调用方不写重置补丁；前端 picker 取消时不落库、靠 `AmbienceMenu` 的 `{#key}` 回弹显示值；新增展示处要读自己的焦点字段。手势路由：拖框与拖图面是两个区域的手势——取景框自己收 pointer 事件并 `stopPropagation`（否则画布会跟着平移），框外区域归画布（拖动平移、单击移框）；方向键微调焦点（Shift 加速，无效轴忽略），弹窗打开即聚焦到根容器。
- **`InstallationList`**：安装行 = 单选圆点 + `.install-main`（路径框 + `.install-flags`）。flags 区两个开关各自成行，形态对齐设置页的 `toggle-switch` + 标签，不加说明文字（开关本身自明）：转区启动一行；Magpie 缩放一行，行右挂两态段控件（全屏 / 窗口），开关关闭时段控件禁用置灰——开关即 `magpie` 的 off，开启默认落 `full`。段控件复用设置页的 `seg-radio-group` / `seg-radio-item`（label 包隐藏 radio、纯自定义样式，不用原生控件外观），radio 的 `name` 按 `item.key` 隔离防多行串组。flags 块整体缩进 + 左竖线，表明从属于该安装行；圆点与移除按钮都只跟路径框行对齐（移除是 `btn btn-danger`，跟角色面板的移除同一按钮语言）。转区开着时参数框禁用、placeholder 换成「转区时无法附加参数」（LE 链路不透传；别在禁用 input 上挂 tooltip——浏览器不派发鼠标事件给 disabled 控件，hover 永远不触发）。
- **`SettingsDialog` 的「工具」标签**：登记 Magpie / Locale Emulator 两个工具路径。失焦即保存（`oncommit`）：trim 后为空发 `null` 注销，非空先 `path_exists` 校验、不存在出行内错误且不落库，通过了才 `update_config` + 广播 `CONFIG_CHANGED`。浏览选完文件同样触发提交——`PathField` 的 `oncommit` 在 pick 成功后也会调，不只是 blur。
