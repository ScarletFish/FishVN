# 封面墙网格布局

封面墙的网格规格。参数已在 1100 / 1440 / 1920 / 2560 视口实测校验。

## 规格

```css
--card-w: 17.3125rem;  /* 277px —— 卡宽固定 */

.cover-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, min(var(--card-w), 100%));
  gap: var(--space-4);
}
```

chrome 固定不随视口缩放：侧栏 `var(--sidebar-w)`（3.75rem / 60px）+ 视图 padding `var(--space-8)`（32px×2）。

卡片 `aspect-ratio: 3 / 4`（竖版封面，高:宽 = 4:3），实测比例 1.338。

`min(var(--card-w), 100%)` 是防溢出兜底 —— 固定尺寸的轨道在容器窄于一列时会溢出，`100%` 让它退化为单列满宽。正常桌面宽度（S ≥ 1156）下不生效，取值即 `--card-w`。

## 实测列数

| 视口 | 内容区 S | 列数 | 卡宽 | gap |
|---|---|---|---|---|
| 1100 | 961 | 3 | 277px | 20px |
| 1440 | 1316 | 4 | 275px | 20px |
| 1920 | 1781 | 5 | 277px | 20px |
| 2560 | 2436 | 8 | 277px | 20px |

1440 实测：卡片 x 起于 92 / 436 / 781 / 1127，步距 344px = 275 + 20×3 摊平。左右边距 32px / 32px。

## 卡宽为什么必须固定

下面三件事都依赖卡宽恒定：

1. **窗口化**（虚拟滚动）—— `row = floor(index / cols)` 要靠卡宽算出 `cols`
2. **详情页 FLIP 转场** —— 卡片与详情页封面共用裁切参数，宽度浮动会在动画结束时产生跳变
3. **横滑推荐区与主网格对齐** —— 两者共享同一卡宽档位，视觉才连贯

## 不要引入 minmax 下限

`minmax(200px, 277px)` 与 `277px` 的**列数、轨道宽完全相同**。实测把下限从 200 依次提到 240、270，四个视口下输出逐字节一致：

| 视口 | S | `277px` | `minmax(200,277)` | `minmax(240,277)` | `minmax(270,277)` |
|---|---|---|---|---|---|
| 1920 | 1781 | 5列 277 | 5列 277 | 5列 277 | 5列 277 |
| 2560 | 2436 | 8列 277 | 8列 277 | 8列 277 | 8列 277 |
| 1440 | 1301 | 4列 277 | 4列 277 | 4列 277 | 4列 277 |
| 1100 | 961 | 3列 277 | 3列 277 | 3列 277 | 3列 277 |

带上限的 `auto-fit` 由 MAX 同时决定列数与轨道宽，下限不起作用。留一个不生效的下限 token 是负债 —— 后人会去调它，然后发现没反应。防溢出交给 `min(..., 100%)`。

## 不要加 justify-content: space-between

与固定 gap 搭配时会撑大列间距：1440 视口下实测 gap 从 20px 变成 69px。`auto-fit` 已保证贴满，无需手动分配余量。

## 容器宽度由谁决定

`auto-fit` 基于**容器实测宽度**，不是视口。窗口 resize、DPI 缩放都由浏览器和 `ResizeObserver` 处理，不需预测。

窗口化实现必须遵守：**列数在 JS 侧从实测容器宽算出，CSS 侧写成显式列数**（`repeat(N, var(--card-w))`），不让 CSS 的 `auto-fit` 决定 —— 否则列数公式会散落在 JS 和 CSS 两处，改一处就可能不同步。

## 待定

- **窗口化阈值**：多少个条目以上启用
- **卡片宽高比**已定为 3:4；窗口化下 `rowH = cardW × 4/3 + gap`，需与实际封面比例一致
