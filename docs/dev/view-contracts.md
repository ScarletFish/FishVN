# 视图契约与数据流 — View Contracts

## 聚合与实体所有权

一部作品是一个聚合，由四组数据描述：

| 组 | 字段 |
|---|---|
| 身份 | `name` · `vndb_id` |
| 用户状态 | `status` · `user_rating` · `notes` · `default_installation_id` |
| 本地安装 | `dir_path` · `entry_path` · `exes` · `size_bytes`（一部作品可有多条） |
| 元数据 | 别名与本地化标题 · 封面 · 发行日期 · 评分与人数 · 平均通关时长 · 简介 · 标签 · 开发商 · 制作人员 |

**聚合是逻辑边界**，定义「什么属于同一个游戏」。加载单位由消费方各自决定。

各组独立成立：没有 VNDB 绑定的作品照样能记，没有本地目录的作品也能进列表。表的归属与写者见 [backend.md](./backend.md)。

角色与游玩记录是聚合内的子实体集合（`0..*`），不占这四组。

## 三个消费方

| 消费方 | 读什么 | 何时取 |
|---|---|---|
| 列表 | 摘要投影 | 进入列表时一次取全量，常驻内存 |
| 详情 | 详情投影 | 打开单条时按需取 |
| 表单 | 可写子集 | 初始值由调用方传入 |

投影是 selector（纯函数）从聚合里 select 出来的子集，每个消费方只声明自己要哪些字段，同一个字段可以出现在多个 selector 里。

## 字段归属判据

> 这个字段被哪个 selector 渲染？
> - 列表 selector 用 → 进摘要投影
> - 详情 selector 用 → 进详情投影
> - 表单 selector 用 → 进可写子集
> - 保留在聚合 schema 里，等有了消费方再暴露

再加一问，它决定写权限：

> 这个字段是用户输入、系统派生、外部元数据，还是本地事实？

| 类别 | 字段 | 写权限 |
|---|---|---|
| 用户输入 | `name` · `status` · `user_rating` · `notes` · `play_seconds` | 表单自由编辑；`status` / `user_rating` 另有同步写路径：账户同步计划确认后按逐字段决策写，见「同步对用户状态的写路径」 |
| 系统派生 | `created_at` · `play_count` · `last_played_at` · `foreground_seconds` · `alive_seconds` · `installation_count` · `can_launch` | 由动作产生 |
| 外部元数据 | 别名与本地化标题 · 封面 · 发行日期 · 评分与人数 · 平均通关时长 · 简介 · 标签 · 开发商 | 同步逐字段比对库里现值与新值，不同的字段进冲突面板，由用户逐字段选覆盖或跳过；JSON 列整列替换 |
| 本地事实 | `dir_path` · `entry_path` · `size_bytes` | 表单的安装行里用文件对话框挑启动文件，路径也可手工输入；`entry_path` 存相对 `dir_path` 的路径 |

`installation_count` · `can_launch` 与四个游玩聚合值是查询期算出来的，其余系统派生字段有列，写者见 [backend.md](./backend.md)。`play_seconds` 有列：用户可任意改写，结算时系统在它上面累加。

## 字段落位

| 字段 | 出现位置 | 说明 |
|---|---|---|
| `name` | 列表 · 详情 · 表单 | 用户指定，同时是搜索词与详情主标题 |
| 元数据（别名 · 封面 · 发行日期 · 评分与人数 · 简介） | 详情 · 表单 | 表单经「同步元数据」填充；详情按需再取 |
| `tags` · `developers` | 详情 · 表单 | JSON 列，冲突粒度是整列替换 |
| `titles` | 详情 | JSON 列，本地化标题，只读展示 |
| `notes` · `default_installation_id` | 详情 | 全文随每条返回会让列表载荷无谓膨胀 |
| `vndb_id` | 列表 · 详情 | 绑定走「搜 VNDB → 选中」动作 |
| `status` | 列表 · 详情 · 表单 | 五取值任意跳转，表单里五个选项全开；用户会记错状态，必须能改回来 |
| `installations[]` | 详情 · 表单 | 表单里增减启动路径、指定默认；详情展示解析出的默认启动路径，与启动目标同源（默认项失效回落第一条有入口的），点击进表单「安装」页 |
| 游玩记录（`play_sessions[]` 与时长、次数、最近游玩的聚合） | 详情 | 列表不取；有进行中的记录时按固定间隔重取，直到它结算 |

## 加载策略

摘要投影随列表一次取全量并常驻内存。个人库规模在几千条以内，摘要投影每行十来个字段，整体体积不构成压力。

**重字段按需再取**：元数据简介、截图、目录内文件清单、游玩历史。判据是这个字段大不大，与它属不属于这部作品无关。

游玩记录按需取：详情打开时取一次；有进行中的记录时每 5 秒重取一次，结算后取最终值。

聚合按需取用：打开详情取一次，关闭即释放。重取单条聚合是一次本机往返，成本可忽略。

## 启动页

启动页是 index.html 里的静态覆盖层（品牌标记 + spinner），纯 HTML/CSS，JS 加载前就可见。背景取 `--bg-page`（浅 `#f1f0ec` / 深 `#121212`，跟主题走），与窗口底色、主界面页面底同值，淡出前后零跳变；tokens 随 JS 包才到，首帧靠 var 内的字面量兜底，取值与 token 严格一致。

就绪信号是 MyList 首次列表加载渲染完成派发的 `app:ready` DOM 事件；main.js 收到后 300ms 淡出并移除 DOM。信号的派发天然幂等（监听 once、splash 移除后为空），详情返回列表重挂 MyList 再派发也是 no-op。两条兜底：JS 活着但数据卡死时 8 秒超时强制移除；浏览器 dev 环境没有启动等待，直接移除。

主题持久化分两层：config.json 是权威（Rust setup 读它涂窗口底色），localStorage 是首帧缓存（index.html 的主题钩子同步读它，保证下次启动第一帧主题正确）。App 挂载后以 getConfig 结果校正两者；校正发生在 splash 淡出之前，跳变被盖住。

## 数据流与写后行为

聚合的权威在后端。selector 只读，视图呈现的每一条状态都经过后端确认；`play_count` 这类系统派生字段由后端维护。

写操作的顺序固定：

1. 提交到后端
2. 以数据层返回的结果为准
3. 重拉受影响的数据
4. 通知视图重新 selector

重拉是一次 `invoke` 调用 —— 前端跑在 WebView 里，与后端同在 Tauri 进程，经 IPC 往返。

| 操作 | 写后去向 |
|---|---|
| 新增 | 回列表，新条目短暂高亮 |
| 编辑 | 回详情 |
| 同步应用 | 重拉受影响的数据：列表投影、已开着的详情、首页统计各自刷新 |
| 资料补全 | 完结后重拉列表投影 |

### 同步对用户状态的写路径

`status` / `user_rating` 除表单外还有一条写路径：外部账户同步（如 VNDB 用户列表）计划确认后落库。这条路径与表单写同一张表、同一个权威，落库后各消费方照常重拉，与表单写入走同一条刷新链路。写前按三路比对判定（本地现值 / 上次同步快照 / 上游现值），本地改过的字段进冲突集交用户逐字段选，勾选结果随计划一次提交；判定口径见 [backend.md](./backend.md) 的「外部数据同步：计划-应用两段式」。

## 表单

表单是纯受控组件，初始值由调用方传入。新增传默认值，编辑传从聚合 select 出的当前值。

新增与编辑同源 —— 同一个组件，按 mode 区分提交目标。

编辑表单的字段集是用户输入类四个加上元数据（见「字段归属判据」的外部元数据一行）。元数据由「同步元数据」动作填充，差异在冲突面板逐字段取舍。绑定走独立的搜索动作，本地启动路径在「安装」页里增减。

## 导航与视图状态

列表与详情之间是整页切换 —— 详情内容多。

返回时还原列表的筛选状态与滚动位置，存在视图状态里。筛选与排序属于列表视图状态。

## 删除作品

删作品走 `ON DELETE CASCADE`：库内登记（含安装记录）一并移除，磁盘文件不动。

界面文案要说明「删除作品记录不会删除磁盘上的文件」。

## 空状态与关键路径

空列表给手动添加入口：先建作品，再到表单的「安装」页指定本地启动路径。

## 重审条件

- 引入窗口化渲染或虚拟列表 —— 摘要投影常驻的前提要重新评估
- 元数据加入截图一类大字段 —— 「重字段」的边界要重新划
- 后端引入推送通道 —— 数据流里的重拉可以换成订阅
