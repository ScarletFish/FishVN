# 视图契约与数据流 — View Contracts

## 聚合与实体所有权

一部作品是一个聚合，由四组数据描述：

| 组 | 字段 |
|---|---|
| 身份 | `name` · `vndb_id` |
| 用户状态 | `status` · `user_rating` · `notes` · `default_installation_id` · `play_count` · `last_played_at` |
| 本地安装 | `dir_path` · `entry_path` · `exes` · `size_bytes`（一部作品可有多条） |
| 元数据 | VNDB 标题 · 封面 · 评分 · 简介 |

**聚合是逻辑边界**，定义「什么属于同一个游戏」。加载单位由消费方各自决定。

各组独立成立：没有 VNDB 绑定的作品照样能记，没有本地目录的作品也能进列表。表的归属与写者见 [backend.md](./backend.md)。

## 三个消费方

| 消费方 | 读什么 | 何时取 |
|---|---|---|
| 列表 | 摘要投影 | 进入列表时一次取全量，常驻内存 |
| 详情 | 详情投影 | 打开单条时按需取 |
| 表单 | 可写子集 | 初始值由调用方传入 |

投影是 selector（纯函数）从聚合里 select 出来的子集，每个消费方只声明自己要哪些字段，同一个字段可以出现在多个 selector 里。

## 字段归属判据

> 这个字段被哪个 selector 渲染？
> - 列表 selector 用 → 进摘要投影
> - 详情 selector 用 → 进详情投影
> - 表单 selector 用 → 进可写子集
> - 保留在聚合 schema 里，等有了消费方再暴露

再加一问，它决定写权限：

> 这个字段是用户输入、系统派生、外部元数据，还是本地事实？

| 类别 | 字段 | 写权限 |
|---|---|---|
| 用户输入 | `name` · `status` · `user_rating` · `notes` | 表单自由编辑 |
| 系统派生 | `created_at` · `play_count` · `last_played_at` · `installation_count` · `can_launch` | 由动作产生 |
| 外部元数据 | VNDB 标题 · 封面 · 评分 · 简介 | 只读；同步填空字段 |
| 本地事实 | `dir_path` · `entry_path` · `size_bytes` | 通过目录选择器替换 |

`installation_count` 与 `can_launch` 是查询期算出来的，其余系统派生字段有列，写者见 [backend.md](./backend.md)。

## 字段落位

| 字段 | 出现位置 | 说明 |
|---|---|---|
| `notes` · `default_installation_id` | 详情 | 全文随每条返回会让列表载荷无谓膨胀 |
| `vndb_id` | 列表 · 详情 | 绑定走「搜 VNDB → 选中」动作 |
| `status` | 列表 · 详情 · 表单 | 四取值任意跳转，表单里四个选项全开；用户会记错状态，必须能改回来 |
| `installations[]` | 详情 | 呈现为列表 |
| 未认领目录 | 独立入口 | 与扫描视图并列 |

## 加载策略

摘要投影随列表一次取全量并常驻内存。个人库规模在几千条以内，摘要投影每行十来个字段，整体体积不构成压力。

**重字段按需再取**：元数据简介、截图、目录内文件清单、游玩历史。判据是这个字段大不大，与它属不属于这部作品无关。

聚合按需取用：打开详情取一次，关闭即释放。重取单条聚合是一次本机往返，成本可忽略。

## 数据流与写后行为

聚合的权威在后端。selector 只读，视图呈现的每一条状态都经过后端确认；`play_count`、目录认领这类系统派生字段由后端维护。

写操作的顺序固定：

1. 提交到后端
2. 以数据层返回的结果为准
3. 重拉受影响的数据
4. 通知视图重新 selector

重拉是 HTTP 往返 —— 前端跑在 WebView 里，与后端之间始终是本机 HTTP。

| 操作 | 写后去向 |
|---|---|
| 新增 | 回列表，新条目短暂高亮 |
| 编辑 | 回详情 |

## 表单

表单是纯受控组件，初始值由调用方传入。新增传默认值，编辑传从聚合 select 出的当前值。

新增与编辑同源 —— 同一个组件，按 mode 区分提交目标。

普通编辑表单的字段集就是用户输入类那四个。绑定走独立的搜索动作，本地目录通过目录选择器替换。

## 导航与视图状态

列表与详情之间是整页切换 —— 详情内容多。

返回时还原列表的筛选状态与滚动位置，存在视图状态里。筛选与排序属于列表视图状态。

## 删除与未认领目录

删作品走 `ON DELETE SET NULL`：本地目录记录保留为未认领，磁盘文件不动。

界面文案要说明「删除作品记录不会删除磁盘上的文件」，未认领目录要有独立入口或徽标 —— 删掉一部作品后用户的第一个问题就是「我那些文件去哪了」。

## 空状态与关键路径

空列表给两个入口：手动添加、扫描本地目录。

本地库用户的游戏通常已经在磁盘上，扫描是首次使用的关键路径之一，优先级不低于详情页。

## 重审条件

- 引入窗口化渲染或虚拟列表 —— 摘要投影常驻的前提要重新评估
- 元数据加入截图一类大字段 —— 「重字段」的边界要重新划
- 后端引入推送通道 —— 数据流里的重拉可以换成订阅
