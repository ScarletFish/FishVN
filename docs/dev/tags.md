# 标签展示与过滤

> 范围：VN 标签在详情页与仪表盘词云的可见性、排序、计数口径与候选列表规则。
> 本文只写规则。为什么这样定、否掉了哪些替代方案，记在 [fdd-game-library.md](../fdd-game-library.md) 的 1.6 节与各活动集条目里。
> 译名数据来源与许可证见 [vndb-localization.md](vndb-localization.md)，显示名查表与加载见 [i18n.md](i18n.md)「VNDB 标签/特征中文显示」。

## 三层判定

| 层 | 决定 | 数据 | 归属 |
|---|---|---|---|
| 出厂范围 | 该标签能出现在哪些界面 | `tag_groups.json` 的 `roots` / `excluded` | 换 dump 时重跑生成脚本 |
| 内容状态 | 当前设置下是否显示 | 标签自带 `lie` / `spoiler` / `category` + 剧透档位、R18 开关 | 用户设置 |
| 个别偏好 | 单条标签例外隐藏 | 排除池 `excluded_tags` | 用户设置 |

三层依次生效，下层不翻上层的结论：被出厂范围挡下的标签，进排除池也不改变结果。

排除池初始预置了 VNDB 最通用的 14 个标签（分类根一类），用户看不到来源时不必惊讶——它们在池子里可以逐条删除。这条只在文档里记录，界面不再交代。

出厂范围三档：

| 档 | 判定 | 详情页 | 词云 |
|---|---|---|---|
| `hidden` | 在 `excluded` 里（技术向：立绘查看器、跳过场景一类） | — | — |
| `detail` | 根为舞台 `g22` / 情节 `g24` / 风格 `g674` | 显示 | — |
| `full` | 根为题材 `g1` / 角色 `g20`、手输标签、字典未收录的新 id | 显示 | 统计 |

`roots` 的值是五个根 id：`g1` 题材、`g20` 角色、`g22` 舞台、`g24` 情节、`g674` 风格。字典未收录的 id 与无 id 的手输标签按 `full` 处理，新标签随同步自然进入统计。

## 展示分类

`tagCategory(tag)` 返回八个分类：`custom`、`theme`、`character`、`setting`、`plot`、`style`、`other`、`tech`。判定顺序：无 id → `custom`；id 在 `excluded` 里 → `tech`；`roots[id]` 命中五根 → 对应分类；其余 → `other`。入参可以是标签对象或裸 id。

`tagScope` 是分类上的一张表：`custom` / `theme` / `character` / `other` → `full`，`setting` / `plot` / `style` → `detail`，`tech` → `hidden`。分类只决定分组与范围，不参与内容状态与排除池的判定。

表单里已选的标签与库内标签选择器都按分类分组：`custom` 置顶，`tech` 垫底，空组不渲染。手输标签保持录入顺序，不参与组内权重排序。

表单输入行按名字接管库内标签：写下的名字与库内条目同名（显示名、VNDB 原名任一命中，忽略大小写）时存成带 id 的条目，没有命中才落成 `{name}`。这样同一个标签不论从输入行还是选择器加进来，存下来的都是同一个键。

标签有两层身份：存储层锚定「VNDB 原名 + id」（稳定，供同步、聚合与后端清洗），显示层是字典翻译、无 id 回退存储名（用户所见的一切）。表单判重一律按显示名（`TagField` 的 `dupKeyOf`）：输入行重名拒加并提示「库内已有重名标签」，回车改为让已有药丸脉冲定位；选择器候选以显示名为键，手输与字典同名只出现一条（手输优先），点选按显示名增删。渲染与单条删除用 `tagKey`（`id ?? tag ?? name`）定位条目。表单打开即预载字典与库内标签，保证判重键全程稳定。`ensure_schema` 末尾跑一遍 `dedupe_metadata_tags` 清洗存量：按存储名去重，重名时保留带 id 的条目，幂等可反复执行；显示名重复而存储名不同的条目不在此列，由用户手动删除。

## 两端一份数据

Rust 侧 `TagGroups::scope` 供词云在聚合后过滤，前端侧 `tagCategory` 与 `tagScope` 供详情页、候选列表与分组展示使用，二者读同一份 `tag_groups.json`。五个根 id 与 `excluded` 的语义是跨端契约：改字典结构时两处一起改，`tagdict.rs` 与 `tag-order` 的测试各守一份。

## 各消费面套用的层

| 消费面 | 套用的层 |
|---|---|
| 仪表盘词云 | `scope == full`、`lie`、剧透档位、R18、频次 ≥ 2、排除池 |
| 详情页标签区 | `scope != hidden`、`lie`、R18、排除池、剧透档位（折叠） |
| 角色 traits | Sexual 组、剧透档位（trait 无五根，排除池按标签设计） |
| 排除池候选 | `scope != hidden` |
| 游戏表单候选 | 全量，技术向单列一组排在末尾 |

候选列表按条目自身的出厂属性过滤；R18、剧透、频次、排除池由消费面在渲染时套用。关掉 R18 过滤或切换剧透档位时候选集合保持不变，已进池的条目始终能在候选里找回。

## 前端判定入口

`lib/tag-order.svelte.js` 的 `classifyTags(tags, { hideR18, spoilerLevel, excludedTags, revealSpoilers })` 是详情页唯一的标签判定入口，返回：

- `shown` —— 当前剧透开关下要渲染的标签，已排序
- `spoilers` —— 被档位折叠的标签，已排序
- `poolCount` —— 被排除池挡掉的条数

计数口径：`poolCount` 只统计否则会可见的条目——被 `lie`、R18、`hidden` 挡下的条目不计数；剧透标签在折叠态不计数，展开后计入。新增展示面复用这三项，计数与判定一起产出。

`revealSpoilers` 与展开态绑定：详情页收起后剧透标签回到 `spoilers`，折叠态的 8 条预览里不出现剧透标签。

## 排序

按 `rating` 降序，同分时 `vn_count` 升序（稀有优先）；再按题材、情节、角色、舞台、风格做轮转交错：手输标签整组前置，字典未收录 id 的沉底。分组表未加载时退回纯 `rating` 排序。展开剧透时把折叠标签并回同一套排序。

## 排除池的键

字典标签按 id 命中，手输标签按名称命中；条目有 id 时按 id 匹配，名称不参与。候选列表暴露的键与池内存储的键同源（`id ?? 名称`），两处口径一致才能在候选与胶囊之间来回切换。

## 数据契约

- `roots` 覆盖全部可挂载标签，与 `excluded` 互斥：一个 id 只出现在其中一处。
- `excluded` 按字符串升序排列，Rust 侧据此二分查找。
- 预置排除池的每一条都必须 applicable、有中文译名、范围不是 `hidden`；两项测试守着这条约束，换 dump 时自动报警。
- 库内标签与词云按显示名聚合：同步标签与手输的同名标签并成一条，代表 id 取该名下首个带 id 的条目。

## 数据量假设

词云与库内标签各自全量解析一次 `game_metadata.tags`。几百部作品内开销可忽略；到千部量级且解析成为瓶颈时，改为同步阶段维护一张标签计数表。
