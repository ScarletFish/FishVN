# 界面文案规范 — Wording

界面上的名字跟数据模型不是一套。模型要说清聚合与子实体，界面只说用户手上在动什么 —— 所以 FDD 里叫「作品」「本地安装」「元数据」的东西，界面上是「游戏」「启动项」「资料」。

文风参考阮一峰《[中文技术文档的写作规范](https://github.com/ruanyf/document-style-guide)》：短句、陈述、少形容词。下面只写界面特有的部分。

## 概念

**游戏** —— 库里的一条记录，模型里叫作品（Entry）。界面上一律称游戏：添加游戏、游戏名、删除游戏、游戏库。不用作品、条目、内容、项。

量词用「部」—— 共 12 部游戏、已补全 3 部。不用「个」：一部游戏是个整体，说「个」就散成零件了。

**启动项** —— 一条启动配置，模型里叫本地安装（Installation）：启动文件、是否转区、Magpie 缩放、附加参数。「启动文件」只指那个 exe 路径，不指整条配置。

所以是「添加启动项」，在里面填「启动文件路径」。「未设置启动文件」说的是 exe 没填，成立。

**游玩时长** —— 一部游戏累计的游玩时间，模型里叫总时长。界面只写「游玩时长」，不写总时长、累计时长。统计模块的「累计时长 / 本周时长」是口径对比，成对出现，不算另一个词。

**评分** 有三个所指：我的评分（用户自己打的）、评分（VNDB 均分）、评分人数。同屏出现时不省前缀。

**资料** —— VNDB 给的封面、简介、标签、角色、制作人员，模型里叫元数据。动作叫「下载资料」。任务面板里同一件事简称「补全」，只在进度语境用。

**同步** —— 比对本地与 VNDB、列出计划、确认后写入。跟「下载资料」是两件事：下载资料不问、直接改本地；同步必须先出计划。

**状态** 五个固定词：游玩中、计划中、已完成、已弃坑、已搁置。不造新词，不加修饰。

**拉取、抓取、获取** 是内部说法，界面上不出现，对应动作就是「下载资料」或「同步」。

## 动作

**删除 / 移除** —— 实体连同数据一起消失用删除（游戏、角色、制作人员）；从某个集合里摘掉、实体还在用移除（标签、声优、启动项、排除池成员）。

**添加 / 新建** —— 一律「添加」。同一菜单里的并列项共用一个动词：手动添加、从启动文件添加、扫描目录添加。

## 量词

部（游戏）、条（列表条目、错误）、项（标签、字段、候选）、个（目录、文件）。

## 语气

陈述句，工具口吻。不用语气词（吧、哦、啦），不用感叹号，不用问句引导。

空态写「暂无 X」或「还没有 X」，不带语气词，也不重复按钮名。

表单校验说清问题，不下指令 —— 写「游戏名不能为空」，不写「请填写游戏名」。

## 格式

中英、中数之间一个半角空格；全角标点前后不留空格；并列词用顿号，末项用「和」或「与」；数值范围用「～」不用半角连字符（`0～100`）；省略号用单字符 `…`，进行时态不省（`加载中…`，但后面紧跟进度的 `正在补全 3/12` 不加）。

界面文案一律不加句号。

## 落盘

全部在 `frontend/src/lib/i18n-zh.js`，一处改、处处生效。组件里不留中文字面量，例外三类：选文件对话框的 filter 名、图片查看器的无障碍兜底标签、日志与内部错误。

占位符交给 `t()` 替换，不在组件里拼字符串。
