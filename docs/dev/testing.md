# 测试写法 — Testing

前后端同口径。

## 用例的构成

一条测试由三部分构成：有区分力的输入、独立来源的期望值、落到可观察结果的断言。

| 组成 | 写法 |
|---|---|
| 有区分力的输入 | 先放入结果一旦算错就会丢掉或变化的那份数据：建表幂等先建一条作品，缓存失效先存一份计划再改本地状态，非法还原先放一个备份，合并前先放一份会被覆盖的本地值 |
| 独立来源的期望值 | 以具体内容写进用例（文本、数值、集合、文件内容），来源是实抓 fixture、手抄常量、规格 / 源码文本、生成物键表，或另一条独立路径的读数 |
| 落到可观察结果的断言 | 断言落在领域返回值、再次读取的数据、库内 / store 最终状态（含未变）、磁盘产物、界面文案、DOM 里的可见内容、发给前端的事件、本地 mock 收到的调用参数，断言里出现期望内容本身 |

## 专项口径

- **用例名即契约**：用例名写「场景 + 期望结果」，名字里每个结果对应一条断言；失败定位由中文用例名与文件头意图注释承载，`expect(value, message)` 用于需要额外说明的断言。
- **反例自检**：写用例时同时给出使它变红的实现改动，作为该用例的验收依据；反例随用例写进测试文件的意图注释（`src-tauri/tests/**` 与 `frontend/src/**/*.test.js` 均在白名单，见 [comments.md](./comments.md)），它是测试规格的一部分。lib 内单测沿用 comments.md 的知识去处。
- **确定性**：时间与并发经注入时钟或纯函数表达，断言确定性的输入与输出；后端请求指向本地 axum server、响应由 fixture 驱动，前端用 `vi.useFakeTimers()` + `advanceTimersByTime` 推进时间、`vi.mock` 掉 `api.js` 的调用。
- **契约用例的归属**：规格、生成物、路由表、键集合的一致性由第二来源校对，集中在后端 `src-tauri/tests/character_spec.rs` / `devhttp.rs` 与前端 `*.contract.test.js` / `character-fields.test.js` 这类 spec / parity 套件，钉住静默丢字段、串列、漏路由。

## 错误路径分档

| 场景 | 断言 |
|---|---|
| 后端写命令失败 | 用户收到的中文提示 + 库内数据未变 |
| 后端只读命令失败 | 用户收到的中文提示 |
| 前端交互失败（保存 / 提交 / 删除） | 界面提示文案 + 视图状态未变 |
| 前端纯函数校验失败 | 具体返回值或提示文案 |

## 核对清单

新增或改动用例时逐项核对：用例名 → 输入里的区分点 → 期望值来源 → 断言落点 → 失败说明 → 反例自检。

后端专项见 [backend.md](./backend.md)「外部 API 的测试」；前端自动检查见 [frontend.md](./frontend.md)「自动检查」。
