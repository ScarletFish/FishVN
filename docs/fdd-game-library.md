# 作品库功能需求文档

> 本文覆盖 FDD 前五过程里的前两步（开发整体模型、构建功能列表），并为后三步（按功能计划 / 设计 / 构建）提供分活动集的落点。

## 文档说明

- **范围**：作品库（Galgame 本地管理）领域的全部功能需求，按五个活动集组织。
- **状态标注**：每个功能标注当前落地情况，基于编写当日（2026-10-16）对代码与命令层的核对，不代表最终设计变更：
  - `已实现` —— 后端命令与前端流程均已接通。
  - `部分实现` —— 核心已通，存在明确缺口（在备注中说明）。
  - `待实现` —— 后端或前端尚未接通，或仅 API 层就绪、缺用户流程。
- **核心思路**：作品条目独立，可进行四个维度（身份、用户状态、本地安装、VNDB元数据）数据的编写，并管理其下属的角色（见活动集五）。特此说明一点：VNDB同步产生的字段值为建议值，用户可选是否采纳。`vndb_id` 可空且 `UNIQUE`（NULL 之间不冲突），后续功能描述不再逐条重复此原则。

## 1. 整体模型（领域模型）

### 1.1 关键抽象

| 概念 | 说明 |
|---|---|
| 作品（Entry） | 库中的一条游戏记录，是聚合根。用户收藏与管理的基本单位。 |
| 作品身份 | 作品的标识与展示名，不依赖任何外部源。 |
| 用户状态 | 用户对作品的主观标记：状态、个人评分、笔记、游玩时间与次数。 |
| 本地安装（Installation） | 作品在磁盘上的目录与启动入口，一部作品可有多条。 |
| 元数据（Metadata） | 别名、本地化标题、封面、发行日期、评分与人数、简介、标签、开发商。 |
| VNDB 绑定 | 作品与 VNDB 条目之间可选的关联关系，由 `vndb_id` 表达。 |
| 角色（Character） | 一部作品下的出场人物，是作品的子实体：立绘、名字、原名、性别、年龄、尺寸、出场定位、简介。VNDB 上同一角色在不同作品里是不同条目（详略与立绘各不相同），故按作品各存一行，不建共享本体。 |
| 声优（Staff） | 为角色配音的人，全局表；与角色的配音关系带版本标记，同一对角色与声优可有多条。 |

### 1.2 聚合边界

一部作品是一个聚合，由四组相互独立的字段描述：

| 组 | 字段 | 能否脱离 VNDB 成立 |
|---|---|---|
| 身份 | `name` · `vndb_id` | 能。`vndb_id` 为空时作品照样存在。 |
| 用户状态 | `status` · `user_rating` · `notes` · `default_installation_id` · `play_count` · `last_played_at` | 能。纯用户数据。 |
| 本地安装 | `dir_path` · `entry_path` · `exes` · `size_bytes`（可多条） | 能。来自磁盘，与 VNDB 无关。 |
| 元数据 | 别名与本地化标题 · 封面 · 发行日期 · 评分与人数 · 简介 · 标签 · 开发商 | 此组是 VNDB 的数据来源，但即使全空，作品与元数据行仍存在。 |

聚合是逻辑边界，定义"什么属于同一部作品"；加载单位由消费方各自决定。

角色是聚合内的**子实体集合**而非字段组：一部作品下有多行，按作品整包替换，随作品删除而级联清除（声优是跨作品复用的全局表，不在此列）。

### 1.3 关系

```
作品 1 ──0..1── VNDB 绑定（vndb_id）
作品 1 ──0..*── 本地安装（installations.game_id，NULL = 待认领）
作品 1 ──1───── 元数据行（game_metadata，每列可空）
作品 1 ──0..*── 角色（characters.game_id，按作品整包替换）
角色 1 ──0..*── 配音关系（character_va，带版本标记）
声优 1 ──0..*── 配音关系（staffs 为全局表，不随作品删除）
```

读法：箭头两端是「一个 X 对应几份 Y」。`1` = 恰好一份，`0..1` = 零或一份（可选），
`0..*` = 零到任意多份（`*` 就是「多」，不限上界）。

### 1.4 不变约束

- `vndb_id` 可空且 `UNIQUE`：NULL 之间不判重；重复绑定已占用 `vndb_id` 的条目报冲突。
- 删除作品走 `ON DELETE SET NULL`：本地安装记录保留为未认领，磁盘文件不动。
- 元数据每列均可由用户手改；同步不按"哪些列空了"判断该不该写，而是逐字段比对现值与新值，差异交给用户逐字段选覆盖或跳过。
- 外键列（`game_id` / `default_installation_id`）写入前判空串，空串按非法输入拒掉。
- 角色以作品为单位整包替换：先删该作品的全部角色行（配音关系靠外键级联），再按数组顺序写回。数组下标即顺序，客户端给的 `sort_order` 不采信。
- 删除作品级联清掉 `characters` 与 `character_va`；`staffs` 是跨作品复用的全局表，行在失去最后一个配音关系时回收——不论那条关系是被删作品、删角色还是整包替换带走的。
- `character_va` 的主键含版本标记：同一对角色与声优在不同版本下各自保留。

### 1.5 字段来源四象限

| 类别 | 字段 | 写权限 |
|---|---|---|
| 用户输入 | `name` · `status` · `user_rating` · `notes` · `image_path` | 表单自由编辑（封面经文件对话框选择，路径也可手工输入） |
| 系统派生 | `created_at` · `play_count` · `last_played_at` · `installation_count` · `can_launch` | 由动作产生 |
| 外部元数据 | 别名与本地化标题 · 发行日期 · 评分与人数 · 简介 · 标签 · 开发商 | VNDB 同步填入，用户可覆盖 |
| 本地事实 | `dir_path` · `entry_path` · `size_bytes` | 通过目录选择器替换 |

角色字段的来源另算：立绘 · 名字 · 原名 · 性别 · 年龄 · 身高 · 体重 · 出场定位 · 声优 · 简介由用户在表单填写；`traits` 与三围、生日、血型只有 VNDB 同步才有来源，表单不暴露——本地编辑只覆盖露出的字段，未露出的保持原值。

## 3. 功能需求详述

### 活动集一 · 管理一部作品

#### 手动新增一部作品
- **描述**：用户填写作品名（必填）与可选字段，创建一条独立作品记录。无需任何 VNDB 信息即可创建。
- **前置**：用户在库内（空列表时提供"手动添加"入口）。
- **后置**：生成带 `id` 与 `created_at` 的作品；可选写入 `vndb_id`、用户状态与元数据。
- **涉及字段与来源**：`name`（用户输入，必填）；`vndb_id`（外部，可空）；`status` / `user_rating` / `notes`（用户输入）；元数据组（外部，可空）。
- **备注**：表单为纯受控组件，新增与编辑同源，按 mode 区分提交目标。

#### 编辑一部作品的字段
- **描述**：修改已有作品的任意可写字段并保存。
- **前置**：存在目标作品，且处于编辑态（表单以聚合当前值初始化）。
- **后置**：仅提交的字段被更新；未给的字段保持原值（PATCH 双层 `Option` 区分"没给"与"显式置空"）。
- **涉及字段与来源**：身份、用户状态、元数据三组的可写字段。
- **备注**：`status` 为 `NOT NULL`，无清空语义，用单层 `Option`。字段级校验的报错渲染在对应字段旁；操作失败（拉取、存盘）才走全局 toast——那时用户可能停在角色 tab 或搜索侧栏，字段旁那条不在他视野里。

#### 删除一部作品（保留磁盘文件）
- **描述**：删除作品记录，但不删除磁盘上的任何文件。
- **前置**：存在目标作品。
- **后置**：作品记录消失；其本地安装记录的 `game_id` 置 `NULL` 成为未认领目录，磁盘内容原样保留。
- **备注**：界面需说明"删除作品记录不会删除磁盘上的文件"，未认领目录要有独立入口或徽标。

#### 设置一部作品的状态
- **描述**：在四个状态（游玩中 / 想玩 / 已通 / 弃）之间任意切换。
- **前置**：存在目标作品。
- **后置**：`user_game_state.status` 更新为所选值。
- **备注**：四选项全开，用户可能改错状态，必须能改回。

#### 记录一部作品的个人评分
- **描述**：用户给作品打个人评分（0–100 百分制，详情页展示时除以 10）。
- **前置**：存在目标作品。
- **后置**：`user_game_state.user_rating` 更新。
- **备注**：与 VNDB 的 `rating`（外部元数据）是不同字段，互不覆盖。

#### 为一部作品添加个人笔记
- **描述**：用户记录自由文本笔记。
- **前置**：存在目标作品。
- **后置**：`user_game_state.notes` 更新。
- **备注**：笔记随详情返回，不进摘要投影，避免列表载荷膨胀。

#### 为一部作品选择本地封面
- **描述**：用户通过原生文件对话框为作品挑选本地图片作为封面，也可直接手工输入图片路径。
- **前置**：存在目标作品，且处于表单编辑态。
- **后置**：`game_metadata.image_path` 为所选图片的绝对路径；表单预览与详情页渲染该封面，无本地封面或加载失败时显示占位。
- **涉及字段与来源**：`image_path`（用户输入，绝对路径）。
- **备注**：VNDB 同步填入的封面与本功能选的是同一个字段 `image_path`，两者在冲突面板里逐个取舍。

### 活动集二 · 关联 VNDB 数据

#### 按标题搜索 VNDB 作品
- **描述**：在表单内并排打开搜索面板，按标题（含别名、关联 release 标题）检索 VNDB，结果按相关度排序。
- **前置**：用户已输入作品名或主动触发搜索。
- **后置**：返回命中列表（标题、罗马字、年代、原作语言、缩略图），供用户选择。
- **备注**：搜索结果有进程内缓存（TTL 10 分钟，LRU 32）；`search` 只接受字符串值，传数组会静默失效。

#### 将一部作品绑定到 VNDB 条目
- **描述**：用户从搜索结果选中一条，将 `vndb_id` 写入作品身份。
- **前置**：搜索已返回结果，用户选中某条目。
- **后置**：作品的 `vndb_id` 设为所选值；重复占用已绑定 `vndb_id` 时报冲突。
- **备注**：选中搜索结果即写入 `vndb_id`，随即拉取该条目的元数据并打开取舍面板。

#### 解除一部作品与 VNDB 的绑定
- **描述**：清除作品的 `vndb_id`，断开与 VNDB 条目的关联，但保留已填入的元数据。
- **前置**：作品当前已绑定。
- **后置**：`vndb_id` 显式置 `NULL`；已同步的元数据字段不受影响。
- **备注（部分实现）**：后端 `update_game` 已支持 `vndb_id` 显式 `null` 解绑，前端目前无独立"解绑"入口，需补。

#### 从 VNDB 同步元数据（逐字段可选覆盖）
- **描述**：基于已绑定的 `vndb_id` 拉取 VNDB 元数据，逐字段比对库里现值与新值；对存在差异的字段，在冲突面板中由用户逐字段选择「覆盖」（采用 VNDB 值）或「跳过」（保留现值）。JSON 列（`tags` / `developers` / `titles`）以整列替换粒度决策。VNDB 提供建议值，用户保留逐字段否决权。
- **前置**：作品已绑定 `vndb_id`。
- **后置**：取舍面板只改表单状态，点保存才落库；用户「跳过」的字段保持原值。名称与元数据在同一决策集内，选中官方标题时一并更新 `games.name`。表单这边为空的字段不进面板，直接填入。
- **备注**：标签与开发商按名字集合比对，顺序不同不算冲突；简介读入时剥掉 BBCode，`[spoiler]` 与 `[raw]` 整块丢弃（前端本来就不渲染 BBCode，剥掉不等于丢数据）。封面按本地 `image_path` 是否为空决定进不进面板：为空则直接采用 VNDB 下载的图，非空则与文本字段一样由用户逐个取舍。
- 元数据与角色集由同一次同步取回，任一失败整体报错：只填上一半会让用户以为同步已经完成，看到的却是空角色列表。封面与立绘的下载相反——单张失败只记日志，不让整次同步失败。
- 标题列表可能一条中文都没有，按 `lang` 挑不出想要的那条，只能看 `official` / `main`。
- 标签列里混着两种来源：VNDB 的标签带 rating 与剧透等级，用户手打的没有。

### 活动集三 · 管理本地安装

#### 扫描库根发现新目录
- **描述**：遍历已登记的库根目录，发现尚未认领的磁盘目录。
- **前置**：存在至少一个已登记库根（首次使用的关键路径之一）。
- **后置**：产出未认领目录清单，与作品列表并列呈现。
- **备注（待实现）**：库根尚无落点——`library_roots` 表、`scan` 命令与前端扫描流程都未实现。

#### 将未认领目录认领为某作品的安装
- **描述**：把一条待认领目录关联到某作品，成为其一个安装项。
- **前置**：存在未认领目录与目标作品。
- **后置**：`installations` 记录 `game_id` 由 `NULL` 设为目标作品。
- **备注（待实现）**：API 层 `create_installation` / `update_installation` 已支持，缺扫描与认领 UI。

#### 设置某安装项的启动入口
- **描述**：为安装项指定入口 exe 与候选入口列表。
- **前置**：存在目标安装项。
- **后置**：`entry_path` 与 `exes` 更新。
- **备注（待实现）**：后端 `update_installation` 已支持，缺 UI。

#### 移除某安装项（保留磁盘文件）
- **描述**：解除作品与某目录的关联，不删除磁盘文件。
- **前置**：存在目标安装项。
- **后置**：安装项记录删除；磁盘内容原样保留。
- **备注（待实现）**：后端 `delete_installation` 已支持，缺 UI。

### 活动集四 · 浏览与筛选

#### 列出全部作品摘要
- **描述**：进入列表时一次取全量摘要投影并常驻内存。
- **前置**：库存在。
- **后置**：渲染封面墙，按状态分区。
- **备注**：摘要投影为 selector 从聚合中选出的子集；个人库规模几千条内不构成压力。分区与筛选栏的展示顺序固定，游玩中的排在最前。

#### 打开一部作品的详情
- **描述**：整页切换到详情，按需取单条聚合（含重字段如简介、安装列表）。
- **前置**：用户从列表选择某作品。
- **后置**：展示身份、用户状态、元数据与安装列表；关闭即释放聚合。
- **备注**：重字段按需再取，与"属不属于这部作品"无关。
- 元数据行可能不存在（作品没绑过 VNDB），这不是失败，页面按空值渲染。
- 评分一律按十分制展示：VNDB 的 `rating` 与个人评分在库里都是百分制，91 显示 9.1，不补成 9.10。
- 标签展示：剧透等级 ≥ 1 的不展示；VNDB 标签按 `rating` 排、同值再按 `vn_count`，用户手打的标签没有这两项，当 0 排在 VNDB 标签之后。
- 启动按钮目前是占位，对应「设置启动入口」尚未接通（见活动集三）。
- 动作条与封面同宽（同一列）：开始游戏 / 游戏时长占位 / ⋯ 菜单。后端还没有时长字段，占位先标明位置。删除不进动作条，收进 ⋯ 菜单 —— 它不高频。

#### 按状态筛选作品
- **描述**：在"全部 / 游玩中 / 想玩 / 已通 / 弃"之间切换，列表按所选状态过滤。
- **前置**：存在作品。
- **后置**：列表仅显示匹配状态的作品，各状态带计数。
- **备注**：筛选属于列表视图状态。

#### 返回时还原列表的筛选与滚动位置
- **描述**：从详情返回列表时，恢复离开前的筛选状态与滚动位置。
- **前置**：曾进入详情。
- **后置**：列表还原到离开时的筛选与滚动偏移。
- **备注（部分实现）**：滚动位置还原已实现；筛选状态当前重置为"全部"，未还原，需补。

### 活动集五 · 管理一部作品的角色

#### 为一部作品新增一个角色
- **描述**：在作品表单「角色」页追加一个空白角色，随即填写其档案字段。
- **前置**：作品处于表单编辑态。
- **后置**：角色集合末尾多出一条；保存时随作品一并提交。
- **涉及字段与来源**：`id`（本地生成，与 VNDB 的 c 编号同列混排）；其余为用户输入。
- **备注**：角色不单独落库，随作品保存时整包提交。

#### 编辑一个角色的档案
- **描述**：修改角色的名字、原名、性别、年龄、身高、体重、出场定位与简介。
- **前置**：该作品已有至少一个角色，且当前选中了其中一个。
- **后置**：草稿更新；保存时整包写回。
- **涉及字段与来源**：上述字段为用户输入；`traits`、三围、生日、血型等未暴露的字段保持原值。
- **备注**：出场定位取 VNDB 的四档（主角 / 主要角色 / 配角 / 登场）。

#### 为一个角色指定本地立绘
- **描述**：通过原生文件对话框为角色挑选本地图片作为立绘，也可手工输入图片路径。
- **前置**：选中了某角色。
- **后置**：`image_path` 为所选图片的绝对路径；卡片渲染该立绘，无立绘时以角色名占位。
- **备注**：立绘走与封面同一条派生图管线（缩图与访问授权）。

#### 增删一个角色的声优
- **描述**：为角色添加或移除配音声优，可带版本标记（如作品的重制版）。
- **前置**：选中了某角色。
- **后置**：配音关系增删对应行；声优按编号复用全局表，已存在的声优行不被本地手填的名字覆盖。
- **备注**：同一对角色与声优在不同版本标记下各自保留。

#### 调整一部作品里角色的顺序
- **描述**：用左移 / 右移按钮改变角色在作品中的先后次序。
- **前置**：该作品有至少两个角色。
- **后置**：保存时按数组下标重写顺序，读取按该顺序返回。
- **备注**：卡条是吸边滚动，不做拖拽重排——会与吸边打架。

#### 删除一个角色
- **描述**：从作品中移除一个角色。
- **前置**：选中了某角色。
- **后置**：该角色与其配音关系一并移除；保存时随整包替换落库。
- **备注**：配音关系随角色删除；声优作为全局表保留，失去最后一个配音关系的行随即回收。

#### 查看一部作品的角色
- **描述**：在详情页浏览该作品的角色列表，展开查看单项详情。
- **前置**：已打开某作品的详情。
- **后置**：展示角色立绘、原名与首位声优；展开后显示性别、尺寸、年龄、声优与按分组归类的 traits。
- **备注**：traits 的分组在 VNDB 侧没有序号字段，前端固定一张展示顺序表，不在这张表里的新分组排到末尾；剧透等级 ≥ 1 的 trait 不展示，成人向分组不进正文。

#### 从 VNDB 同步一部作品的角色
- **描述**：随「同步元数据」一并拉取该作品的角色与配音关系，按角色名比对后逐条取舍。
- **前置**：作品已绑定 `vndb_id`。
- **后置**：角色的档案、立绘与 traits 落库；配音关系按角色、声优与版本标记去重。
- **备注**：源为 `/character`（角色档）与 `/vn` 的 `va`（声优，带版本标记），接口坑与数据模型见 `docs/dev/vndb-api.md`。只取主角与主要角色两档：`side` / `appears` 里混着无立绘的配角，收进来只是让卡条多一排占位块，还要为它们多下一批图。
- 与本地角色按名字配对，配对键优先取原名——罗马字名重名会把两个不同角色判成同一个。与作品级同口径：本地优先，冲突项逐个取舍后随保存落库；一个冲突项都没有就不开面板，直接填入。

## 4. 后续迭代落点

FDD 后三步（按功能计划 / 设计 / 构建）对每个功能集迭代推进：

- **活动集三「本地安装」** 是当前主要待建区：安装项的增删改查后端已就绪且有测试，扫描整条链路（库根登记 → 遍历 → 未认领清单）未实现，前端流程也整体缺失。
- **网络调用的等待上限** 尚缺：拉取元数据与角色时已有提示条，但 `fetch_vn_metadata` 与 `search_vndb` 被限流排队时只显示加载中，没有等待上限与超时提示。
- **派生图缓存无清理机制**：`covers/` 按内容寻址累积（作品封面与角色立绘同目录），换过的封面旧文件会留下。缺清理策略。
- **活动集四的筛选还原缺口** 与 **活动集二的解绑入口** 为小粒度的功能补充，可并入相应活动集的下一轮。
- **活动集一** 已基本建成，迭代以缺陷修复与微调为主。

每个功能进入构建前，仍按项目工作流先出方案、过目确认后再实现。
