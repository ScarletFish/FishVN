## 文档说明

- **范围**：作品库（Galgame 本地管理）领域的全部功能需求，按八个活动集组织。
- **排版原则**：活动集内的小节尽量按生命周期排列（建立 → 成形 → 使用 → 退场），纯设置项按设置页的区块顺序排列；新增功能按所处阶段插入，不追加到末尾。
- **状态标注**：每个功能标注当前落地情况，基于编写当日（2026-11-05）对代码与命令层的核对（2026-11-07 修订：添加入口与表单单例、组内排序、减少动画），不代表最终设计变更：
  - `已实现` —— 后端命令与前端流程均已接通。
  - `部分实现` —— 核心已通，存在明确缺口（在备注中说明）。
  - `待实现` —— 后端或前端尚未接通，或仅 API 层就绪、缺用户流程。
- **核心思路**：作品条目独立，可进行四个维度（身份、用户状态、本地安装、元数据）数据的编写，并管理其下属的角色（见活动集五）。特此说明一点：VNDB同步产生的字段值为建议值，用户可选是否采纳。`vndb_id` 可空且 `UNIQUE`（NULL 之间不冲突），后续功能描述不再逐条重复此原则。

## 1. 整体模型（领域模型）

### 1.1 关键抽象

| 概念 | 说明 |
|---|---|
| 作品（Entry） | 库中的一条游戏记录，是聚合根。用户收藏与管理的基本单位。界面文案中称「游戏」。 |
| 作品身份 | 作品的标识与展示名，不依赖任何外部源。 |
| 用户状态 | 用户对作品的主观标记：状态、个人评分、笔记。 |
| 本地安装（Installation） | 作品在磁盘上的一条启动路径：目录与入口 exe，一部作品可有多条。每条自带启动方式：是否转区（Locale Emulator）、Magpie 缩放方式（关 / 全屏 / 窗口）、附加启动参数。 |
| 游玩记录（Play Session） | 一次启动留下的一行：起点、结束与两个时长。一部作品同时只有一条进行中的记录。 |
| 总时长 | 作品累计的游玩时长。用户可随时改写；软件在结算时按时间口径加在它上面。 |
| 前景时间 / 存活时间 | 软件记录的两个时间口径：前景时间是游戏窗口处于前台的时间，存活时间是进程从起点到结束的存在时长。取哪一个累加进总时长由设置页选择，配置持久化在数据目录的 config.json。 |
| 元数据（Metadata） | 别名、本地化标题、封面、发行日期、评分与人数、简介、标签、开发商、制作人员。 |
| VNDB 绑定 | 作品与 VNDB 条目之间可选的关联关系，由 `vndb_id` 表达。 |
| 角色（Character） | 一部作品下的出场人物，是作品的子实体：立绘、名字、原名、性别、年龄、尺寸、出场定位、简介。VNDB 上同一角色在不同作品里是不同条目（详略与立绘各不相同），故按作品各存一行，不建共享本体。 |
| 声优（Staff） | 为角色配音的人，全局实体：编号是身份（本地铸造 `local-` 前缀，VNDB 同步附带 `s` 编号，同列混排），主名与原文用户可编辑，是查询与列表显示的权威。与角色的配音关系带版本标记，同一对角色与声优可有多条；关系上的署名（该作封面署的名）是只读证据，不随主名改写。 |

### 1.2 聚合边界

一部作品是一个聚合，由四组相互独立的字段描述：

| 组 | 字段 | 能否脱离 VNDB 成立 |
|---|---|---|
| 身份 | `name` · `vndb_id` | 能。`vndb_id` 为空时作品照样存在。 |
| 用户状态 | `status` · `user_rating` · `notes` · `default_installation_id` · `play_seconds` | 能。纯用户数据。 |
| 本地安装 | `dir_path` · `entry_path` · `exes` · `size_bytes` · `le_launch` · `magpie` · `launch_args`（可多条） | 能。来自磁盘与用户勾选，与 VNDB 无关；后三项决定启动链路，工具本体路径在设置页登记。 |
| 元数据 | 别名与本地化标题 · 封面 · 发行日期 · 评分与人数 · 平均通关时长 · 简介 · 标签 · 开发商 · 制作人员 | 能。全部字段表单可编辑，VNDB 同步仅填入建议值、可逐字段覆盖；即使全空，作品与元数据行仍存在。 |

聚合是逻辑边界，定义"什么属于同一部作品"；加载单位由消费方各自决定。

### 1.3 关系

```
作品 1 ──0..1── VNDB 绑定（vndb_id）
作品 1 ──0..*── 本地安装（installations.game_id）
作品 1 ──0..*── 游玩记录（play_sessions.game_id，安装项可空）
作品 1 ──1───── 元数据行（game_metadata，每列可空）
作品 1 ──0..*── 角色（characters.game_id，按作品整包替换）
角色 1 ──0..*── 配音关系（character_va，带版本标记）
声优 1 ──0..*── 配音关系（staffs 为全局表，不随作品删除）
```

读法：箭头两端是「一个 X 对应几份 Y」。`1` = 恰好一份，`0..1` = 零或一份（可选），
`0..*` = 零到任意多份（`*` 就是「多」，不限上界）。

### 1.4 字段来源四象限

| 类别 | 字段 |
|---|---|
| 用户输入 | `name` · `status` · `user_rating` · `notes` · `image_path` · `cover_focal_x` · `cover_focal_y` · `ambience_path` · `ambience_mode` · `ambience_plate` · `ambience_focal_x` · `ambience_focal_y` · `default_installation_id` · `play_seconds` |
| 系统派生 | `created_at` · `play_count` · `last_played_at` · `foreground_seconds` · `alive_seconds` · `installation_count` · `can_launch` |
| 元数据 | 别名与本地化标题 · 发行日期 · 评分与人数 · 平均通关时长 · 简介 · 标签 · 开发商 · 制作人员 |
| 本地事实 | `dir_path` · `entry_path` · `size_bytes` |

### 1.5 标签与特征

标签分两个承载实体，各自带两种来源：

| 实体 | 承载字段 | 来源 |
|---|---|---|
| 游戏标签 | 作品的 `tags` | 词典项（VNDB 标签，带 id）＋ 用户自定义项（手输，id 为空） |
| 角色特征（traits） | 角色的 `traits` | 词典项（VNDB traits，带 id）＋ 用户自定义项（手输，id 为空） |

用户自定义不是独立存储，而是上面两类的来源标志：手输或词典未收录的条目 `id` 为空。​**两类对自定义项的归组不同——游戏标签的自定义项进「自定义」组（置顶），角色特征的自定义项无 VNDB 分组、进「其他」组**​；词典更新收录后，原自定义项若有 id 则归入对应类。游戏标签与角色特征共用同一套中文名（见「标签与特征显示中文名」）。

标签按用途分三类，由自带的标签词典决定，各类出现在不同的界面：

| 类别 | 举例 | 出现的界面 |
|---|---|---|
| 题材与角色 | 纯爱 · 学生 · 赛博朋克 | 详情页标签区 · 词云 · 排除池候选 |
| 舞台、情节、风格 | 校园 · 轮回 · 赛璐璐画风 | 详情页标签区 · 排除池候选 |
| 界面功能类 | ADV · 跳过已读 · 立绘查看器 | （默认全隐藏，不在任何界面出现） |

- 题材与角色既描述作品也描述角色，详情页与词云共用这一类；词云另要求两部以上作品共有，只在一部作品出现的标签不足以说明库的情况。
- 舞台指故事发生在哪儿，情节指怎么讲故事，风格指画面什么样子；三者是单部作品自己的补充说明，只进详情页。
- 界面功能类（技术向）是 VNDB 给数据本身打的标记，默认全隐藏，不在任何界面出现；文档他处沿用「技术向」这个称呼。
- 手输与词典未收录的标签按题材与角色处理。

标签的去留由三层独立的筛选各自决定，任一层的输入变化只重算该层：

- 显示范围：技术向标签在任何界面都不出现，这一层不随设置变化（见上文分类表）。
- 内容状态：成人向与剧透，随同步数据更新，并随设置里「隐藏成人向标签」「剧透标签」两项变化。
- 个别偏好：是否进入标签设置的排除池（见「管理标签排除池」）。

已选标签的分组与编辑交互由对应活动承载：游戏标签见「编辑一部作品的标签」，角色特征见「编辑一个角色的档案」，成人向与剧透的默认级别见对应设置项。

## 3. 功能需求详述

### 活动集一 · 管理一部作品

<a id="as1"></a>

#### 手动新增一部作品

- **描述**：用户填写作品名（必填）与可选字段，创建一条独立作品记录。无需任何 VNDB 信息即可创建。
- **前置**：无（添加入口常驻标题栏品牌菜单，含手动添加、挑文件、扫描目录三项；空库时首页与「我的列表」的空态各有一个「添加游戏」按钮，点击唤起该菜单——空态引导只负责把人带到菜单，动作仍由菜单统一出口）。
- **后置**：生成带 `id` 与 `created_at` 的作品；可选写入 `vndb_id`、用户状态与元数据。
- **涉及字段与来源**：`name`（用户输入，必填）；`vndb_id`（外部，可空）；`status` / `user_rating` / `notes`（用户输入）；元数据组（外部，可空）。
- **备注**：添加/编辑表单是全局单例（App 挂一份），由 `openForm` / `openPrefilled` / `addFromFile` / `addFromScan` 四个驱动入口统一开关，各视图不持有自己的表单实例。表单为纯受控组件，新增与编辑同源，按 mode 区分提交目标。外键列（`game_id` / `default_installation_id`）写入前判空串，空串按非法输入拒掉。

#### 从本地安装快速添加作品

- **描述**：在标题栏品牌菜单里挑一个可执行文件，识别出作品名（文件名去扩展名）与启动入口（父目录 + 所选文件）后，以预填内容打开新建表单；保存走「手动新增」与「手动指定本地启动路径」的既有链路。
- **前置**：无。
- **后置**：新建的作品带一条安装记录（目录 + 默认启动入口），目录占用按既有冲突口径报错。
- **涉及字段与来源**：`name`（文件名去扩展名，用户可改）；`dir_path`（所选文件的父目录）；`entry_path`（所选文件相对 `dir_path` 的路径）。
- **备注**：识别在挑选后异步完成（`inspect_path` 命令，避免扫盘阻塞界面），exe 候选与安装行共用同一套磁盘扫描（递归 3 层、30 个封顶、按层数排序，攒够候选即停止下钻）；卸载器与运行库安装器类文件名（`unins` / `setup` / `update` / `redist` / `vcredist` / `dxsetup` / `dotnetfx` / `crashreport` / `langsetup` 前缀）不进候选，`redist` / `_redist` / `uninstall` 目录不深入收集，目录大小仍累加全部内容。挑目录的入口走「扫描目录发现未登记的作品」（活动集三）。预填表单停在「基本」页，名称与安装行都已就位。

#### 编辑一部作品的字段

- **描述**：在编辑表单里修改作品的可写字段并保存。表单是多 tab 容器：基本信息、扩展信息、图片与标签、安装、角色；标签、安装、角色各自有独立活动，本活动覆盖基本信息 / 扩展信息两栏与表单整体的保存协议。
- **前置**：存在目标作品，且处于编辑态（表单以聚合当前值初始化，各 tab 绑定草稿的对应切片）。
- **后置**：仅提交的字段被更新，未给的字段保持原值（PATCH 双层 `Option`：区分"没给"与"显式置空"）；保存是整表单一次提交，tags / installations / characters 三个切片随各自活动描述的整包规则一并写回。
- **涉及字段与来源**：身份（`name` · `vndb_id`）、用户状态（`status` · `user_rating` · `notes` · `default_installation_id` · `play_seconds`）、元数据（别名与本地化标题 · 发行日期 · 评分与人数 · 平均通关时长 · 简介 · 开发商）、制作人员；VNDB 同步可带入元数据与制作人员的建议值，用户逐字段覆盖。
- **备注**：
  - 入口在卡片 ⋯ 菜单（首页与「我的列表」）与详情页 ⋯ 菜单。
  - 编辑打开时落在上次停留的 tab（全部作品共享一份记忆，由 App 统一持久化到重启）；新建（显式添加行为）固定从「基本」页开始并覆写记忆，编辑未指定 tab 沿用记忆页。详情页跳指定页的入口（安装路径条跳安装页、横幅右键「调整取景位置」跳图片页）走 tab 参数覆盖记忆。
  - 保存协议：`status` 为 `NOT NULL`、无清空语义，用单层 `Option`；其余可空字段用双层 `Option` 区分"没给"与"显式置空"。外键列（`vndb_id` / `default_installation_id`）写入前判空串，空串按非法输入拒掉。
  - 校验分两层：字段级校验（名字必填、评分 0–100、评分人数与时长非负、安装路径可解析）持续在算，但只在**字段离开过或点过保存**之后才显示——聚焦即报错、边敲边报错都属于提前指责；显示后随输入实时消退。提交时一次报全，跳到最靠前的出错页并聚焦该字段。拉取与存盘等跨字段操作失败才走全局 toast——那时用户可能停在角色 tab 或搜索侧栏，字段旁那条不在他视野里。
  - 输入层先拦一道：评分 / 评分人数 / 时长三个框在键入时就只收数字（评分的整数位最多三位，一位小数），离焦时再规整到合法范围（评分 0–100，人数与时长非负并限位数）——越界值通常到不了提交那一刻。渲染层校验保留作兜底，管的是粘贴、程序化赋值这类绕过键入的路径。
  - 发行日期是日期字段：分段显示（年 / 月 / 日各段独立编辑）＋日历弹层（头部年份 / 月份下拉圈定 1980–2030，两侧翻月）；存量自由文本解析失败（`TBA`、乱格式）时显示为空、不覆写原值，用户主动修改才写回。
  - 表单有未保存改动时关闭先弹确认「有修改尚未保存，确定要放弃吗？」。
  - VNDB 同步与本地编辑共用一份草稿：同步填入的建议值进草稿后用户可改，保存时与手动改动同等对待。

#### 编辑一部作品的制作人员

- **描述**：在表单「扩展信息」页里按行维护人员条目，每行选职能、填姓名与别名（可选）。
- **前置**：存在目标作品，且处于表单编辑态。
- **后置**：`game_metadata.staff` 整列替换为表单当前列表；两边都没填名字的行在提交时丢弃。
- **涉及字段与来源**：`staff`（用户输入 + VNDB 同步，条目为职能 · 姓名 · 别名 · 备注）。
- **备注**：职能为固定十项（剧本 / 导演 / 人物设计 / 原画 / 音乐 / 歌手 / 翻译 / 编辑 / 测试 / 制作），与 VNDB 的 `staff_role` 枚举一一对应；备注列由 VNDB 同步带入，表单里就地保留原值；同步来源的条目与手输条目在同一列表里混排，冲突按整列取舍；页内常驻提示「详情页将按职能分组展示」。

#### 编辑一部作品的标签

- **描述**：在表单「图片与标签」页维护标签列表，两条入口。标签框下方常驻输入行：写名字后回车或点「添加」提交，名字与库内标签相同时直接关联该标签，否则记为自定义标签；空输入时退格删除末尾一条。已选标签按分类分组展示——自定义、题材、角色、舞台、情节、风格、其他，自定义置顶，空组不渲染；技术向默认隐藏，不进该列表。「从库内标签挑选」在右侧并排打开选择器，分组与顺序同上，组内按库内出现次数降序并标 `×N`，可搜中文名与 VNDB 原名，点选加入、再点移除，已选的以强调色标出，搜不到时提供「添加「xxx」」。
- **前置**：作品处于表单编辑态。
- **后置**：标签随保存写入 `tags` 列；手输标签与 VNDB 标签混列，两种来源以有无 `rating` 与 `spoiler` 区分。
- **涉及字段与来源**：`tags`（外部元数据 + 用户输入）。VNDB 同步与冲突面板按名字集合比对，顺序不同不算冲突。
- **备注**：两条入口分工——输入行用于知道要写什么，选择器用于看库里已用过什么，省去回忆准确写法。输入行常驻，写标签不必先点开一个按钮；名字命中库内标签时沿用其 id，结果与在选择器里点选一致。标签以显示名为身份：输入行写下的名字与已选标签显示名重名时拒加，行内提示「库内已有重名标签」，回车改为让已有药丸脉冲定位，不产生重复条目；选择器里手输标签与字典同名的候选只出现一条，点选按显示名增删。手输标签保持输入顺序，不参与详情页的排序。库内标签候选随同步、编辑、删除作品实时刷新；同名的手输标签与字典标签在候选里只出现一条。技术向标签与详情页一致地默认隐藏：表单展示与「从库内标签挑选」选择器都不渲染技术向组，不在编辑器里出现，仅在设置页排除池维护区的说明行里被提及。

#### 为一部作品选择本地封面

- **描述**：用户通过原生文件对话框为作品挑选本地图片作为封面。封面字段是预览图加「更换 / 移除」两个按钮：点预览图进取景框编辑器，点「更换」重选图片，点「移除」回到无封面。
- **前置**：存在目标作品，且处于表单编辑态。
- **后置**：`game_metadata.image_path` 为所选图片的绝对路径；表单预览与详情页渲染该封面，无本地封面或加载失败时显示占位。
- **涉及字段与来源**：`image_path`（用户输入，绝对路径）。
- **备注**：VNDB 同步填入的封面与本功能选的是同一个字段 `image_path`，两者在冲突面板里逐个取舍。封面字段不展示图片路径——路径本身没有可读性，选中与更换都经文件对话框。换图时焦点重置 50/50（见下一条）。

#### 调整一部作品的封面展示位置

- **描述**：用户为封面选择在 3:4 展示容器里的构图位置（焦点）。表单封面字段点击预览图打开取景框编辑器：图片查看器式画布（滚轮以指针为中心缩放、拖动平移看局部、双击适应窗口/100%、方向键微调、Shift 加速），3:4 取景框浮在图上，拖框或单击图面设焦点，快捷位置位；确定后写库，取消则丢弃草稿。
- **前置**：作品有封面且可加载（`image_path` 非空、图未裂）；无封面时预览区不可点、不露入口——没有封面就没有焦点可调。
- **后置**：`game_metadata.cover_focal_x` / `cover_focal_y`（0–100，默认 50）随保存写入；卡片墙、详情页主封面、表单预览、合并面板本地侧、首页继续游玩背景、详情页 FLIP 过渡动画按焦点渲染 `object-position`。换封面（手动选图、同步填入、合并接受、批量补全首次填）时焦点强制重置 50/50——旧焦点对新图无意义，该重置在后端 `upsert` 一处收口。
- **涉及字段与来源**：`cover_focal_x` / `cover_focal_y`（用户输入，0–100 整数）。
- **备注**：焦点是 `object-fit: cover` 语义下的位置：容器 3:4，横图只剩左右可移、竖图只剩上下可移，无效轴自动锁死、快捷位置灰。氛围背景层不跟这个焦点——它有自己的画幅与焦点（见「调整一部作品的横幅展示位置」）；角色立绘没有该字段。焦点不进合并面板——VNDB 没有这个概念，同步不产生该字段的冲突。

#### 自定义一部作品的横幅

- **描述**：详情页顶部的氛围横幅默认跟随封面（模糊放大的一档）。用户可在「图片与标签」页为单个作品另选一张图，并分别设定观感（柔和 / 清晰）与文字衬底。柔和档沿用跟随封面时的模糊放大与五段遮罩；清晰档原图直出、不模糊不放大，遮罩在 70% 处开始淡出。预览按详情页的真实画幅与真实文字渲染，点预览图进取景框编辑器。
- **前置**：存在目标作品，且处于表单编辑态。
- **后置**：`game_metadata.ambience_path` 为空表示跟随封面（`image_path`），非空为该图的绝对路径；`ambience_mode`（`soft` / `clear`，默认 `soft`）与 `ambience_plate`（0/1，默认 0）随保存写入。文字衬底只在清晰档出现在表单里：开启后标题与副标题各垫一层 `--plate-on-image`，两片独立，板边贴列边、文字内缩 8px。
- **涉及字段与来源**：`ambience_path` · `ambience_mode` · `ambience_plate`（用户输入，VNDB 同步不触碰这三个字段）。
- **备注**：柔和档取 560px 缩图（反正要模糊），清晰档走原图直链——缩图上限会把高清横幅压糊，正是清晰档要避免的。清晰档有两条约束：不叠 scrim（把页面底色压到图上会立刻发灰，抵消清晰档的意义），遮罩从 70% 起淡出（让评分条那一行落在薄底纹上，而不是压在全亮的图上）。副标题压在亮图上仍可能发飘，这是用户可控项——开衬底即可，系统不兜底加阴影。缩图生成耗时以秒计，详情页与表单预览都保留旧图直到新图就绪，替换时淡入——切换观感不塌成空占位再整块闪现。

#### 调整一部作品的横幅展示位置

- **描述**：横幅容器比封面扁得多（约 3.58:1），同一张图只剩中间一段纵向可见，所以横幅单独有焦点。点横幅预览打开取景框编辑器，缩放、平移、拖框、快捷位置与封面焦点一致，取景框换成横幅画幅。
- **前置**：作品有横幅图（自定义图或封面）且可加载；无图时预览不可点。
- **后置**：`game_metadata.ambience_focal_x` / `ambience_focal_y`（0–100，默认 50 / 22）随保存写入，详情页与表单预览按焦点渲染 `object-position`。选新横幅图时前端把焦点重置为默认值——旧焦点对新图无意义。
- **涉及字段与来源**：`ambience_focal_x` / `ambience_focal_y`（用户输入，0–100 整数）。
- **备注**：默认纵向 22 是跟随封面时的历史取景位置，换成自定义图后通常要重调。取景框按 3.58:1 绘制，是 1200px 宽横幅的参考比例；窗口更宽时实际可见的纵向比取景框显示的更少，焦点百分比本身仍然成立。

#### 在横幅上右键调整

- **描述**：详情页横幅整块支持右键，菜单分三组：图片（跟随封面 / 自定义）、观感（柔和 / 清晰）、文字衬底（仅清晰档出现）。菜单是表单那套的快捷入口，改完即时落库，不等保存。
- **前置**：详情页已加载出作品。
- **后置**：与表单同一组字段——`ambience_path` · `ambience_mode` · `ambience_plate`，`update_game_metadata` 的局部 patch 直接写回，返回的元数据覆盖本地状态，横幅当场重绘。
- **涉及字段与来源**：同「自定义一部作品的横幅」三个字段（用户输入）。
- **备注**：菜单内容是表单控件，点选后不关，可以连着调观感与衬底、看着横幅变；选「自定义」会开文件对话框，取消选择则维持原状（单选钮视觉回弹）。选图后焦点重置为默认值，与表单一致。菜单底部有分隔线隔开的动作条目「调整取景位置」——打开编辑表单并落在图片与标签页，点预览即进取景框编辑器；没有横幅图（无封面也无自定义图）时条目禁用。列表卡片与详情页工具栏的 ⋮ 下拉仍是原来的 `Menu.svelte`，没有并进这一套。

#### 设置一部作品的状态

- **描述**：在五个状态（游玩中 / 计划中 / 已完成 / 已搁置 / 已弃坑）之间任意切换。
- **前置**：存在目标作品。
- **后置**：`user_game_state.status` 更新为所选值。
- **备注**：五选项全开，用户可能改错状态，必须能改回。已搁置与已弃坑一样不上首页，只在「我的列表」与统计里出现。状态自动迁移只有一条：越过静默窗后把「计划中」改成「游玩中」，其余三个状态不被改写。

#### 记录一部作品的个人评分

- **描述**：用户给作品打个人评分（0–100 百分制，详情页展示时除以 10）。
- **前置**：存在目标作品。
- **后置**：`user_game_state.user_rating` 更新。
- **备注**：与 VNDB 的 `rating`（外部元数据）是不同字段，互不覆盖。

#### 记录一部作品的个人感想

- **描述**：用户为作品写下自由文本感想。表单与详情页两处入口写同一个字段。
- **前置**：存在目标作品。
- **后置**：`user_game_state.notes` 更新，详情页感想区随即刷新。
- **备注**：详情页可就地编辑，失焦、Ctrl+Enter 或框下的保存按钮落库，Esc 或取消按钮放弃，清空保存即删除 —— 写作场景是刚关掉游戏想记两句，为两句话开整个编辑表单成本不成比例。保存是显式的一次动作，落库后在标题行给一次「已保存」回执。正文按纯文本渲染，不解析 BBCode：那是 VNDB 简介的协议，自己的感想不继承它的语法。感想随详情返回，不进摘要投影，避免列表载荷膨胀。

#### 删除一部作品（保留磁盘文件）

- **描述**：删除作品记录，但不删除磁盘上的任何文件。
- **前置**：存在目标作品。
- **后置**：作品记录与其安装记录一并消失，磁盘内容原样保留。
- **备注**：界面需说明"删除作品记录不会删除磁盘上的文件"。入口在卡片 ⋯ 菜单（首页与「我的列表」）与详情页 ⋯ 菜单，不占详情页动作条。删除走 `ON DELETE CASCADE`：安装记录、角色与配音关系一并移除，磁盘文件不动；声优作为全局表保留，失去最后一个配音关系的行随即回收。

### 活动集二 · 关联 VNDB 数据

<a id="as2"></a>

#### 按标题搜索 VNDB 作品

- **描述**：在表单内并排打开搜索面板，按标题（含别名、关联 release 标题）检索 VNDB，结果按相关度排序。
- **前置**：用户已输入作品名或主动触发搜索。
- **后置**：返回命中列表（标题、罗马字、年代、原作语言、缩略图），供用户选择。
- **备注**：搜索结果有进程内缓存（TTL 10 分钟，LRU 32）；`search` 只接受字符串值，传数组会静默失效。

#### 将一部作品绑定到 VNDB 条目

- **描述**：用户从搜索结果选中一条，将 `vndb_id` 写入作品身份。
- **前置**：搜索已返回结果，用户选中某条目。
- **后置**：作品的 `vndb_id` 设为所选值；重复占用已绑定 `vndb_id` 时报冲突。
- **备注**：选中搜索结果即写入 `vndb_id`，随即拉取该条目的元数据并打开取舍面板。`vndb_id` 可空且 `UNIQUE`：NULL 之间不判重，重复绑定已占用 `vndb_id` 的条目报冲突。

#### 从 VNDB 同步元数据（逐字段可选覆盖）

- **描述**：基于已绑定的 `vndb_id` 拉取 VNDB 元数据，逐字段比对库里现值与新值；对存在差异的字段，在冲突面板中由用户逐字段选择「覆盖」（采用 VNDB 值）或「跳过」（保留现值）。JSON 列（`tags` / `developers` / `titles`）以整列替换粒度决策。VNDB 提供建议值，用户保留逐字段否决权。
- **前置**：作品已绑定 `vndb_id`。
- **后置**：取舍面板只改表单状态，点保存才落库；用户「跳过」的字段保持原值。名称与元数据在同一决策集内，选中官方标题时一并更新 `games.name`。本地为空的字段同样进面板，默认勾选，当前侧显示「未填写」。
- **备注**：标签与开发商按名字集合比对，顺序不同不算冲突；简介（作品与角色）都以 VNDB 原文入库，`[url=…]` 在简介里渲染为可点击外链、点击经系统浏览器打开，非 `http(s)` 目标的 `[url]` 降级为纯文字，`[spoiler]` 与 `[raw]` 的块内容在前端剥除、不进正文。封面同样进面板：本地为空默认勾选采用 VNDB 下载的图，非空则与文本字段一样由用户逐个取舍。制作人员行按职能展示两侧姓名集合不一致的职能（缺失一侧显示占位符），并计数其余一致的职能；职能与姓名全同而仅备注不同时整列展示。
- 元数据与角色集由同一次同步取回，任一失败整体报错：只填上一半会让用户以为同步已经完成，看到的却是空角色列表。封面与立绘的下载相反——单张失败只记日志，不让整次同步失败。
- 封面下载失败按类别透出错误码（HTTP 状态码 / timeout / network / local）进同步回执与日志：下载失败不写文件，下次拉取元数据会重下该封面。图片客户端用读超时（每收到一块重置计时）而非总超时——封面体积无上限（实测单张 4.26MB），总超时预算内下不完慢速大图会被误杀，且 reqwest 会把 body 超时包成 decoding 错误误导排查。
- 标题列表可能一条中文都没有，按 `lang` 挑不出想要的那条，只能看 `official` / `main`。
  - 标签列里混着两种来源：VNDB 的标签带 rating 与剧透等级，用户手打的没有。

#### 批量下载 VNDB 数据（资料补全）

- **描述**：扫库内资料不全的游戏（没有资料行、简介为空、封面为空或没有角色），从 VNDB 批量拉取元数据填入空白列：已绑定的按 `vndb_id` 直拉；未绑定的按作品名搜索 VNDB，取第一条结果自动绑定后再拉。别名、发行日期、评分与人数、平均通关时长、简介、封面、标题列表、标签、开发商、制作人员与角色集都在补全范围内，补丁只填空白列，已有内容不动。扫描结果与执行过程都在补全页：左侧是**全量游戏列表**（默认筛到本次目标集，可切到库内全部），右栏任务在跑时是日志、跑完是选中条目的修正台。列表来自 `listGames()` 的按名称稳定排序，任务状态只作叠加徽章，不重建列表；任务执行顺序锚定同一条 SQL 规则，因此从列表第一条往下推进。
- **前置**：导航「补全」页点「开始补全」扫全库——没跑过也先给出计划清单，页面不留空；或同步账户数据应用成功后，在弹出的「下载资料」确认框里选「开始下载」，只对本次新建的条目补全。两处触发都即时反馈，不等首个进度事件——重操作的响应要先于结果出现。
- **后置**：空白列被 VNDB 值填入，未绑定游戏绑定搜索命中的第一条；搜索无结果的跳过并计数，单部失败只记数、不中断整批。资料按批取回、逐部落库，进度与徽章随批推进；资料落库即算该条成功，封面与角色立绘随后进图片池下载并回填，不计入条目状态。两段进度都显示在补全页与任务坞：资料段是「正在补全 {done}/{total}」，转图片段后变「正在下载图片 {done}/{total}」。进度、失败计数与完结汇总经任务事件播报，逐条过程进补全页右栏的运行日志，条目完成即按条回取该条状态。运行中可暂停、可停止，停止在批边界生效——当前批跑完并落库后不再开新批，期间按钮与进度行都显示「正在停止…」；图片阶段立即中断，已下载的照常回填。底部任务坞只作入口，点击跳到补全页；坞只在任务推进时出现，暂停与取消都不留痕，完结汇总留 6 秒。
- **备注**：
  - 与「从 VNDB 同步元数据」的分工：单部同步逐字段比对、差异交用户取舍，是编辑动作；批量补全只填空白、不弹面板——空列没有可丢失的本地值。
  - 未绑定游戏取搜索结果第一条自动绑定：库内条目来自手动添加、扫描添加、VNDB 同步三个用户主动途径，作品名即搜索词，多数情况下第一条就是它；取错时封面与资料摆在明处，可在同一页的修正台里手动指定正确条目（见「手动修正一条补全结果」）。
  - 「只填空白」的代价是固化错误匹配：错的作品把数据写进空列后，即使改绑正确作品，这些列也不会再被碰，只能手动修正。批量仍保持仅空白——无人值守时没有更好的策略。
  - 两条路径的可信度不同：本次任务**不对已绑定条目做匹配决策**（按 `vndb_id` 直拉）；只有无 id 的条目会按本地名搜索取第一条自动绑定，这是本次唯一可能配错的来源。已绑定 id 也可能来自表单手动选择或上一轮自动绑定，所以「已绑定」指的是本次未做匹配，不是断言 id 一定正确。后端以 `bind_source`（`existing` / `search`）标记，补全页据此提供「需复核」筛选（成功且为搜索绑定）与就地改绑：右栏直接复用本次 run 记下的前 3 个候选和本地名，选错可一键重绑。人工改绑后该条自动退出「需复核」，无需「标记已复核」这类写操作；直拉条目与库内普通条目右栏只给结果摘要，需要完整逐字段编辑时在编辑表单中打开。这是会话内回执，不持久化、不记字段来源。
  - 默认「本次」视图是**冻结的目标集**：成功、失败、未匹配的条目都留在列表里不移除，方便逐条复查错配；切「全部」可看库内所有条目，任意一条都能选中修正。列表成员只在 `LIBRARY_CHANGED`（新建/删除/改名/同步应用/还原/任务完成）时重取，任务推进只叠加状态。本地优先且全字段可改，因此**不用字段完整性判定成员资格**，也不记字段来源；`SCAN_SQL` 只在进入页面时查询一次生成计划清单。列表按名称排序，批量扫描与按 id 启动都锚定 `games.rs::GAME_ORDER_SQL` 这一条规则，所以任务从列表第一条自上而下推进，成功的条目自然出现在上方，不需要额外置顶或重排。
  - 「成功」指资料齐了，不含图片：封面与立绘在图片池里异步补齐，失败只记日志、不翻状态，下次补全会重试。图片是展示物，缺一张封面不该把资料齐全的记录重新拖回待办。
  - 触发 VNDB 限流（429）时冻结约 5 分钟等待恢复，期间不发请求，恢复后自动继续。
  - 账户同步后另弹一次确认再下载，而不是把勾选框放进计划弹窗：计划弹窗回答的是「写什么」，此时新建条数还没确定；下载是写完之后的第二步联网动作，条数已知时问才有意义，也让计划弹窗少一块。

#### 手动修正一条补全结果

- **描述**：在补全页选中一条，就地改写搜索词或从候选里点选正确的 VNDB 作品；拉取后逐项确认要覆盖的内容，确认即写入，该条就地变为成功。
- **前置**：在补全页列表中选中任意库内条目（默认「本次」或切到「全部」皆可），且没有补全任务在跑。
- **后置**：该条绑定到所选作品，确认的字段、封面与角色写入库内；该行状态随之更新，列表不重排、不重建。不在本次目标集里的条目，修正结果记在前端局部叠加层，不写回任务快照。
- **备注**：
  - 这里可以覆盖，与批量的「只填空白」正相反：批量一旦匹配错，错的数据留在空列里再也纠不掉；手动修正时作品是人选的，所以把差异摆出来由人挑。
  - 与「重试此条」的分工：重试用已绑定的作品再拉一次、仍只填空白，治的是网络与限流；它不重新搜索，解决不了匹配错。
  - 候选与过程分处两栏：候选落在详情面板，逐条过程进运行日志——编辑表单里这两件事原本挤在一个侧栏，到补全页各归其位。

#### 从 VNDB 同步账户数据（用户列表 ↔ 状态与评分）

- **描述**：拉取 VNDB 用户列表（ulist），与库内已绑定 `vndb_id` 的作品逐条比对 `status` 与 `user_rating`；先产出同步计划弹窗，用户确认后才落库或写回 VNDB。方向由设置页决定：仅下载（VNDB → 本地）、仅上传（本地 → VNDB）、双向（两个方向同时）。计划按动作分类：库里没有对应作品的新建建议（导入名单，逐条勾选）、本地未改而上游变了的对齐更新、本地改过待推送的条目、本地与上游都改过的冲突（逐字段取舍）、两侧一致的无需操作。
- **前置**：已连接 VNDB 账户（见「连接 VNDB 账户」）。上传与双向还要求 Token 带 `listwrite` 权限，同步开始前检查。
- **后置**：下载侧的改动点「应用」后单事务落库——勾选的新建条目写入作品与初始用户状态，对齐更新与冲突取舍结果写入 `user_game_state`，刷新同步基线快照。上传侧逐条 `PATCH /ulist`，每条成功后立即提交该条基线；中途失败已推送的不回滚，下次同步接着推。取消则什么都不写。本次有新建条目时再弹一次「下载资料」确认，确认后按这些 id 启动批量补全，选「稍后」则不联网。
- **涉及字段与来源**：`user_game_state.status` 与 `user_rating`（VNDB 的 `vote` 1:1 映射，不换算）；`synced_status` / `synced_rating` / `state_modified_at`（同步基线，系统写）。
- **备注**：
  - 三种力度均已实现。仅上传遇到两边都改过的条目时不进冲突区，直接按本地推送，列表里带「→ 目标状态」，看得出要写成什么；双向的冲突默认选较新的一侧（条目级时间，两侧时间都显示在冲突行），用户可逐字段改选。
  - 计划弹窗分步，一屏只问一件事：有冲突时第一屏只做裁决，第二屏是写入预览（将推送到 VNDB 的条目分新增 / 状态变更 / 评分变化三段：新增按目标状态分组、条目只放名字，状态变更按源状态分组、条目带「→ 目标」，评分变化显示「旧 → 新」；将导入本地的新建条目按状态分组，各自可取消勾选）；只有一类内容时不显示步骤。落库仍是一个事务，取消即全部不做。账户同步只碰 `status` 与 `user_rating` 两个字段，VNDB 值始终是建议值、本地是默认保留的一侧。
  - 本地优先：VNDB 值始终是建议值。本地改过的字段进冲突区，用户逐字段选「本地 / VNDB」，也可批量选择；库里没有的新建条目默认全选，再点一次转幽灵态表示不导入。
  - 推送分组常驻一句提示（写入 VNDB 账户，不支持删除条目），逐条列出会写什么，用户可取消勾选；不另设「首次确认」弹窗——计划本身就是预览。写入结果与在 VNDB 网页上手动修改等效，可再去改回，但没有批量撤销。
  - 标签 id 每次上传前从 `/ulist_labels` 取，不写死：`PATCH` 不校验 id 是否存在，写错会静默挂上不存在的标签。
  - 导入名单按 VNDB 状态分组（游玩中 / 已完成 / 已搁置 / 已弃坑 / 计划中），组头带整组全选与计数；组内每条是双选 chip，点一下在「导入 / 不导入」间切换。
  - 纯投票条目（VNDB 列表里没有状态标记的）恒跳过；未知状态标记跳过，并在弹窗警告区逐条列出。
  - 计划中（wishlist）的条目受设置页「同步计划中的游戏」开关控制（见活动集六），默认不同步——本地优先，只搬有用的数据；开关同时约束两个方向。
  - 设置页可关闭评分同步：关闭后 `user_rating` 不参与比对、不写本地、不推送、不动基线，状态照常。
  - 同步计划在进程内缓存 60 秒，防连点重复请求；应用计划、切换同步开关或更换 Token 即使缓存失效。
  - 同步过程不阻塞界面：点「立即同步」立即弹出加载态（阶段进度、已拉取条数、已用秒数、取消），计划生成后平滑切换到结果内容；应用阶段若涉及上传，弹窗留在原地显示写入进度。取消不写任何数据，后台拉取的结果被丢弃，但计划缓存会刷新，下次同步即时复用。
  - VNDB 的 `rating`（元数据贝叶斯评分）不映射 `user_rating`，与元数据同步同一原则。

#### 连接 VNDB 账户（API Token）

- **描述**：在设置页保存 VNDB 的 API Token，建立与账户数据的连接；保存即验证一次连通性，也可随时清除。
- **前置**：无。未保存 Token 时同步入口不可用。
- **后置**：Token 只存本机 config.json，界面不明文回显；保存触发的验证通过即确认可用。
- **备注**：Token 在 vndb.org 生成，说明里这个域名是可点链接，直达 [https://vndb.org/u/tokens](https://vndb.org/u/tokens)（VNDB 官方指定的重定向地址）；输入框密文显示、圆点占位。整个区块只有一个动作按钮：输入框有内容时是「保存」（回车等效），点了即落盘并立刻验证一次，随后清空输入框、把结果交给状态行（尚未保存 / 已保存 / 已保存 · 连接成功 / 已保存 · Token 可能不正确），换了输入内容旧结果即失效；输入框为空时按钮转为「验证」，测的是已存的那份，验证「当前保存的」不必重新粘贴。「清除 Token」挂在状态行末尾作为文字动作，不与保存并列抢注意力。清除后账户数据同步不可用，已同步进库的内容保留。

#### 标签与特征显示中文名

- **描述**：VNDB 的标签（`g` 前缀）与角色特征（`i` 前缀）在界面上一律显示中文译名，覆盖近 6000 条。译名表随程序打包，启动时一次性载入。
- **前置**：无。译名随二进制发布，不依赖网络与额外文件。
- **后置**：详情页标签区、角色 traits、词云、排除池候选与表单选择器共用同一套中文名。
- **备注**：回退链为中文词典 → 库内的英文原名 → 裸 id。译名表与界面文案分开维护：译名随 VNDB 数据整批替换，缺条目属正常状态（回退英文原名），而界面文案缺键是缺陷；两者随界面语言切换的维度也不同，标签译名不跟 UI 语言走。标签与特征分表存放，同一个编号在两表里是不同词（`g2` 是奇幻，`i2` 是别的）。

### 活动集三 · 管理本地安装

<a id="as3"></a>

#### 手动为一部作品指定本地启动路径

- **描述**：在作品表单的「安装」页添加本地启动路径（可多条），每行一个可执行文件，并指定其中一条为默认启动。
- **前置**：作品处于表单编辑态；新增与编辑同一套流程。
- **后置**：保存时整包写回该作品的安装集合——草稿里带 `id` 的更新、不带 `id` 的新建、库里本作品有而草稿里没有的删除；顺序按数组下标写回；磁盘内容原样保留。
- **涉及字段与来源**：`dir_path` 与 `entry_path`（本地事实，从这一行的路径文本拆出：父目录与文件名）；`exes` 与 `sort_order` 由后端重算与派生，客户端给的值不采信。
- **备注**：一行一个输入框加右侧浏览按钮，浏览走文件对话框；手输的末段带可执行扩展名时按文件拆，其余整串按目录登记。默认由行首的单选圆点显式指定，默认项为空或指向已移除的安装时取列表第一条；列表次序由添加先后决定，不提供调序。同一目录可以加多个启动文件，各自成一条记录；目录本身只归一部作品，别的作品再加该目录下的文件报冲突。已有安装项的目录不在保存时重新读盘，换目录或新建时才读。`installations` 的唯一键是「目录 + 入口」这对，同一对只留一条，`entry_path` 为空按空串参与比较；`entry_path` 存相对 `dir_path` 的路径，空串、绝对路径与越出该目录的路径按非法输入拒掉。

#### 扫描目录发现未登记的作品

- **描述**：在标题栏品牌菜单挑一个目录（如整个游戏库根），扫描其直接子目录，识别各目录的作品名与启动入口，产出候选清单；用户在清单里勾选（可全选），确认后批量创建作品。
- **前置**：无（手动挑目录的单次扫描）。
- **后置**：勾选的目录逐条创建作品并写入安装记录（名称 = 目录名，默认入口 = 识别的候选入口，`entry_path` 相对 `dir_path`）；结果汇总「已添加 N 项，跳过 M 项」；作品列表刷新。
- **备注**：扫描经 `scan_dir` 命令异步执行（`spawn_blocking`），进度经任务事件通道（`scan`）在面板里展示且可取消；识别复用快捷添加同一套磁盘扫描与排除名单，无候选入口的子目录不进清单；已登记目录在清单里标灰禁选（与库内 `installations.dir_path` 忽略大小写比对），扫描与创建之间的窗口期冲突仍由保存时的既有冲突口径兜底计入跳过。清单的入口列就地编辑：候选下拉（datalist）列出扫到的入口，行尾浏览按钮打开文件对话框（以该行目录为起点）指定扫不到的深层入口，选到目录外提示未采纳；多候选且无同名顶层命中的行显示候选数提示点。批量创建走 `create_game` + `save_installations` 既有链路，逐条循环、单条失败计入跳过。

#### 设置某安装项的启动入口

- **描述**：把一条安装项的启动文件换成另一个可执行文件。
- **前置**：作品表单里存在该安装项。
- **后置**：`entry_path` 与 `dir_path` 按新的路径文本重拆；`exes` 由后端读目录重算。
- **备注**：改这一行的路径文本或用右侧浏览按钮重挑文件；换到别的目录时顺带把失效的目录大小置空。

#### 以转区方式启动某安装项（Locale Emulator）

- **描述**：给一条安装项打上「转区启动」开关，启动时不直接拉起入口，而是经 Locale Emulator（LEProc）以日文等区域设置拉起，应对日文原作的乱码与路径兼容问题。
- **前置**：作品表单里存在该安装项；设置页「工具」已登记 Locale Emulator 主程序路径（未登记时启动被拦截并提示）。
- **后置**：该安装项的 `le_launch` 置真；启动链路以 LEProc 为父进程、入口路径作参数、安装目录作工作目录拉起；转区开关下不透传附加参数（附加参数框禁用）。
- **涉及字段与来源**：`installations.le_launch`（用户写），`config.le_path`（用户写在设置页）。
- **备注**：开关是该安装项的属性而非全局偏好——同一部作品可以一条转区、一条不转区。LE 模式只接手入口文件的启动，不暴露 LE 自身的区域参数，也不提权。

#### 选择 Magpie 缩放方式启动某安装项

- **描述**：给一条安装项选 Magpie 缩放方式（关 / 全屏 / 窗口），游戏启动后自动触发对应动作：全屏把画面超分辨率放大到整个屏幕，窗口化只放大游戏窗口。
- **前置**：作品表单里存在该安装项；设置页「工具」已登记 Magpie 主程序路径（未登记时启动被拦截并提示）。
- **后置**：该安装项的 `magpie` 记为模式值（0 = 关，1 = 全屏，2 = 窗口）；启动走旁路链路：先把 Magpie 无参拉起（未在跑时）→ 等前台切换到游戏进程 → 停 2 秒 → 向 Magpie 的热键消息窗口 `PostMessageW` 一条 `WM_HOTKEY`，`wParam` 为 Magpie 热键动作序号（全屏 = `Scale`，窗口化 = `WindowedModeScale`），等价于用户按下对应热键。
- **涉及字段与来源**：`installations.magpie`（用户写），`config.magpie_path`（用户写在设置页）。
- **备注**：触发走消息窗口而非模拟按键：不依赖输入焦点、不受游戏抢焦影响、不需要管理员权限，也不抢用户的键鼠；消息窗口链路不校验用户有没有在 Magpie 里绑过热键，两个动作都能发。Magpie 旁路触发不进 Job Object、不记入游玩计时回路；计时侧靠前台白名单（前台进程映像名为 `Magpie.exe` 时仍算前台），缩放期间计时连续。与「转区启动」同时开启时链路叠加：LE 作父进程，Magpie 照常旁路触发。

#### 给某安装项附加启动参数

- **描述**：给一条安装项填附加启动参数（如 `-window`、`-screen-fullscreen 0`），启动时透传给入口进程。
- **前置**：作品表单里存在该安装项；该安装项未开「转区启动」（转区模式不透传，输入框禁用）。
- **后置**：该安装项的 `launch_args` 落库（去首尾空白，空串按未填写存 `NULL`）；启动时按 MSVCRT 引号规则拆成参数数组透传。
- **涉及字段与来源**：`installations.launch_args`（用户写）。
- **备注**：拆分遵循命令行引号规则：引号内为一个参数，引号内 `""` 表示字面引号；拆词只发生在直接启动模式，LE 与 Magpie 链路均不透传。

#### 启动一部作品并记录游玩

- **描述**：从详情页启动作品的默认安装项，并为这次游玩记一条记录：起点、前景时间、存活时间。
- **前置**：作品有可启动的安装项（默认项失效时回落列表第一条）；该作品当前没有进行中的记录。
- **后置**：入口文件在其目录下被拉起（转区项经 LEProc 拉起，选了缩放方式的顺带旁路触发 Magpie）；一条进行中的记录入账；结束时结算两个时长，并把这次的时间按时间口径累加进作品的总时长，必要时把「计划中」改成「游玩中」；结束后前端收到通知，弹出「本次游玩时间：X 小时 Y 分」并刷新列表与首页。设置里「启动游戏时最小化」开着时（默认开），拉起成功后主窗口缩到任务栏；收尾时窗口仍处于最小化状态则还原并聚焦，再发通知。开关关掉时窗口状态全程不动，藏到托盘的窗口不唤回。
- **涉及字段与来源**：`play_sessions.foreground_seconds` 与 `alive_seconds`（系统派生，由计时回路写入），`user_game_state.play_seconds`（系统在上面累加）。
- **备注**：进程被放进 Job Object 守着，子进程逃不出去，启动器型入口也被完整覆盖。偏差一律偏向少算：全屏挂机会计入前景时间；游戏进程脱离本进程树（走 Steam / DRM 客户端，或被系统服务代理）会被判成已经结束。详情页按固定间隔重取进行中的记录。转区启动时 LEProc 作父进程，Job 覆盖不缩水；Magpie 旁路进程刻意不进 Job，其生命周期由触发回路自行等待。游玩记录由启动动作产生，一次游玩一行；同一部作品同时只有一条进行中的记录，重复启动直接拒掉。结束判定带静默窗：进程全部退出后连续 3 秒仍为空才算结束（兼容启动器型入口拉起本体时的短暂归零）；上次没干净退出的进行中记录，在 FishVN 下次开库时按最后在场时间结算，不交给启动流程顺带做（那会结算掉别的作品的进行中记录）。

#### 写作品的总时长

- **描述**：用户写作品的总时长 —— 本应用之前玩掉的时间这样补。填完进表单草稿，随「保存」与其余改动一起提交，不单独落库。
- **前置**：打开作品编辑表单的「基本信息」。
- **后置**：保存时总时长按填写值落库。
- **涉及字段与来源**：`user_game_state.play_seconds`（用户写）。
- **备注**：输入认 `12:30` / `12h30m` / 纯数字（按秒），失焦只整理格式，认不出来就还原。游玩记录不由用户编辑；总时长可随时改写，软件的累加只在结算时发生。表单打开后没动过总时长就不写这一列 —— 进行中的游玩结算会自己往上累加，写回打开时的旧值等于倒退。

#### 移除某安装项（保留磁盘文件）

- **描述**：解除作品与某目录的关联，不删除磁盘文件。
- **前置**：作品表单里存在该安装项。
- **后置**：保存时该安装项从集合里消失；磁盘内容原样保留。

### 活动集四 · 浏览与筛选

<a id="as4"></a>

#### 列出全部作品摘要

- **描述**：进入列表时一次取全量摘要投影并常驻内存。
- **前置**：库存在。
- **后置**：渲染封面墙，按状态分区。卡片右下角常驻我的评分（实心 ★、强调色底）；存在社区评分时，指针悬停改为左侧的社区评分（空心 ☆、中性底）。两个口径同一时刻只出现一个，靠位置与形状区分，避免把社区分读成「我的分数变了」；某一侧缺评分就不画，不留占位。
- **备注**：摘要投影为 selector 从聚合中选出的子集；个人库规模几千条内不构成压力。分区与筛选栏的展示顺序固定，游玩中的排在最前。标题默认只在悬停时出现，设置里可改为常驻；常驻时标题占底部一行，评分让开右侧与它同行。

#### 打开一部作品的详情

- **描述**：整页切换到详情，按需取单条聚合（含重字段如简介、安装列表）。
- **前置**：用户从列表选择某作品。
- **后置**：展示身份、用户状态、元数据与默认启动路径；关闭即释放聚合。
- **备注**：重字段按需再取，与"属不属于这部作品"无关。
- 元数据行可能不存在（作品没绑过 VNDB），这不是失败，页面按空值渲染。
- 评分一律按十分制展示：VNDB 的 `rating` 与个人评分在库里都是百分制，91 显示 9.1，不补成 9.10。
- 启动按钮启动默认安装项的入口文件；默认项失效时回落列表第一条，都没有可启动的入口时按钮不可点，悬停给出原因。默认启动路径以路径条展示在动作条下方，点击直达表单的「安装」页；显示的路径与启动目标同源。
- 动作条与封面同宽（同一列）：开始游戏 / 时长格 / ⋯ 菜单。时长格显示作品的总时长，只放数字（没玩过显示 `--`），悬停提示可跳到该作品的游玩记录 —— 记录区在页末（感想之前），这是它唯一的入口。删除不进动作条，收进 ⋯ 菜单 —— 它不高频。

#### 查看一部作品的标签

- **描述**：详情页身份区下方以胶囊列出作品的标签。折叠态显示 8 条，超出时以「更多 N 项」展开；展开后在列表下方以一行小字报告被隐藏的构成，行尾提供剧透标签的就地开关。
- **前置**：作品带有标签。
- **后置**：折叠态与展开态共用同一套排序；就地开关只影响当前作品，全局默认值不变，收起后剧透标签重新折叠。
- **备注**：排序为 `rating` 降序、同分时挂载量少的靠前，再按题材、情节、角色、舞台、风格轮转交错；手输标签整组置顶并保持输入顺序，词典未收录 id 的沉底。轮转服务于折叠态的 8 条预算：题材类每部戏常有 10–20 条，按类聚合会让前 8 条被一个类占满，角色标签一条都露不出。技术向标签不进入标签区。行尾报告只统计否则会可见的标签：剧透折叠的、被成人向开关挡下的、技术向的都不计入这一行，同一批标签不报两次。轮转的意图在界面上没有视觉交代，胶囊按顺序平铺；分段标题或类别角标都会盖过标签本身，不做。

#### 查看一部作品的制作人员

- **描述**：详情页在角色区之后展示制作人员模块，按职能分组，各组以多列网格排布。
- **前置**：作品的元数据里有制作人员条目。
- **后置**：每个职能一组，职能名作组标题，人名在组内竖排；同步备注以小字灰显跟在人名后，列宽不足时在组内换行；超过 8 人的组默认收起，组尾「… 还有 N 人」展开、再点收回；模块整体另有限高，内容超出在内部滚动。
- **备注**：人名展示以原文姓名优先，罗马字转写放进悬停提示；职能名取本地化映射，同步带来映射外的职能时原样显示。

#### 查看一部作品的游玩记录

- **描述**：详情页在制作人员之后用一条累计曲线画出这部作品的游玩轨迹：横轴从第一次游玩到最近一次，纵轴是累计时长，每级台阶对应一次游玩，台阶高度就是那一次的时长。
- **前置**：作品存在游玩记录。
- **后置**：覆盖全部历史，不按窗口截断；末点标出累计总量，指针移上去读某一次的日期、那一次时长与当时的累计；没有任何会话时整个模块不出现。
- **备注**：不按月聚合，也不切窗口。按月聚合是先把精确到秒的记录扔掉、再画一遍统计页已经有的东西；累计曲线一旦从窗口起点起算，y 轴就从零开始，读起来像「总共只玩了这么点」，与封面那个总时长打架。全周期累加让长跨度自动压成平段 —— 停玩一年是一条水平线，因此不需要空月压缩与「更早还有 N 次」两个控件。
- **备注**：曲线画的是软件记录到的会话累计，封面的时长格可手填，两者不必然相等，图的右上角写明当前口径与这层差异。刻度按小时取整（1/2/5/10 小时），不足一小时改按分钟取整；时长口径取设置里的那一项，与统计页、首页同源，换口径改的是整条曲线的陡缓。进行中的会话随固定间隔重取，末端会自己长高。

#### 按状态筛选作品

- **描述**：在"全部 / 游玩中 / 计划中 / 已完成 / 已搁置 / 已弃坑"之间切换，列表按所选状态过滤。
- **前置**：存在作品。
- **后置**：列表仅显示匹配状态的作品，各状态带计数。
- **备注**：筛选属于列表视图状态。

#### 组内排序作品列表（我的列表与首页）

- **描述**：「我的列表」工具栏右侧与首页「我的游戏」模块标题行右侧各有一个排序控件（当前值描述文字 + 图标按钮，点击展开菜单），在名称（默认）/ VNDB 评分 / 我的评分 / 添加时间之间切换。排序只作用于状态分组内部，分组与组序固定不变。
- **前置**：列表非空。
- **后置**：各区按所选方式重排：名称按 zh-CN 升序；VNDB 评分与个人评分降序、无评分的排后；添加时间新的在前。
- **备注**：两处排序状态各自独立，持久化到重启（与卡片标题常显、表单 tab 记忆同模式）；存储值非法时回落按名称。与查询页的排序互相独立。首页模块标题行的排序控件随模块显隐——模块关闭时不出现。

#### 按名称搜索并跳转作品

- **描述**：标题栏常驻搜索框，输入后分两段给出结果——先作品，按名字、别名与 `vndb_id` 的子串匹配并高亮命中词；再设置项，按界面文案与关键词匹配。点作品或回车跳到该作品的详情，点设置项打开设置页。`/` 与 Ctrl+F 在任意非输入位置唤起搜索框；↑↓ 切换选中项，Esc 收起。
- **前置**：无。
- **后置**：切换到目标位置，搜索框收起。选作品固定落在「我的列表」视图下的详情，返回时回到「我的列表」与它上次的滚动位置，不回到发起搜索的那个视图。
- **备注**：搜索只负责跳转；「我的列表」的筛选仍只由状态条控制，两者不联动。作品结果取全量摘要就地匹配，不额外请求；面板展开有 300 毫秒防抖，避免边打字边闪；选中设置项只打开设置页，不定位到具体设置行。空输入不展开面板，无命中时显示一条空态。

#### 组合条件查询作品

- **描述**：查询页以「作品」为主体组合条件检索库内作品。侧栏条件卡分两组：「作品」组——标签（任一 / 全部＋排除）、状态、评分（VNDB / 个人，区间）、发行日期（区间）、开发商（子串）、通关时长（区间，小时）；「角色」组条件在作品主体下作用于作品的角色，任一角色满足即命中该作品。条件行之间 AND。
- **前置**：库存在。
- **后置**：结果为封面卡片墙（60 条以上窗口化渲染），与「我的列表」同一套卡片；顶部显示命中计数，排序可选 VNDB 评分 / 个人评分 / 添加时间 / 名称。
- **涉及字段与来源**：标签、开发商、发行日期、VNDB 评分、通关时长取元数据；状态、个人评分取用户状态。全部本地可满足，不发网络请求。
- **备注**：剧透过滤跟随设置里的剧透级别——等级不低于阈值的标签不参与命中，包含与排除同规则。标签与特征条件的选择器为库内 / 词典双 scope：默认列库内聚合（带出现计数，自定义项天然在内），可切全部词典兜底；条件值有 id 存 id、无 id 存名字，两种取值都精确匹配。

#### 组合条件查询角色

- **描述**：查询页切到「角色」主体，以角色为结果单位组合条件。「角色」组条件作用于角色本身——特征（任一 / 全部＋排除，选择器同上双 scope）、出场定位、性别、名字包含、声优（多选，任一命中）；「作品」组条件作用于角色所属的作品。
- **前置**：库存在。
- **后置**：结果为轻量列表：角色名＋原名＋所属作品；点击一行打开所属作品的详情页并自动展开该角色。排序可选名称 / 所属作品。
- **涉及字段与来源**：特征、定位、性别、名字、配音关系取角色与配音表；作品组条件同「组合条件查询作品」。
- **备注**：声优条件按声优编号匹配，VNDB 的配音条目恒指人物主编号，跨马甲归属天然正确；两个主体的分组副标题随主体切换说明当前作用对象（作品主体下角色组＝任一角色满足即命中；角色主体下作品组＝作用于角色所属作品）。

#### 在查询页切换与往返间保持状态

- **描述**：查询页的条件、排序、两个主体各自的结果与滚动位置，在主体切换与跳转详情后返回之间保持。
- **前置**：无。
- **后置**：切主体不重置条件，两主体各自缓存最近一次结果；跳转后返回立即呈现上次结果与滚动位置；条件内容未变化（开合卡片、切回原主体）时不重复请求，计数与列表保持稳定。
- **备注**：状态提升至模块级 store，视图往返不销毁；滚动位置记忆沿用 App 层 saveViewScroll 惯例（切换时刻保存、返回后恢复）。

#### 返回时还原列表的筛选与滚动位置

- **描述**：从详情返回列表时，恢复离开前的筛选状态与滚动位置。
- **前置**：曾进入详情。
- **后置**：列表还原到离开时的筛选与滚动偏移。
- **备注**：筛选状态与滚动位置均会在返回时还原；首页的滚动位置以同一机制还原（首页无筛选状态）。

### 活动集五 · 管理一部作品的角色

<a id="as5"></a>

#### 为一部作品新增一个角色

- **描述**：在作品表单「角色」页追加一个空白角色，随即填写其档案字段。
- **前置**：作品处于表单编辑态。
- **后置**：角色集合末尾多出一条；保存时随作品一并提交。
- **涉及字段与来源**：`id`（本地生成，与 VNDB 的 c 编号同列混排）；其余为用户输入。
- **备注**：角色不单独落库，随作品保存时整包提交。角色以作品为单位整包替换：先删该作品的全部角色行（配音关系靠外键级联），再按数组顺序写回；数组下标即顺序，客户端给的 `sort_order` 不采信。

#### 编辑一个角色的档案

- **描述**：修改角色的名字、原名、性别、年龄、身高、体重、三围（胸围 / 腰围 / 臀围 / 罩杯）、生日、血型、出场定位、简介与特征（traits）。
- **前置**：该作品已有至少一个角色，且当前选中了其中一个。
- **后置**：草稿更新；保存时整包写回。
- **涉及字段与来源**：名字、原名、性别、年龄、身高、体重、三围、生日、血型、出场定位、简介与 `traits`（人物特征）均为用户输入；VNDB 同步可带入这些字段的建议值，用户可覆盖。
- **备注**：出场定位取 VNDB 的四档（主角 / 主要角色 / 配角 / 登场）。生日保持文本输入（VNDB 的角色生日一半无年份，日期控件要求完整年月日），失焦校验格式——放行 `YYYY-MM-DD` 与无年份的 `M-D`，不符时行内报错。特征在角色表单内编辑：输入行手输（回车或逗号添加、Esc 清空、空输入时退格删末项）自定义特征，「从库内特征挑选」在右侧并排打开选择器按 VNDB 顶层分组（Hair / Eyes / Body / Clothes / Items / Personality / Role / Engages in / Subject of）归类展示，可搜中英文名、点选加入或移除、已选以强调色标出；特征携带分组信息，落位正确，库内无 id 的自定义特征归「其他」，且自定义特征也注入选择器，可在侧栏高亮并点选移除。特征随角色整包写回，切换角色时表单与选择器都跟随当前角色。

#### 为一个角色指定本地立绘

- **描述**：通过原生文件对话框为角色挑选本地图片作为立绘，也可手工输入图片路径。
- **前置**：选中了某角色。
- **后置**：`image_path` 为所选图片的绝对路径；卡片渲染该立绘，无立绘时以角色名占位。
- **备注**：立绘走与封面同一条派生图管线（缩图与访问授权）。

#### 增删一个角色的声优

- **描述**：为角色添加或移除配音声优，可带版本标记（如作品的重制版）。新增时输入框对库内已有声优自动补全（匹配显示名、主名与原文），选中即复用该声优编号；完全无匹配才铸造新的本地声优。已选署名胶囊可点击，就地编辑版本备注（署名级，随角色保存）。
- **前置**：选中了某角色。
- **后置**：配音关系增删对应行；手输命中已有声优时复用全局表同一行，不再另铸编号；声优按编号复用全局表，已存在的声优行不被本地手填的名字覆盖。
- **备注**：同一对角色与声优在不同版本标记下各自保留。手输未匹配时以 `local-` 前缀新编号入库，与 VNDB 同步附带的 `s` 编号同列混排；录入归并（自动补全）从源头避免同一人分裂成多个实体。

#### 管理声优实体（主名编辑与合并）

- **描述**：在角色编辑器的声优编辑块里维护声优作为全局实体的数据：修改主名与原文（界面标注全局生效），或将该声优并入另一个声优。两个入口都挂在署名胶囊的点击编辑块内。
- **前置**：角色编辑器内存在该署名。
- **后置**：改名写 `staffs` 并立即落库，库内该声优的所有显示随之更新；合并把来源的全部配音关系重指向目标并删除来源行，目标主名空缺时从来源补上。
- **涉及字段与来源**：`staffs.name` / `staffs.original`（用户写，个体层权威）。
- **备注**：署名证据（各作品署的名）不随改名被涂改——它是「这一作封面署的是什么名」的事实；合并遇到同角色同版本标记的重复署名时丢弃重复行。改名、合并与录入自动补全三者共同保证「同一声优在库内只有一个实体」。

#### 调整一部作品里角色的顺序

- **描述**：用左移 / 右移按钮改变角色在作品中的先后次序。
- **前置**：该作品有至少两个角色。
- **后置**：保存时按数组下标重写顺序，读取按该顺序返回。
- **备注**：卡条是吸边滚动，不做拖拽重排——会与吸边打架。

#### 查看一部作品的角色

- **描述**：在详情页浏览该作品的角色列表，展开查看单项详情。
- **前置**：已打开某作品的详情。
- **后置**：展示角色立绘、原名与首位声优；展开后显示性别、尺寸（身高 / 体重）、年龄、血型、三围、声优、简介与按分组归类的 traits，并提供「在 VNDB 查看完整资料」外链，用系统浏览器打开该角色的 VNDB 页面。
- **备注**：traits 的分组在 VNDB 侧没有序号字段，前端固定一张展示顺序表，不在这张表里的新分组排到末尾；剧透折叠阈值跟随设置里的剧透级别（全部隐藏从等级 1 起、仅隐藏严重从 2 起、全部显示不折叠），成人向分组不进正文。剧透特征不并入分组，揭示后在特征表下方单独成行，与标签区共用同一套开关与计数文案。traits 没有五根归属，不参与显示范围的判定。

#### 删除一个角色

- **描述**：从作品中移除一个角色。
- **前置**：选中了某角色。
- **后置**：该角色与其配音关系一并移除；保存时随整包替换落库。
- **备注**：配音关系随角色删除；声优作为全局表保留，失去最后一个配音关系的行随即回收。

#### 从 VNDB 同步一部作品的角色

- **描述**：随「同步元数据」一并拉取该作品的角色与配音关系，按角色名比对后逐条取舍。
- **前置**：作品已绑定 `vndb_id`。
- **后置**：角色的档案、立绘与 traits 落库；配音关系按角色、声优与版本标记去重。
- **备注**：源为 `/character`（角色档）与 `/vn` 的 `va`（声优，带版本标记），接口坑与数据模型见 `docs/dev/vndb-api.md`。只取主角与主要角色两档：`side` / `appears` 里混着无立绘的配角，收进来只是让卡条多一排占位块，还要为它们多下一批图。
- 与本地角色按名字配对，配对键优先取原名——罗马字名重名会把两个不同角色判成同一个。与作品级同口径：本地优先，冲突项逐个取舍后随保存落库。角色冲突不单独开面板，作为「角色」分节展示在同一张取舍面板的元数据行下方；本地没有的新角色直接补进列表，随保存落库。

### 活动集六 · 调整软件设置

<a id="as6"></a>

#### 切换主题

- **描述**：在设置页「基础」标签内选择浅色 / 深色 / 跟随系统。
- **前置**：打开设置页。
- **后置**：整个界面即时切换配色；选择写入数据目录的 `config.json`，重启后保持。选「跟随系统」时按操作系统当前的深浅渲染，系统在运行中切换深浅，本应用就地跟着变，无需重启。
- **备注**：存的是选择本身而不是解析结果，所以系统换色后下次启动仍跟随。窗口外壳与启动页的配色在界面渲染前就按主题就位，深浅两色都无白闪；`localStorage` 只是首帧缓存，权威在配置文件。

#### 选择强调色

- **描述**：在设置页「基础」标签内从六种强调色（绯红 / 琥珀 / 海洋 / 樱花 / 翡翠 / 紫罗兰）中挑选界面主色。
- **前置**：打开设置页。
- **后置**：强调色写入数据目录的 `config.json`，重启后保持；界面即时按新色渲染。
- **备注**：强调色与深浅主题正交，每种色在两套主题下分别给定色值；按钮、选中态、焦点等主色元素跟随强调色。窗口外壳与启动页在界面渲染前就按强调色就位，切换无闪变。

#### 调整界面字号

- **描述**：在设置页「基础」标签里用滑块调整整体字号，75%–125%、步长 5%，右侧显示当前百分比；缩放作用于根字号，全部文字与控件同步变化，拖动即生效。
- **前置**：打开设置页。
- **后置**：缩放值写入 `localStorage` 的 `fishvn.fontScale`，重启后保持。
- **备注**：读写两端都夹在 0.5–2.0，界面只暴露中间一段。`index.html` 首帧前就读出并写 `--app-font-scale`，与主题一样没有首帧跳变。

#### 减少动画

- **描述**：设置页「基础」区的开关，开启后跳过位移动画与转场（菜单展开、下拉弹出、封面飞入转场、视图切换、滚动进入动画等），保留淡入淡出；加载指示器（spinner、同步进度）不受影响。
- **前置**：打开设置页。
- **后置**：开关写入 `localStorage` 的 `fishvn.reduceMotion`，判定结果落到 `<html data-reduce-motion>`，界面动画就地降级，切换即时生效、重启后保持。
- **备注**：应用内开关优先；默认关闭时跟随系统的 `prefers-reduced-motion`（Windows「动画效果」设置），系统在运行中变化时实时同步。判定源统一在动画模块（`lib/motion.js`），滚动进入动画、封面飞入转场、视图切换过渡等消费方读同一判定，减少时直接跳过；CSS 侧按 `data-reduce-motion` 属性把位移动画降级为纯淡入。原先零散的局部 reduce 规则已收编到统一判定下。

#### 选择计时口径

- **描述**：在前景时间与存活时间两种口径间二选一，决定游玩结束时把哪个时长累加进总时长。
- **前置**：打开设置页。
- **后置**：选择写入数据目录的 `config.json`；此后启动与收尾的结算按新口径取值，历史记录不回算。
- **备注**：口径在结算线程内即时读取，选完即对下一局生效；配置损坏或缺省时按前景时间处理。

#### 首页包含未安装的作品

- **描述**：设置页「基础」区的开关，决定首页「我的游戏」模块是否收录没有本地安装项的作品。
- **前置**：打开设置页。
- **后置**：开关写入 `config.json`；首页三分区按新口径即时重渲染。
- **备注**：默认开启。它只作用于「我的游戏」模块，继续游玩与统计概览不受影响；关闭后回到严格本地口径。开关挂在「我的游戏」行内作为子项，模块关闭时置灰禁用——模块不上首页时口径无意义。

#### 退出应用

- **描述**：系统托盘常驻，菜单两项「显示」「退出」；点窗口关闭按钮时按「退出时行为」设置处理——直接退出（先弹确认）或最小化到托盘。
- **前置**：无。
- **后置**：最小化时窗口隐藏、托盘仍在，从托盘「显示」唤回；确认退出与托盘「退出」结束进程。
- **备注**：设置入口在基础页底部；托盘「退出」不经确认；直接退出的确认与放弃表单改动共用同一套确认弹窗。

#### 隐藏成人向标签

- **描述**：设置页「内容」区的开关，开启后 category 为 ero 的标签在详情页标签区与统计页词云中隐藏。
- **前置**：打开设置页。
- **后置**：选择写入数据目录的 `config.json`；详情页与词云按新值过滤，编辑表单不受影响。
- **备注**：开关只影响展示，不修改库内标签数据。它只管内容状态这一层：显示范围（技术向）与排除池（个别偏好）各自独立判定，任一命中即隐藏；报告被排除条数时先按范围与状态筛一遍，再查池子，同一批标签只报一次。

#### 选择剧透标签的默认隐藏级别

- **描述**：设置页「内容」区的三选一，决定剧透标签（VNDB 的 spoiler 等级 1/2）默认隐藏的范围：全部隐藏、仅隐藏严重、全部显示。
- **前置**：打开设置页。
- **后置**：选择写入 `config.json`；详情页标签区按级别拆分可见与折叠两拨，词云按级别过滤，角色 traits 的折叠阈值跟随级别，查询的标签与特征命中过滤同样跟随级别（等级不低于阈值的条目不参与匹配）。
- **备注**：详情页展开态提供就地开关，可临时展开当前作品的折叠剧透标签，全局默认值不变。不给剧透标签打特殊标记：VNDB 只提供 1 与 2 两级，不说明剧透的具体内容，标注成本高且不可靠，标了也帮不上判断，因此只在展开态给出「已折叠 N 条」与就地方便查看。

#### 管理标签排除池

- **描述**：设置页「内容」区维护一份标签排除池：池内标签不再出现在详情页标签区与统计页词云。候选取自库内已有标签，按出现次数降序列出并可搜索，点选加入，每个条目可单独移出。候选只列可能出现在界面的标签：技术向标签在任何界面都不显示，不列入候选，选择器顶部以「技术向标签已默认排除」一行说明。
- **前置**：打开设置页。
- **后置**：名单写入 `config.json`；详情页与词云按名单过滤，编辑表单不受影响。
- **备注**：初始预置 VNDB 挂载量前 14 的可挂载（applicable）、有中文译名且非技术向的标签（色情内容、男性主人公、恋爱、女性主人公、奇幻、戏剧、多分支结局、主人公露过正脸、大量色情内容、拔作、非插入式做爱、虚构物种、学生女主角、性骚扰），均可删除。预置要求 applicable：VNDB 的不可挂载条目（如 No Sexual Content、Penetrative Sex、Student）是否定式元标记，不描述作品内容，选入会在界面显示裸 id；要求有中文译名：译名回退链为中文词典 → 库内英文名 → 裸 id；要求非技术向：技术向标签永不显示，预置里放进也无效，单测对这两条逐项校验。字典标签按 id 命中排除池，手输标签按名称命中；详情页展开态以一行小字报告被池子隐藏的条目数。库内标签候选随同步、编辑、删除作品实时刷新。候选不过滤成人向与剧透：两类是条件可见，随开关可能变成可见，单独排除其中某一条亦有用途；若候选随偏好变化，已进池的条目被隐藏后无法先删再加回。池子存 id 而非名字：名字是外部数据，换译名或改译法后按名字存的条目会静默失效，id 由 VNDB 保证稳定。

#### 登记启动工具路径（Magpie / Locale Emulator）

- **描述**：设置页「工具」标签登记两个外部工具的主程序路径：Magpie（画面放大）与 Locale Emulator（转区运行，LEProc）。安装行上的 Magpie 缩放方式与「转区启动」开关读这两个配置决定启动链路。
- **前置**：打开设置页。
- **后置**：路径写入 `config.json`；失焦即校验并保存——填过的路径必须存在（`path_exists` 命令校验），不存在时行内报错、不落库；清空即注销该工具。
- **涉及字段与来源**：`config.magpie_path` 与 `config.le_path`（用户写，均可空）。
- **备注**：留空表示未启用：对应开关在启动时被拦截并提示去设置页登记。路径只登记不托管——升级换位后用户自己改这里。两个工具都是本机第三方软件，不随应用分发。

#### 选择 VNDB 同步方式

- **描述**：在设置页「VNDB」标签里三选一：仅下载 / 仅上传 / 双向，决定账户数据同步的方向。
- **前置**：打开设置页。
- **后置**：选择写入 `config.json`，并立即使已生成的同步计划缓存失效。
- **备注**：三种力度均已实现。上传与双向要求 Token 带 `listwrite` 权限，同步开始前用 `/authinfo` 检查，缺权限直接提示。

#### 同步评分

- **描述**：设置页「VNDB」标签的开关，决定个人评分是否参与账户同步。
- **前置**：打开设置页。
- **后置**：开关写入 `config.json`，并立即使同步计划缓存失效。
- **备注**：默认开启。关闭后 `user_rating` 不参与任何方向的比对——不写本地、不推送、不动同步基线，状态照常。重新打开时基线还是关闭前的值，可能先出现一次冲突；偏保守的一侧。

#### 同步计划中的游戏

- **描述**：设置页「VNDB」标签的开关，决定状态为计划中的条目是否参与账户同步。下载侧表现为是否导入为新作品，上传侧表现为是否把本地计划中的作品推到 VNDB。
- **前置**：打开设置页。
- **后置**：开关写入 `config.json`，并立即使同步计划缓存失效。
- **备注**：默认关闭——本地优先，只搬有用的数据。它影响的是同步计划的生成：下一次生成按新值重算，已展示的旧计划不就地改写。

#### 创建整库备份

- **描述**：设置页「数据库」标签点「创建备份」，把当前游戏库（作品、封面、设置）存一份副本到备份列表。
- **前置**：打开设置页。
- **后置**：备份列表新增一条带创建时间的记录。

#### 自动清理旧备份（可关闭）

- **描述**：设置页「数据库」标签的「自动清理」下拉：不自动清理 / 保留 7·30·90·180 天。开启后，每次创建备份会清掉超过保留天数的旧备份。
- **前置**：打开设置页。
- **后置**：选择即时生效，默认不自动清理。

#### 从备份还原整库

- **描述**：备份列表每项「还原」，二次确认后把该备份恢复为当前库。还原不需要重启应用，确认后即生效。
- **前置**：备份列表里存在备份。
- **后置**：当前库替换为该份备份的内容，界面就地刷新。
- **备注**：还原会覆盖当前作品、状态、游玩记录与封面，且不可撤销。

#### 删除备份

- **描述**：备份列表每项「删除」，二次确认后永久删除该份备份。
- **前置**：备份列表里存在备份。
- **后置**：该份备份从列表消失，对应的备份文件被删除。

#### 启动等待（品牌页随就绪淡出）

- **描述**：窗口出现时画面必定已有内容——数据在阈值内就绪时窗口直接带完整首页出现，品牌页不出现；更慢时窗口与品牌页同一帧出现，数据渲染完成后淡出。
- **前置**：无。
- **后置**：窗口出现后不存在空白帧；淡出后露出的首帧是加载完的首页；主题背景与主界面同值，前后零跳变。
- **备注**：品牌页是纯 HTML/CSS，脚本未执行也照常显示，进程级兜底放出来的也是它而不是空窗；数据加载卡住 8 秒强制放行；浏览器 dev 环境直接跳过。实测数字与阈值约束见第 4 章。

### 活动集七 · 首页

<a id="as7"></a>

#### 查看库的统计概览

- **描述**：首页以数字行展示库的现状：作品总数、游玩中 / 计划中 / 已完成三个状态的计数、累计时长、本周时长与游玩次数。
- **前置**：库存在且作品总数大于 0（空库整节隐藏，由空态提示兜底）。
- **后置**：各值反映当前库内数据；本周时长按设置的时间口径聚合七天内的游玩记录。
- **备注**：计数与时长来自一次聚合查询，不逐条取聚合；累计时长即各作品 `play_seconds` 之和（含用户手填部分），与详情页口径一致。首页不展示搁置与弃坑计数（首页分区不含这两类），统计页保留五状态全量。统计页的统计数字与本节同源，是它的扩展视图。

#### 自定义首页的模块开关与顺序

- **描述**：在设置页的「首页布局」里开关各模块并调整上下顺序，首页按该顺序渲染启用的模块。
- **前置**：打开设置页。
- **后置**：布局写入数据目录的 `config.json`，重启后保持；首页即时按新布局渲染。
- **备注**：布局是有序的「模块 + 开关」列表，缺省顺序为继续游玩、统计概览、我的游戏；首页只渲染它认识的模块，配置里多余的 id 被忽略。统计概览在作品总数为 0 时整节隐藏（空库一排 0 无信息量）；继续游玩与我的游戏没有可展示的条目时整节隐藏。库为空时显示空态：图标、「还没有游戏」提示、「扫描文件夹或手动添加」一句与「添加游戏」按钮，按钮唤起标题栏添加菜单——空态即引导，库建立后自然消失，无持久化。

#### 从首页继续游玩（最近游玩 + 一键启动）

- **描述**：首页以 16:8 场景卡横向分页展示最近游玩的作品：封面裁切满铺整卡，斜向压暗渐变上叠图上信息——「继续游玩」标签（强调色，图上用淡化变体）与作品名，右下角为总时长（用户可改，为 0 不显示，格式为整数「X 小时 Y 分」/「Y 分」，不足 1 分钟显示「&lt;1 分」）；分区标题行右侧有分页圆点，横向按卡步进翻页。点击卡片任意位置（含 hover 居中浮现的播放按钮）都是继续游玩：跳转详情并自动启动默认安装项，起飞动画从卡片的居中竖幅窗口过渡到详情封面。
- **前置**：存在游玩中、有启动入口且有游玩记录的作品；没有时整节隐藏。
- **后置**：卡片按上次游玩时间倒序；自动启动后详情页进入会话计时。
- **备注**：筛选范围是状态为游玩中且入口可启动的条目，已完成、已搁置与已弃坑不出现；无默认安装或不可启动时只跳转不自动启动。横滚分页走水平分页契约（`docs/dev/shell.md`），封面裁切保上不保下（竖封裁宽幅取偏上区域）。

#### 首页展示我的游戏

- **描述**：首页以「我的游戏」模块展示作品，按状态分为游玩中、计划中、已完成三区；每区以封面墙排布，卡片点击进入详情。
- **前置**：作品状态为上述三者之一；没有安装项的作品是否收录由「首页包含未安装的作品」设置决定（默认收录）。
- **后置**：模块按当前口径呈现子集；某状态没有条目时该区隐藏，模块没有任何条目时整个模块隐藏。
- **备注**：子集判定随设置浮动——开启时全量收录，关闭时以安装项数量判定，均不要求入口可启动；已搁置与已弃坑不上首页。每区组内按模块标题行的排序控件排序（默认作品名，见「组内排序作品列表」），超过 60 条的区逐行窗口化渲染。模块默认启用，可在设置里开关与排序；「我的列表」始终展示全量，与该设置无关。

### 活动集八 · 统计页

<a id="as8"></a>

#### 查看库的统计数字

- **描述**：统计页是主导航的独立页面；页面顶部以数字行展示库的现状：作品总数、五个状态（游玩中 / 计划中 / 已完成 / 已搁置 / 已弃坑）的计数、累计时长、本周时长与游玩次数。
- **前置**：库存在（空库各值为零，照常展示）。
- **后置**：各值反映当前库内数据。
- **备注**：与活动集七「查看库的统计概览」同源同口径（同一次聚合），统计页是它的扩展视图；累计时长含用户手填部分，与详情页口径一致。

#### 查看游玩活跃度

- **描述**：统计页以面积图展示近 6 个月每月的游玩时长：按月聚合游玩记录的前景时间，无游玩记录的月补零，跨年不断档。
- **前置**：库存在。
- **后置**：图按月份从左到右排列，纵轴为时长刻度，峰值标注时长；一条游玩记录都没有时显示空态。
- **备注**：固定按前景时间口径聚合；计时口径只决定游玩结束时累进总时长取哪个值。

#### 查看游玩时长排行

- **描述**：统计页以横向条形列出累计时长前 6 的作品，含排名、作品名与时长，条长按榜首归一。
- **前置**：库内存在时长大于零的作品。
- **后置**：按时长降序展示；没有可展示的作品时显示空态。
- **备注**：时长取作品的总时长（含用户手填部分），零时长不进榜；与统计数字的累计时长同源，可对账。

#### 查看发行年代分布

- **描述**：统计页以柱状图按发行年代统计作品数量，分 2000 年前 / 2000 年代 / 2010 年代 / 2020 年代四档。
- **前置**：库内作品带有发行年份。
- **后置**：每档一根柱并标数量；没有有效年份时显示空态。
- **备注**：年份取自元数据发行日期的前 4 位，无法解析或超出 1900–2100 的值不计入。

#### 查看游玩偏好

- **描述**：统计页以词云展示库内题材与角色标签的共有情况：词越大、越靠中心出现频次越高，颜色深浅同样随频次，统一使用强调色。
- **前置**：库内两部以上作品带有关联 VNDB 的标签。
- **后置**：候选标签经四层管道收敛后取前 40 铺满卡片：lie 剔除；剧透与成人向按设置过滤；标签须落在「进词云」的显示范围——即题材（g1）与角色（g20）两个根下的标签及手输标签，技术向标签与舞台、情节、风格三类不进；只保留两部以上作品共有的标签；排除池命中的条目剔除。副标题显示候选总数与被排除池挡掉的条数；候选全部进入排除池时提示前往设置调整，没有候选时提示同步元数据后显示。
- **备注**：词典未收录的新标签 id 归入放行，词典再生后自动归队；平票时按标签名字母序取稳定次序。设置变更与库内标签变更（同步、编辑、删除）都实时刷新词云。单个标签的详细解释留待后续，入口定在悬停提示。判定层级、排序与计数口径见 [docs/dev/tags.md](dev/tags.md)。

## 4. 启动性能基线

本机 Windows 桌面实测，从 webview 开始导航起算（库内 4 部作品、2 个安装项）：

| 阶段 | 打包版 | `tauri dev` |
|---|---|---|
| splash 解析完成 | 52–61ms | 48–63ms |
| 首屏数据就绪（`app:ready`） | 129–157ms | 878–1008ms |
| 窗口实际出现 | 130–170ms | 310–360ms |

- 打包版的窗口出现时刻等于数据就绪时刻，品牌页不渲染；dev 下数据要等 Vite 的按需模块图，窗口在阈值处带品牌页出现，中间没有空白帧。
- dev 的窗口出现晚于阈值 60–110ms，是主线程被模块加载占住导致的定时器排队，不构成打包版的成本。
- 判定阈值相对打包版就绪时间留约 100ms 余量。新增首屏请求、改首屏视图时这个余量要重新对照——阈值低于就绪时间会让同一台机器时而跳过品牌页、时而显示。库规模对就绪时间的影响量级见下段，不构成主要变量。

`app:ready` 的口径是首屏可读，由启动时实际挂载的视图派发；后端就绪日志与它不在同一条时间轴上（后端从 `main()` 起算，前端从 webview 导航起算），两者不可相加。

首页的数据查询与库规模弱相关。原 SQL 实测（各取 15 次最小值，库内 2000 条游玩记录）：

| 作品总数 | `list_games` | `stats` |
|---|---|---|
| 100 | 0.34ms | 0.03ms |
| 892 | 3.19ms | 0.20ms |
| 3884 | 15.23ms | 0.84ms |

近 4000 部时两条查询合计仍在 20ms 以内，低于单次 IPC 往返。启动耗时集中在 webview 导航、bundle 解析与首屏渲染，不在数据层。`list_games` 按全量取回设计、不设分页，这个取舍的边界就是上面的数字——库规模增长不构成改它的理由。

## 5. 后续迭代落点

FDD 后三步（按功能计划 / 设计 / 构建）对每个功能集迭代推进：

- **VNDB 同步方向** 三种力度均已建成：仅上传走逐条 `PATCH`，双向按条目级时间选默认侧；评分可整体关闭（`vndb_sync_rating`，默认开）。限流下的自动重试仍未做（429 直接报错），上传中途也不能取消——几百条的首次全量要跑二十来分钟。
- **安装项的目录大小**（`size_bytes`）在手动指定流程里留空：对整棵子树求和在保存路径上耗时不可控，值由扫描流程连同遍历一起补。
- **网络调用的排队等待提示** 尚缺：请求级超时已设（20 秒，超时提示独立于连接失败），但 `fetch_vn_metadata` / `search_vndb` / 账户同步被限流排队时只显示加载中，排队的等待上限与提示没有。
- **派生图缓存无清理机制**：`covers/` 按内容寻址累积（作品封面与角色立绘同目录），换过的封面旧文件会留下。缺清理策略。
- **统计页**的候选面板未实现：状态分布、评分分布、开发商 TOP、硬盘占用；词云的单标签详细解释待做，入口已定在悬停提示。
- **声优实体的收尾**：VNDB 同步时把名字一致的手输声优升级为真实编号尚未做——当前手输与同步各用各的编号，同步后同一人可能并存两行，可经「并入其他声优」手动合并；别名表与误合并的拆分（暂可删署名重录覆盖）待真实需求出现再加。
- **补全页的收尾项**：限流排队时缺倒计时、运行日志只留最近一段、库里没有按名绑定的条目时「仅看无 ID」形同空开关。（清单已改为全量列表按名称稳定排序，可切到库内全部条目；任务执行顺序锚定同一规则，排序不再是待办项。）
- **查询页**的词表已无本地够不着的维度（标签与特征选择器均为库内 / 词典双 scope，十一种条件行全部本地可满足）；保存查询方案、结果导出等待需求驱动再议。

每个功能进入构建前，仍按项目工作流先出方案、过目确认后再实现。
