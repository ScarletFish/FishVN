# 作品库功能需求文档

> 本文覆盖 FDD 前五过程里的前两步（开发整体模型、构建功能列表），并为后三步（按功能计划 / 设计 / 构建）提供分活动集的落点。

## 文档说明

- **范围**：作品库（Galgame 本地管理）领域的全部功能需求，按五个活动集组织。
- **状态标注**：每个功能标注当前落地情况，基于编写当日（2026-10-16）对代码与命令层的核对，不代表最终设计变更：
  - `已实现` —— 后端命令与前端流程均已接通。
  - `部分实现` —— 核心已通，存在明确缺口（在备注中说明）。
  - `待实现` —— 后端或前端尚未接通，或仅 API 层就绪、缺用户流程。
- **核心思路**：作品条目独立，可进行四个维度（身份、用户状态、本地安装、VNDB元数据）数据的编写，并管理其下属的角色（见活动集五）。特此说明一点：VNDB同步产生的字段值为建议值，用户可选是否采纳。`vndb_id` 可空且 `UNIQUE`（NULL 之间不冲突），后续功能描述不再逐条重复此原则。

## 1. 整体模型（领域模型）

### 1.1 关键抽象

| 概念 | 说明 |
|---|---|
| 作品（Entry） | 库中的一条游戏记录，是聚合根。用户收藏与管理的基本单位。 |
| 作品身份 | 作品的标识与展示名，不依赖任何外部源。 |
| 用户状态 | 用户对作品的主观标记：状态、个人评分、笔记。 |
| 本地安装（Installation） | 作品在磁盘上的一条启动路径：目录与入口 exe，一部作品可有多条。 |
| 游玩记录（Play Session） | 一次启动留下的一行：起点、结束与两个时长。一部作品同时只有一条进行中的记录。 |
| 总时长 | 作品累计的游玩时长。用户可随时改写；软件在结算时按时间口径加在它上面。 |
| 前景时间 / 存活时间 | 软件记录的两个时间口径：前景时间是游戏窗口处于前台的时间，存活时间是进程从起点到结束的存在时长。取哪一个累加进总时长由设置页选择，配置持久化在数据目录的 config.json。 |
| 元数据（Metadata） | 别名、本地化标题、封面、发行日期、评分与人数、简介、标签、开发商、制作人员。 |
| VNDB 绑定 | 作品与 VNDB 条目之间可选的关联关系，由 `vndb_id` 表达。 |
| 角色（Character） | 一部作品下的出场人物，是作品的子实体：立绘、名字、原名、性别、年龄、尺寸、出场定位、简介。VNDB 上同一角色在不同作品里是不同条目（详略与立绘各不相同），故按作品各存一行，不建共享本体。 |
| 声优（Staff） | 为角色配音的人，全局表；与角色的配音关系带版本标记，同一对角色与声优可有多条。 |

### 1.2 聚合边界

一部作品是一个聚合，由四组相互独立的字段描述：

| 组 | 字段 | 能否脱离 VNDB 成立 |
|---|---|---|
| 身份 | `name` · `vndb_id` | 能。`vndb_id` 为空时作品照样存在。 |
| 用户状态 | `status` · `user_rating` · `notes` · `default_installation_id` · `play_seconds` | 能。纯用户数据。 |
| 本地安装 | `dir_path` · `entry_path` · `exes` · `size_bytes`（可多条） | 能。来自磁盘，与 VNDB 无关。 |
| 元数据 | 别名与本地化标题 · 封面 · 发行日期 · 评分与人数 · 平均通关时长 · 简介 · 标签 · 开发商 · 制作人员 | 此组是 VNDB 的数据来源，但即使全空，作品与元数据行仍存在。 |

聚合是逻辑边界，定义"什么属于同一部作品"；加载单位由消费方各自决定。

角色是聚合内的**子实体集合**而非字段组：一部作品下有多行，按作品整包替换，随作品删除而级联清除（声优是跨作品复用的全局表，不在此列）。

游玩记录同样是子实体集合：一次游玩一行，随作品删除而级联清除。不同之处是它不经表单整包提交，而由启动这类单条动作写入；作品的总时长另有用户直接填写的入口。

### 1.3 关系

```
作品 1 ──0..1── VNDB 绑定（vndb_id）
作品 1 ──0..*── 本地安装（installations.game_id）
作品 1 ──0..*── 游玩记录（play_sessions.game_id，安装项可空）
作品 1 ──1───── 元数据行（game_metadata，每列可空）
作品 1 ──0..*── 角色（characters.game_id，按作品整包替换）
角色 1 ──0..*── 配音关系（character_va，带版本标记）
声优 1 ──0..*── 配音关系（staffs 为全局表，不随作品删除）
```

读法：箭头两端是「一个 X 对应几份 Y」。`1` = 恰好一份，`0..1` = 零或一份（可选），
`0..*` = 零到任意多份（`*` 就是「多」，不限上界）。

### 1.4 不变约束

- `vndb_id` 可空且 `UNIQUE`：NULL 之间不判重；重复绑定已占用 `vndb_id` 的条目报冲突。
- 删除作品走 `ON DELETE CASCADE`：库内登记（含安装记录）一并移除，磁盘文件不动。
- `installations` 的唯一键是「目录 + 入口」这对：同一目录下可以有多条不同启动入口的记录（同一部作品的原版与汉化版各占一条），同一对只留一条；`entry_path` 为空按空串参与比较。
- 一个目录只归一部作品：目录写入前绝对化，写到已被别的作品占用的目录按冲突拒掉。
- 安装集合以作品为单位整包写回：草稿带 `id` 的更新、不带 `id` 的新建、库里本作品有而草稿里没有的删除；顺序按数组下标写回，客户端给的 `sort_order` 不采信。
- 安装行以启动文件路径为输入：末段是可执行扩展名（`exe` / `bat` / `cmd` / `com` / `lnk`，不分大小写）时按"父目录 + 文件名"拆成 `dir_path` 与 `entry_path` 写库，其余整串作为目录写入、`entry_path` 留空；路径文本与读回的路径一致时原样提交，改动过的按这条规则重拆。
- `entry_path` 存相对 `dir_path` 的路径：空串、绝对路径与越出该目录的路径按非法输入拒掉。
- 元数据每列均可由用户手改；同步不按"哪些列空了"判断该不该写，而是逐字段比对现值与新值，差异交给用户逐字段选覆盖或跳过。
- 外键列（`game_id` / `default_installation_id`）写入前判空串，空串按非法输入拒掉。
- 角色以作品为单位整包替换：先删该作品的全部角色行（配音关系靠外键级联），再按数组顺序写回。数组下标即顺序，客户端给的 `sort_order` 不采信。
- 删除作品级联清掉 `characters` 与 `character_va`；`staffs` 是跨作品复用的全局表，行在失去最后一个配音关系时回收——不论那条关系是被删作品、删角色还是整包替换带走的。
- `character_va` 的主键含版本标记：同一对角色与声优在不同版本下各自保留。
- 游玩记录由启动动作产生，一次游玩一行；同一部作品同时只有一条进行中的记录，重复启动直接拒掉。
- 结束判定带静默窗：进程全部退出后连续 3 秒仍为空才算结束 —— 启动器型入口会「启动器退出、本体被它拉起」，计数会短暂归零。
- 上次没干净退出留下的进行中记录，在 FishVN 下次开库时按最后在场时间结算；不能交给启动流程顺带做，那会结算掉别的作品的进行中记录。
- 游玩记录不由用户编辑；总时长可随时改写，软件的累加只在结算时发生。
- 状态自动迁移只有一条：越过静默窗后把「想玩」改成「游玩中」；其余三个状态不被改写。

### 1.5 字段来源四象限

| 类别 | 字段 | 写权限 |
|---|---|---|
| 用户输入 | `name` · `status` · `user_rating` · `notes` · `image_path` · `play_seconds` | 表单自由编辑（封面经文件对话框选择，路径也可手工输入）；总时长可任意改写 |
| 系统派生 | `created_at` · `play_count` · `last_played_at` · `foreground_seconds` · `alive_seconds` · `installation_count` · `can_launch` | 由动作产生 |
| 外部元数据 | 别名与本地化标题 · 发行日期 · 评分与人数 · 平均通关时长 · 简介 · 标签 · 开发商 · 制作人员 | VNDB 同步填入，用户可覆盖 |
| 本地事实 | `dir_path` · `entry_path` · `size_bytes` | 表单的安装行里用文件对话框挑启动文件，路径也可手工输入；`entry_path` 存相对 `dir_path` 的路径 |

角色字段的来源另算：立绘 · 名字 · 原名 · 性别 · 年龄 · 身高 · 体重 · 出场定位 · 声优 · 简介由用户在表单填写；`traits` 与三围、生日、血型只有 VNDB 同步才有来源，表单不暴露——本地编辑只覆盖露出的字段，未露出的保持原值。

## 3. 功能需求详述

### 活动集一 · 管理一部作品

#### 手动新增一部作品
- **描述**：用户填写作品名（必填）与可选字段，创建一条独立作品记录。无需任何 VNDB 信息即可创建。
- **前置**：用户在库内（空列表时提供"手动添加"入口）。
- **后置**：生成带 `id` 与 `created_at` 的作品；可选写入 `vndb_id`、用户状态与元数据。
- **涉及字段与来源**：`name`（用户输入，必填）；`vndb_id`（外部，可空）；`status` / `user_rating` / `notes`（用户输入）；元数据组（外部，可空）。
- **备注**：表单为纯受控组件，新增与编辑同源，按 mode 区分提交目标。

#### 从本地安装快速添加作品
- **描述**：在「我的列表」的添加菜单里挑一个可执行文件，识别出作品名（文件名去扩展名）与启动入口（父目录 + 所选文件）后，以预填内容打开新建表单；保存走「手动新增」与「手动指定本地启动路径」的既有链路。
- **前置**：无。
- **后置**：新建的作品带一条安装记录（目录 + 默认启动入口），目录占用按既有冲突口径报错。
- **涉及字段与来源**：`name`（文件名去扩展名，用户可改）；`dir_path`（所选文件的父目录）；`entry_path`（所选文件相对 `dir_path` 的路径）。
- **备注**：识别在挑选后异步完成（`inspect_path` 命令，避免扫盘阻塞界面），exe 候选与安装行共用同一套磁盘扫描（递归 3 层、30 个封顶、按层数排序，攒够候选即停止下钻）；卸载器与运行库安装器类文件名（`unins` / `setup` / `update` / `redist` / `vcredist` / `dxsetup` / `dotnetfx` / `crashreport` / `langsetup` 前缀）不进候选，`redist` / `_redist` / `uninstall` 目录不深入收集，目录大小仍累加全部内容。挑目录的入口走「扫描目录批量添加作品」（活动集三）。预填表单停在「基本」页，名称与安装行都已就位。

#### 编辑一部作品的字段
- **描述**：修改已有作品的任意可写字段并保存。
- **前置**：存在目标作品，且处于编辑态（表单以聚合当前值初始化）。
- **后置**：仅提交的字段被更新；未给的字段保持原值（PATCH 双层 `Option` 区分"没给"与"显式置空"）。
- **涉及字段与来源**：身份、用户状态、元数据三组的可写字段。
- **备注**：`status` 为 `NOT NULL`，无清空语义，用单层 `Option`。字段级校验的报错渲染在对应字段旁；操作失败（拉取、存盘）才走全局 toast——那时用户可能停在角色 tab 或搜索侧栏，字段旁那条不在他视野里。

#### 删除一部作品（保留磁盘文件）
- **描述**：删除作品记录，但不删除磁盘上的任何文件。
- **前置**：存在目标作品。
- **后置**：作品记录与其安装记录一并消失，磁盘内容原样保留。
- **备注**：界面需说明"删除作品记录不会删除磁盘上的文件"。

#### 设置一部作品的状态
- **描述**：在四个状态（游玩中 / 想玩 / 已通 / 弃）之间任意切换。
- **前置**：存在目标作品。
- **后置**：`user_game_state.status` 更新为所选值。
- **备注**：四选项全开，用户可能改错状态，必须能改回。

#### 记录一部作品的个人评分
- **描述**：用户给作品打个人评分（0–100 百分制，详情页展示时除以 10）。
- **前置**：存在目标作品。
- **后置**：`user_game_state.user_rating` 更新。
- **备注**：与 VNDB 的 `rating`（外部元数据）是不同字段，互不覆盖。

#### 为一部作品添加个人笔记
- **描述**：用户记录自由文本笔记。
- **前置**：存在目标作品。
- **后置**：`user_game_state.notes` 更新。
- **备注**：笔记随详情返回，不进摘要投影，避免列表载荷膨胀。

#### 为一部作品选择本地封面
- **描述**：用户通过原生文件对话框为作品挑选本地图片作为封面，也可直接手工输入图片路径。
- **前置**：存在目标作品，且处于表单编辑态。
- **后置**：`game_metadata.image_path` 为所选图片的绝对路径；表单预览与详情页渲染该封面，无本地封面或加载失败时显示占位。
- **涉及字段与来源**：`image_path`（用户输入，绝对路径）。
- **备注**：VNDB 同步填入的封面与本功能选的是同一个字段 `image_path`，两者在冲突面板里逐个取舍。

#### 编辑一部作品的制作人员
- **描述**：在表单「制作人员」页里按行维护人员条目，每行选职能、填姓名与别名（可选）。
- **前置**：存在目标作品，且处于表单编辑态。
- **后置**：`game_metadata.staff` 整列替换为表单当前列表；两边都没填名字的行在提交时丢弃。
- **涉及字段与来源**：`staff`（用户输入 + VNDB 同步，条目为职能 · 姓名 · 别名 · 备注）。
- **备注**：职能为固定十项（剧本 / 导演 / 人物设计 / 原画 / 音乐 / 歌手 / 翻译 / 编辑 / 测试 / 制作），与 VNDB 的 `staff_role` 枚举一一对应；备注列由 VNDB 同步带入，表单里就地保留原值；同步来源的条目与手输条目在同一列表里混排，冲突按整列取舍；页内常驻提示「详情页将按职能分组展示」。

### 活动集二 · 关联 VNDB 数据

#### 按标题搜索 VNDB 作品
- **描述**：在表单内并排打开搜索面板，按标题（含别名、关联 release 标题）检索 VNDB，结果按相关度排序。
- **前置**：用户已输入作品名或主动触发搜索。
- **后置**：返回命中列表（标题、罗马字、年代、原作语言、缩略图），供用户选择。
- **备注**：搜索结果有进程内缓存（TTL 10 分钟，LRU 32）；`search` 只接受字符串值，传数组会静默失效。

#### 将一部作品绑定到 VNDB 条目
- **描述**：用户从搜索结果选中一条，将 `vndb_id` 写入作品身份。
- **前置**：搜索已返回结果，用户选中某条目。
- **后置**：作品的 `vndb_id` 设为所选值；重复占用已绑定 `vndb_id` 时报冲突。
- **备注**：选中搜索结果即写入 `vndb_id`，随即拉取该条目的元数据并打开取舍面板。

#### 从 VNDB 同步元数据（逐字段可选覆盖）
- **描述**：基于已绑定的 `vndb_id` 拉取 VNDB 元数据，逐字段比对库里现值与新值；对存在差异的字段，在冲突面板中由用户逐字段选择「覆盖」（采用 VNDB 值）或「跳过」（保留现值）。JSON 列（`tags` / `developers` / `titles`）以整列替换粒度决策。VNDB 提供建议值，用户保留逐字段否决权。
- **前置**：作品已绑定 `vndb_id`。
- **后置**：取舍面板只改表单状态，点保存才落库；用户「跳过」的字段保持原值。名称与元数据在同一决策集内，选中官方标题时一并更新 `games.name`。本地为空的字段同样进面板，默认勾选，当前侧显示「未填写」。
- **备注**：标签与开发商按名字集合比对，顺序不同不算冲突；简介读入时剥掉 BBCode，`[spoiler]` 与 `[raw]` 整块丢弃（前端本来就不渲染 BBCode，剥掉不等于丢数据）。封面同样进面板：本地为空默认勾选采用 VNDB 下载的图，非空则与文本字段一样由用户逐个取舍。制作人员行按职能展示两侧姓名集合不一致的职能（缺失一侧显示占位符），并计数其余一致的职能；职能与姓名全同而仅备注不同时整列展示。
- 元数据与角色集由同一次同步取回，任一失败整体报错：只填上一半会让用户以为同步已经完成，看到的却是空角色列表。封面与立绘的下载相反——单张失败只记日志，不让整次同步失败。
- 标题列表可能一条中文都没有，按 `lang` 挑不出想要的那条，只能看 `official` / `main`。
- 标签列里混着两种来源：VNDB 的标签带 rating 与剧透等级，用户手打的没有。

### 活动集三 · 管理本地安装

#### 手动为一部作品指定本地启动路径
- **描述**：在作品表单的「安装」页添加本地启动路径（可多条），每行一个可执行文件，并指定其中一条为默认启动。
- **前置**：作品处于表单编辑态；新增与编辑同一套流程。
- **后置**：保存时整包写回该作品的安装集合——草稿里带 `id` 的更新、不带 `id` 的新建、库里本作品有而草稿里没有的删除；顺序按数组下标写回；磁盘内容原样保留。
- **涉及字段与来源**：`dir_path` 与 `entry_path`（本地事实，从这一行的路径文本拆出：父目录与文件名）；`exes` 与 `sort_order` 由后端重算与派生，客户端给的值不采信。
- **备注**：一行一个输入框加右侧浏览按钮，浏览走文件对话框；手输的末段带可执行扩展名时按文件拆，其余整串按目录登记。默认由行首的单选圆点显式指定，默认项为空或指向已移除的安装时取列表第一条；列表次序由添加先后决定，不提供调序。同一目录可以加多个启动文件，各自成一条记录；目录本身只归一部作品，别的作品再加该目录下的文件报冲突。已有安装项的目录不在保存时重新读盘，换目录或新建时才读。

#### 扫描目录发现未登记的作品
- **描述**：在「我的列表」的添加菜单挑一个目录（如整个游戏库根），扫描其直接子目录，识别各目录的作品名与启动入口，产出候选清单；用户在清单里勾选（可全选），确认后批量创建作品。
- **前置**：无（库根登记未实现，当前为手动挑目录的单次扫描）。
- **后置**：勾选的目录逐条创建作品并写入安装记录（名称 = 目录名，默认入口 = 识别的候选入口，`entry_path` 相对 `dir_path`）；结果汇总「已添加 N 项，跳过 M 项」；作品列表刷新。
- **备注**：扫描经 `scan_dir` 命令异步执行（`spawn_blocking`），进度经任务事件通道（`scan`）在面板里展示且可取消；识别复用快捷添加同一套磁盘扫描与排除名单，无候选入口的子目录不进清单；已登记目录在清单里标灰禁选（与库内 `installations.dir_path` 忽略大小写比对），扫描与创建之间的窗口期冲突仍由保存时的既有冲突口径兜底计入跳过。清单的入口列就地编辑：候选下拉（datalist）列出扫到的入口，行尾浏览按钮打开文件对话框（以该行目录为起点）指定扫不到的深层入口，选到目录外提示未采纳；多候选且无同名顶层命中的行显示候选数提示点。批量创建走 `create_game` + `save_installations` 既有链路，逐条循环、单条失败计入跳过。库根登记（`library_roots` 落库）与定期重扫未实现。

#### 设置某安装项的启动入口
- **描述**：把一条安装项的启动文件换成另一个可执行文件。
- **前置**：作品表单里存在该安装项。
- **后置**：`entry_path` 与 `dir_path` 按新的路径文本重拆；`exes` 由后端读目录重算。
- **备注**：改这一行的路径文本或用右侧浏览按钮重挑文件；换到别的目录时顺带把失效的目录大小置空。

#### 移除某安装项（保留磁盘文件）
- **描述**：解除作品与某目录的关联，不删除磁盘文件。
- **前置**：作品表单里存在该安装项。
- **后置**：保存时该安装项从集合里消失；磁盘内容原样保留。

#### 启动一部作品并记录游玩
- **描述**：从详情页启动作品的默认安装项，并为这次游玩记一条记录：起点、前景时间、存活时间。
- **前置**：作品有可启动的安装项（默认项失效时回落列表第一条）；该作品当前没有进行中的记录。
- **后置**：入口文件在其目录下被拉起；一条进行中的记录入账；结束时结算两个时长，并把这次的时间按时间口径累加进作品的总时长，必要时把「想玩」改成「游玩中」。
- **涉及字段与来源**：`play_sessions.foreground_seconds` 与 `alive_seconds`（系统派生，由计时回路写入），`user_game_state.play_seconds`（系统在上面累加）。
- **备注**：进程被放进 Job Object 守着，子进程逃不出去，启动器型入口也被完整覆盖。偏差一律偏向少算：全屏挂机会计入前景时间；游戏进程脱离本进程树（走 Steam / DRM 客户端，或被系统服务代理）会被判成已经结束。详情页按固定间隔重取进行中的记录。

#### 写作品的总时长
- **描述**：用户写作品的总时长 —— 本应用之前玩掉的时间这样补。
- **前置**：无；正在游玩中也能改。
- **后置**：总时长按填写值落库。
- **涉及字段与来源**：`user_game_state.play_seconds`（用户写）。
- **备注**：输入认 `12:30` / `12h30m` / 纯数字（按秒），失焦落库，认不出来就还原。

### 活动集四 · 浏览与筛选

#### 列出全部作品摘要
- **描述**：进入列表时一次取全量摘要投影并常驻内存。
- **前置**：库存在。
- **后置**：渲染封面墙，按状态分区。
- **备注**：摘要投影为 selector 从聚合中选出的子集；个人库规模几千条内不构成压力。分区与筛选栏的展示顺序固定，游玩中的排在最前。

#### 打开一部作品的详情
- **描述**：整页切换到详情，按需取单条聚合（含重字段如简介、安装列表）。
- **前置**：用户从列表选择某作品。
- **后置**：展示身份、用户状态、元数据与默认启动路径；关闭即释放聚合。
- **备注**：重字段按需再取，与"属不属于这部作品"无关。
- 元数据行可能不存在（作品没绑过 VNDB），这不是失败，页面按空值渲染。
- 评分一律按十分制展示：VNDB 的 `rating` 与个人评分在库里都是百分制，91 显示 9.1，不补成 9.10。
- 标签展示：剧透等级 ≥ 1 的不展示；VNDB 标签按 `rating` 排、同值再按 `vn_count`，用户手打的标签没有这两项，当 0 排在 VNDB 标签之后。
- 启动按钮启动默认安装项的入口文件；默认项失效时回落列表第一条，都没有可启动的入口时按钮不可点，悬停给出原因。默认启动路径以路径条展示在动作条下方，点击直达表单的「安装」页；显示的路径与启动目标同源。
- 动作条与封面同宽（同一列）：开始游戏 / 时长格 / ⋯ 菜单。时长格显示作品的总时长，只放数字（没玩过显示 `--`），悬停显示「游戏时长」。删除不进动作条，收进 ⋯ 菜单 —— 它不高频。

#### 查看一部作品的制作人员
- **描述**：详情页在角色区之后展示制作人员模块，按职能分组，各组以多列网格排布。
- **前置**：作品的元数据里有制作人员条目。
- **后置**：每个职能一组，职能名作组标题，人名在组内竖排；同步备注以小字灰显跟在人名后，列宽不足时在组内换行；超过 8 人的组默认收起，组尾「… 还有 N 人」展开、再点收回；模块整体另有限高，内容超出在内部滚动。
- **备注**：人名展示以原文姓名优先，罗马字转写放进悬停提示；职能名取本地化映射，同步带来映射外的职能时原样显示。

#### 按状态筛选作品
- **描述**：在"全部 / 游玩中 / 想玩 / 已通 / 弃"之间切换，列表按所选状态过滤。
- **前置**：存在作品。
- **后置**：列表仅显示匹配状态的作品，各状态带计数。
- **备注**：筛选属于列表视图状态。

#### 返回时还原列表的筛选与滚动位置
- **描述**：从详情返回列表时，恢复离开前的筛选状态与滚动位置。
- **前置**：曾进入详情。
- **后置**：列表还原到离开时的筛选与滚动偏移。
- **备注（部分实现）**：滚动位置还原已实现；筛选状态当前重置为"全部"，未还原，需补。

### 活动集五 · 管理一部作品的角色

#### 为一部作品新增一个角色
- **描述**：在作品表单「角色」页追加一个空白角色，随即填写其档案字段。
- **前置**：作品处于表单编辑态。
- **后置**：角色集合末尾多出一条；保存时随作品一并提交。
- **涉及字段与来源**：`id`（本地生成，与 VNDB 的 c 编号同列混排）；其余为用户输入。
- **备注**：角色不单独落库，随作品保存时整包提交。

#### 编辑一个角色的档案
- **描述**：修改角色的名字、原名、性别、年龄、身高、体重、出场定位与简介。
- **前置**：该作品已有至少一个角色，且当前选中了其中一个。
- **后置**：草稿更新；保存时整包写回。
- **涉及字段与来源**：上述字段为用户输入；`traits`、三围、生日、血型等未暴露的字段保持原值。
- **备注**：出场定位取 VNDB 的四档（主角 / 主要角色 / 配角 / 登场）。

#### 为一个角色指定本地立绘
- **描述**：通过原生文件对话框为角色挑选本地图片作为立绘，也可手工输入图片路径。
- **前置**：选中了某角色。
- **后置**：`image_path` 为所选图片的绝对路径；卡片渲染该立绘，无立绘时以角色名占位。
- **备注**：立绘走与封面同一条派生图管线（缩图与访问授权）。

#### 增删一个角色的声优
- **描述**：为角色添加或移除配音声优，可带版本标记（如作品的重制版）。
- **前置**：选中了某角色。
- **后置**：配音关系增删对应行；声优按编号复用全局表，已存在的声优行不被本地手填的名字覆盖。
- **备注**：同一对角色与声优在不同版本标记下各自保留。

#### 调整一部作品里角色的顺序
- **描述**：用左移 / 右移按钮改变角色在作品中的先后次序。
- **前置**：该作品有至少两个角色。
- **后置**：保存时按数组下标重写顺序，读取按该顺序返回。
- **备注**：卡条是吸边滚动，不做拖拽重排——会与吸边打架。

#### 删除一个角色
- **描述**：从作品中移除一个角色。
- **前置**：选中了某角色。
- **后置**：该角色与其配音关系一并移除；保存时随整包替换落库。
- **备注**：配音关系随角色删除；声优作为全局表保留，失去最后一个配音关系的行随即回收。

#### 查看一部作品的角色
- **描述**：在详情页浏览该作品的角色列表，展开查看单项详情。
- **前置**：已打开某作品的详情。
- **后置**：展示角色立绘、原名与首位声优；展开后显示性别、尺寸、年龄、声优与按分组归类的 traits。
- **备注**：traits 的分组在 VNDB 侧没有序号字段，前端固定一张展示顺序表，不在这张表里的新分组排到末尾；剧透等级 ≥ 1 的 trait 不展示，成人向分组不进正文。

#### 从 VNDB 同步一部作品的角色
- **描述**：随「同步元数据」一并拉取该作品的角色与配音关系，按角色名比对后逐条取舍。
- **前置**：作品已绑定 `vndb_id`。
- **后置**：角色的档案、立绘与 traits 落库；配音关系按角色、声优与版本标记去重。
- **备注**：源为 `/character`（角色档）与 `/vn` 的 `va`（声优，带版本标记），接口坑与数据模型见 `docs/dev/vndb-api.md`。只取主角与主要角色两档：`side` / `appears` 里混着无立绘的配角，收进来只是让卡条多一排占位块，还要为它们多下一批图。
- 与本地角色按名字配对，配对键优先取原名——罗马字名重名会把两个不同角色判成同一个。与作品级同口径：本地优先，冲突项逐个取舍后随保存落库。角色冲突不单独开面板，作为「角色」分节展示在同一张取舍面板的元数据行下方；本地没有的新角色直接补进列表，随保存落库。

### 活动集六 · 调整软件设置

#### 切换深色主题
- **描述**：在设置页「个性化」标签内切换浅色 / 深色两套配色。
- **前置**：打开设置页。
- **后置**：整个界面即时切换配色；选择写入数据目录的 `config.json`，重启后保持。
- **备注**：窗口外壳与启动页的配色在界面渲染前就按主题就位，深浅两色都无白闪；`localStorage` 只是首帧缓存，权威在配置文件。

#### 选择强调色
- **描述**：在设置页「个性化」标签内从六种强调色（绯红 / 琥珀 / 海洋 / 樱花 / 翡翠 / 紫罗兰）中挑选界面主色。
- **前置**：打开设置页。
- **后置**：强调色写入数据目录的 `config.json`，重启后保持；界面即时按新色渲染。
- **备注**：强调色与深浅主题正交，每种色在两套主题下分别给定色值；按钮、选中态、焦点等主色元素跟随强调色。窗口外壳与启动页在界面渲染前就按强调色就位，切换无闪变。

#### 选择计时口径
- **描述**：在前景时间与存活时间两种口径间二选一，决定游玩结束时把哪个时长累加进总时长。
- **前置**：打开设置页。
- **后置**：选择写入数据目录的 `config.json`；此后启动与收尾的结算按新口径取值，历史记录不回算。
- **备注**：口径在结算线程内即时读取，选完即对下一局生效；配置损坏或缺省时按前景时间处理。

#### 启动到品牌页（随就绪淡出）
- **描述**：应用启动即见品牌页（金鱼标记 + spinner），首页数据加载渲染完成后淡出进入主界面。
- **前置**：无。
- **后置**：淡出后露出的首帧是加载完的首页；主题背景与主界面同值，前后零跳变。
- **备注**：数据加载卡住时 8 秒超时强制放行；浏览器 dev 环境直接跳过品牌页。

### 活动集七 · 首页

#### 查看库的统计概览
- **描述**：首页以数字行展示库的现状：作品总数、四个状态的计数、累计时长、本周时长与游玩次数。
- **前置**：库存在（空库各值为零，照常展示）。
- **后置**：各值反映当前库内数据；本周时长按设置的时间口径聚合七天内的游玩记录。
- **备注**：计数与时长来自一次聚合查询，不逐条取聚合；累计时长即各作品 `play_seconds` 之和（含用户手填部分），与详情页口径一致。

#### 自定义首页的模块开关与顺序
- **描述**：在设置页的「首页布局」里开关各模块并调整上下顺序，首页按该顺序渲染启用的模块。
- **前置**：打开设置页。
- **后置**：布局写入数据目录的 `config.json`，重启后保持；首页即时按新布局渲染。
- **备注**：布局是有序的「模块 + 开关」列表，缺省顺序为继续游玩、统计概览；首页只渲染它认识的模块，配置里多余的 id 被忽略。统计概览空库照常展示；继续游玩没有可展示的条目时整节隐藏。

#### 从首页继续游玩（最近游玩 + 一键启动）
- **描述**：首页以 16:8 场景卡横向分页展示最近游玩的作品：封面裁切满铺整卡，斜向压暗渐变上叠图上信息——「继续游玩」标签（强调色，图上用淡化变体）与作品名，右下角为累计时长（为 0 不显示）；分区标题行右侧有分页圆点，横向按卡步进翻页。点击卡片任意位置（含 hover 居中浮现的播放按钮）都是继续游玩：跳转详情并自动启动默认安装项，起飞动画从卡片的居中竖幅窗口过渡到详情封面。
- **前置**：存在游玩中、有启动入口且有游玩记录的作品；没有时整节隐藏。
- **后置**：卡片按上次游玩时间倒序，时长口径跟随设置；自动启动后详情页进入会话计时。
- **备注**：筛选范围是状态为游玩中且入口可启动的条目，通关与弃坑不出现；无默认安装或不可启动时只跳转不自动启动。横滚分页走水平分页契约（`docs/dev/frontend.md`），封面裁切保上不保下（竖封裁宽幅取偏上区域）。

## 4. 后续迭代落点

FDD 后三步（按功能计划 / 设计 / 构建）对每个功能集迭代推进：

- **活动集三「本地安装」** 的手动指定已建成：表单内增删、指定默认启动；「从本地安装快速添加作品」与「扫描目录发现未登记的作品」已建成，`inspect_path` / `scan_dir` 的识别原语（目录 exe 扫描 + 候选排序 + 排除名单 + 已登记比对）就是扫描链路的地基。库根登记（`library_roots` 落库）与定期重扫未实现。
- **活动集六「软件设置」** 的主题、强调色与计时口径已建成，后续设置项扩入 config.json 同一机制。
- **安装项的目录大小**（`size_bytes`）在手动指定流程里留空：对整棵子树求和在保存路径上耗时不可控，值由扫描流程连同遍历一起补。
- **网络调用的排队等待提示** 尚缺：请求级超时已设（20 秒，超时提示独立于连接失败），但 `fetch_vn_metadata` 与 `search_vndb` 被限流排队时只显示加载中，排队的等待上限与提示没有。
- **派生图缓存无清理机制**：`covers/` 按内容寻址累积（作品封面与角色立绘同目录），换过的封面旧文件会留下。缺清理策略。
- **活动集四的筛选还原缺口** 为小粒度的功能补充，可并入相应活动集的下一轮。
- **活动集一** 已基本建成，迭代以缺陷修复与微调为主。

每个功能进入构建前，仍按项目工作流先出方案、过目确认后再实现。
